## Karar

### 47.A — `cd/math/Range.hpp`
Template'lı `Range<T>` (min, max) + helper'lar:
- `length(r)` — max - min
- `contains(r, v)` — inclusive both ends
- `clamp(r, v)`
- `lerp(r, u)` (u ∈ [0,1])
- `inverse_lerp(r, v)` (v in [min,max] → [0,1])
- `expand(r, amount)` — symmetric pad
- `normalize(r)` — swap if reversed

T = float/double/int/uint32_t için tek primitive; tüm engine'in
"min/max" boilerplate'ini birleştirir.

### 47.B — `cd/ecs/EntityRange.hpp`
Editor list view pagination:
- `paginate(span<Entity>, page_size, page_index)` → `EntityPage
  { entities, page_index, page_count, total }`.
- Out-of-range page_index son sayfaya clamp.
- `page_size == 0` veya empty input → zero-page sane fallback.
- span subspan zero-allocation.

Inspector / Hierarchy panel'i 1000+ entity ile zaten yavaşlamasın
diye: page çek, prev/next ile gez.

## Reddedilen alternatifler

- **Range half-open semantik [min, max)**: matematik 0..1 range için
  closed daha doğru hissetiriyor — UI slider'ı 0 ve 1'i de göstermeli.
- **EntityRange iterator-based query (lazy)**: snapshot pragmatik;
  iterator stability ECS storage'da bozulabilir. Caller `paginate`
  öncesi snapshot çekiyor.
