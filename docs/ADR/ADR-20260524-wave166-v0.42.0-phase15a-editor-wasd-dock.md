# ADR — v0.42.0 / Wave 166 — Phase 15.A editor WASD camera + DockSpace

- Date: 2026-05-24
- Status: Accepted
- Wave: 166
- Tag: v0.42.0
- Predecessor: ADR-20260524-wave165 (Phase 15 master)

## Context

The editor's camera (Phase 14.E, v0.38.0) was auto-orbiting on a
wall-clock timer — visible but uninteractive. The panel layout
(v0.35.1) was pin-positioned but non-dockable, so users couldn't
rearrange the editor to their preference.

## Decision

Tag **v0.42.0**. Scope:
1. Free-fly WASD camera driven by ImGui input.
2. ImGui::DockSpace host so panels can be dragged into docks.

### What landed

- **Free-fly camera (`FlyCamera`)** with state `{position, yaw,
  pitch, speed, mouse_sensitivity}`. Inputs:
  - **W/S** translate along camera-forward.
  - **A/D** strafe along camera-right.
  - **E/Q** elevate/descend along world-up.
  - **Right-mouse drag** rotates yaw/pitch (sensitivity 0.005;
    pitch clamped to ±1.55 rad).
  - Inputs gate on `imgui_io.WantCaptureMouse / WantCaptureKeyboard`
    so dragging across a panel doesn't move the camera.
- **DockSpace host** — a full-window invisible
  `##DockSpaceHost` Begin/End wrapping a `DockSpace` with
  `PassthruCentralNode`, so the 3D viewport behind ImGui
  shows through the central area. Style vars are pushed
  (zero rounding/border/padding) so the host window doesn't
  add chrome.
- **`ImGuiConfigFlags_DockingEnable`** set during context
  init — the ImGui fork shipped with cd::imgui_backend
  already includes the docking branch (`IMGUI_HAS_DOCK`).
- Camera state lives in `main()` and survives across frames
  without disk persistence (the next polish wave can extend
  the cdscene.json schema to carry a `camera` key).

### What deliberately did NOT land

- **Mouse capture / pointer-lock** during right-drag. The
  drag currently moves the pointer freely; capture would
  need OS-level cursor confinement which isn't in the
  cd::platform window surface yet.
- **Camera persistence in cdscene.json.** Save/Load
  currently only round-trips scene state. Adding camera
  is a tiny schema bump deferred to the next editor wave.
- **Per-panel docking presets.** A first-launch builder
  that auto-docks Scene to the left, Inspector to the
  right, History at the bottom would polish the
  experience further. Currently users drag panels into
  the host once and the layout persists via ImGui's
  imgui.ini.

## Rejected alternatives

- *Use cd::input instead of ImGui::IsKeyDown.* Rejected:
  cd::input is the gameplay-side abstraction; the editor
  already pumps ImGui's input handler. Adding a second
  consumer would duplicate state.
- *Use OrbitController* (cd::camera::OrbitController).
  Rejected: editor users expect free-fly; orbit is the
  right shape for product-viewer demos, not authoring.

## Consequences

- v0.42.0 is the new latest SemVer marker.
- The editor goes from "the auto-orbit shows you the cubes"
  to "you fly through the scene and inspect from any
  angle".
- Phase 15.B (D3D12 descriptor sets → v0.43.0) opens next.
