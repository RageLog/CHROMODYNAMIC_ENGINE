# ADR-20260524 / Wave 295 / v0.99.60 / Phase 134 — RT pipeline handle + IDevice virtuals

## Status
Accepted — 2026-05-24

## Context

Phase 118 (this run) landed the `RtPipelineDesc` descriptor type
but no `RtPipelineHandle` and no `IDevice::create_rt_pipeline`
virtual. Phase 135 (Vulkan impl) needs both before
`vkCreateRayTracingPipelinesKHR` can be wired.

## Decision

Three additions to the cross-backend RHI surface:

1. **`cd::rhi::RtPipelineHandle`** + `RtPipelineTag` in
   `Handles.hpp`. Mirrors the existing GraphicsPipeline /
   ComputePipeline handle pattern.

2. **IDevice virtuals**:
   - `create_rt_pipeline(RtPipelineDesc, PipelineLayoutHandle) →
     Result<RtPipelineHandle>` — default impl returns
     `kNotImplemented` so existing backends compile.
   - `destroy_rt_pipeline(RtPipelineHandle)` — empty default.

3. **SBT authoring helpers** on IDevice (also non-pure-virtual):
   - `rt_shader_group_handle_size()` → bytes per shader-group
     handle (Vulkan: `physicalDeviceRayTracingPipelinePropertiesKHR.
     shaderGroupHandleSize`; typically 32 B).
   - `rt_shader_group_handle_alignment()` → handle stride
     alignment (typically 32 B).
   - `rt_shader_group_base_alignment()` → SBT region base
     alignment (typically 64 B).
   - `get_rt_shader_group_handles(pipeline, first, count, out)`
     → copy a span of shader-group handles into the caller's
     buffer; the caller then uploads them into the SBT regions
     it passes to `dispatch_rays`. Default returns
     `kNotImplemented`.

All five entry points have non-pure-virtual default implementations
so the OpenGL / Metal / D3D12 backends compile unchanged.

## Rejected alternatives

- **Pure-virtual the new RT entry points.** Would force every
  backend's class definition to override them today even though
  only Vulkan + (eventually) D3D12 need real impls. The
  default-non-pure pattern matches what
  `create_acceleration_structure` already does.
- **Per-stage `create_rt_shader_module` API.** Vulkan ingests
  SPIR-V per stage; `RtPipelineDesc::shaders` already lists each
  stage's GLSL source string, and `cd::shader::ICompiler` is the
  established cross-backend compile entry point. Stage modules
  are an internal detail of `create_rt_pipeline`.
- **Bundle SBT alloc into create_rt_pipeline.** Forces the SBT
  layout into the pipeline-create call. Keeping SBT alloc
  separate (Phase 135 helper + `DispatchRaysDesc::raygen/miss/hit/
  callable` SBT regions) lets callers reuse SBT buffers across
  pipelines or pack their own records.

## Consequences

- `cd::rhi` surface gains five new virtuals (no breaking change
  for existing backends; defaults are kNotImplemented or 0 / no-op).
- Phase 135 implements all five for Vulkan via
  `vkCreateRayTracingPipelinesKHR` +
  `vkGetRayTracingShaderGroupHandlesKHR` + property lookup.
- Full engine + 33 samples build clean (the new entry points are
  unconsumed today; Phase 136 hello_rt is the first call site).
