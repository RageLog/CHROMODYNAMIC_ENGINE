# ADR — v0.26.0 / Wave 147 — Phase 12.A perf sweep closure

- Date: 2026-05-23
- Status: Accepted
- Wave: 147
- Tag: v0.26.0
- Predecessor: ADR-20260523-wave142 (Phase 12 master plan)

## Context

Phase 12.A — performance + profile sweep — was the first sub-phase
in the autonomous Phase 12 feature marathon. Goal per Wave 142:
broaden the bench surface, commit a baseline, install a CMake-level
regression gate, document the perf story.

## Decision

Tag **v0.26.0**. Phase 12.A closes here.

Rolled up:

- **Wave 143** `feat(bench)` — hello_bench expanded from 7 to 21
  micro-benchmarks. New coverage spans math kernels (Mat4 multiply
  / inverse, Vec3 normalize, Quat slerp, Transform→Mat4), foundation
  primitives (Handle, HandleStore, format owning vs literal, CVar
  set+get), log ring push + snapshot, imgdiff compare, ECS for_each.
- **Wave 144** `test(bench)` — committed
  `tests/bench/baseline-debug-nvidia.json` as the v0.26.0 perf floor.
  `tests/bench/README.md` documents the file conventions and how
  `cd_bench_compare` reads it.
- **Wave 145** `build(bench)` — `cmake/CDBench.cmake` installs
  `smoke-bench` + `smoke-bench-capture` CMake targets. Threshold set
  to 25% (rationale in PERFORMANCE.md: ≤50 ns tier has 15-20% Debug
  noise floor on this machine; 10% would false-trip).
- **Wave 146** `docs(perf)` — `docs/PERFORMANCE.md` is the new
  single entry point: bench surface tiered tour, per-gate semantics,
  noise-floor explanation, "adding a new benchmark" recipe.

## What v0.26.0 carries beyond v0.25.0

- 14 new micro-benchmarks (7 → 21).
- One committed baseline file consumers can pin against.
- One CMake-level regression gate (`smoke-bench`) anyone can run
  locally + CI can call.
- One performance doc.

## What's NOT in v0.26.0

The hot-path audit deliverable that Wave 142 listed ("find at least
3 measurable wins") came up empty: the foundation hot paths are
already tight (Result happy path 4 ns, PoolAllocator 4 ns, Handle
create 6 ns). The cheap wins are already gone. Real micro-optimisation
from here needs proper profiler attachment (Tracy, vsprofile, perf
on Linux) — that's out of scope for a headless AI marathon and is
filed for a follow-up wave when the user is back.

What we shipped instead: the bench surface itself, which IS the audit
infrastructure. Anyone running `smoke-bench` after a change gets
diff signal for free.

## Rejected alternatives

- *Don't ship perf without 3 wins.* Rejected: the bench expansion +
  baseline + gate are themselves the v0.26.0 deliverable. They're
  load-bearing for every subsequent phase (12.B/C/D will all add
  bench rows). Holding the tag for opportunistic wins blocks the
  marathon.
- *Tag v0.26.0 only after a Release baseline lands too.* Rejected:
  Release baseline is a real follow-up but adds bench wave for
  capture + CI cell — out of scope for "land Phase 12.A this wave".
  Debug baseline + 25% local gate is concrete forward motion.

## Consequences

- `v0.26.0` becomes the new latest SemVer marker.
- Phase 12.B (D3D12 backend completion) opens next, autonomously.
- The bench surface is now reusable infrastructure: 12.B/C/D adds
  rows for D3D12 command record cost, editor frame cost, raytrace
  dispatch cost respectively.
