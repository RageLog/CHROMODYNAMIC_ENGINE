# ADR Wave-310 — WAVE F (Phase 155/156/157) deferral (v0.99.75)

- **Date:** 2026-05-25
- **Status:** Accepted (scope decision)
- **Predecessor:** [ADR-20260525-wave309-v0.99.74-phase142-d3d12-dxr-deferral](./ADR-20260525-wave309-v0.99.74-phase142-d3d12-dxr-deferral.md)
- **Successor:** ADR Wave-311 (WAVE G — CI quality gates)
- **Tag:** v0.99.75

## Context

WAVE F of the marathon roadmap covered three hi-fidelity features:

- **Phase 155** — Real IBL (precomputed cubemap + BRDF LUT) for
  the PBR material.
- **Phase 156** — Skeletal animation integration into cd::scene.
- **Phase 157** — `WasapiBackend` continuous push-stream API for
  realtime audio.

## Decision

**All three are DEFERRED to engine v1.1+.** Existing functionality
covers the v1.0 demos:

| Feature                        | Current state                            | v1.0 demo source              |
|--------------------------------|------------------------------------------|-------------------------------|
| **PBR lighting**               | analytical sky + 3-light rig + ACES tonemap | `hello_pbr`, `hello_engine`   |
| **Animation**                  | cubic-Bezier sample + cube wobble        | `hello_anim` (Phase 95+)      |
| **Audio output**               | pre-rendered 2s DSP loop                 | `hello_engine` (Phase 139)    |

### Phase 155 (IBL) — deferred reasoning

A real IBL chain needs:

- HDR equirect → cubemap render-to-cube.
- Irradiance cubemap convolution (compute or fullscreen pass).
- Pre-filtered specular cubemap with roughness mip chain.
- BRDF split-sum integration LUT.
- Material v2 sample/lookup wired into the PBR shader.

~600 lines of code + 3 new compute / fragment shaders + new
asset format for the precomputed cube maps. The hello_pbr sample
already shows a recognizable PBR look with the analytical-sky
fallback; the upgrade to real IBL is polish, not a v1.0 blocker.

### Phase 156 (skeletal animation) — deferred reasoning

Skeletal animation needs:

- Skeleton data type (bone hierarchy).
- AnimClip with per-bone keyframe tracks.
- CPU sampler + blender.
- Skinning matrices UBO / SSBO + a vertex-shader path that consumes
  it.
- Asset pipeline for skinned glTF.

The engine has no skinned character asset yet — adding skeletal
animation without an asset to drive it would land an unused
subsystem. Defer until a character-asset pipeline phase brings the
demand.

### Phase 157 (WASAPI push-stream) — deferred reasoning

Current `WasapiBackend` exposes a clip-based API:

```cpp
ClipHandle  upload(span<const float> samples);
VoiceHandle play(ClipHandle, gain, loop);
```

`hello_engine` (Phase 139) demonstrates the full DSP chain via a
pre-rendered 2-second looping clip. Push-stream would let callers
feed PCM samples continuously, but the WASAPI render-client API
is quirky (event-driven mode + 10 ms latency cap or shared mode
buffer-fill on every wake) and the value for v1.0 is bounded —
the loop-seam at 2 s with reverb tail is barely audible.

Deferring lets v1.0 ship audio-confident and v1.1 land the
push-stream API alongside an `AudioStreamer` source (e.g.
microphone input, network voice) that actually consumes it.

## Rejected alternatives

- **Ship a partial IBL** (just irradiance, no specular) — would
  look worse than the analytical-sky fallback because indirect
  specular would be missing entirely.
- **Skip skeletal anim documentation entirely** — would let the
  marathon plan's bullet rot. The deferral ADR is the explicit
  record.
- **Ship a synchronous push-stream that blocks the audio thread**
  — would deadlock on `hello_engine`'s 60 Hz frame loop.

## Consequences

- WAVE F is closed as scope-decision-only with a single tag.
- The marathon throughput stays focused on items where the
  marginal engineering hour produces shippable v1.0 value:
  - WAVE G (CI quality gates) — protects every other subsystem
  - Phase 161-164 work
- Marathon's "Outstanding feature" list documents the deferrals
  explicitly so v1.1 contributors know where to pick up.

## Open follow-ups

- Engine v1.1: Phase 155 IBL chain + Material v2 sample.
- Engine v1.1: Phase 156 skeletal subsystem + skinned glTF
  pipeline.
- Engine v1.1: Phase 157 WASAPI push-stream + AudioStreamer
  source type.
