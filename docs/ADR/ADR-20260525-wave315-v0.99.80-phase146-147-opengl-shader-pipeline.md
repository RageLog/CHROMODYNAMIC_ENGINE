# ADR Wave-315 — Phase 146/147 OpenGL shader + pipeline (v0.99.80)

- **Date:** 2026-05-25
- **Status:** Accepted
- **Predecessor:** [ADR-20260525-wave314-v0.99.79-phase148-lite-opengl-resources-sample](./ADR-20260525-wave314-v0.99.79-phase148-lite-opengl-resources-sample.md)
- **Successor:** ADR Wave-316 (Phase 145 OpenGL swapchain — next reclaim)
- **Tag:** v0.99.80
- **Reclaim:** Phases 146 + 147 from the Wave 308 deferral.

## Context

WAVE D scope decision (ADR Wave-308) deferred OpenGL Phases 145-148
to engine v1.1+. With Phase 148-lite (Wave 314) shipped, the next
v1.1 reclaim continues the OpenGL backend chain: shader compile
(146) and graphics pipeline link (147). The swapchain (145) sits
last because it brings the most environmental risk (WGL extension
loading order, FBO render targets, OS resize semantics).

## Decision

### Phase 146 — `create_shader_module`

OpenGL takes GLSL source directly via `glCreateShader` +
`glShaderSource` + `glCompileShader`. The engine's
`ShaderModuleDesc::code` + `code_size` already model an opaque
byte payload — for OpenGL we interpret it as GLSL UTF-8 (no
NULL-termination required; we pass `code_size` to GL).

The cross-backend contract is documented as:

- **Vulkan**: `code` = SPIR-V bytes from `cd::shader::ICompiler`.
- **D3D12**: `code` = DXIL bytes from the same compiler at a
  D3D12 target.
- **OpenGL**: `code` = GLSL source bytes (no compiler intermediate).

Callers compile differently per backend until a future phase
introduces a SPIR-V → OpenGL path via `GL_ARB_gl_spirv`.

Stages supported in v1.1.0: vertex / fragment / geometry / compute.
RT / mesh / tess stages return `kNotImplemented` on the OpenGL
path.

On compile failure the backend pulls `glGetShaderInfoLog` and
surfaces it via `rhi_errors::make_owning(kResourceCreationFailed,
"glCompileShader failed: <log>")` so the error message is
actionable.

### Phase 147 — `create_pipeline_layout` + `create_graphics_pipeline`

OpenGL has no PSO object; the engine surface still requires a
`PipelineLayoutHandle` + `GraphicsPipelineHandle`, so the backend
issues opaque ids:

- `create_pipeline_layout` returns a no-op handle (no GL counterpart
  needed; the layout is a Vulkan-side concept the GL backend simply
  records to keep the surface uniform).
- `create_graphics_pipeline` runs `glCreateProgram` + `glAttachShader`
  per non-null shader handle (`vertex_shader`, `fragment_shader`,
  `geometry_shader`) + `glLinkProgram`. Link failure returns the
  `glGetProgramInfoLog` text. The handle stores the GL program id;
  destroy calls `glDeleteProgram`.

The rest of the `GraphicsPipelineDesc` (raster / depth / blend /
vertex layout) is **not** baked into the GL program object — it
will be replayed on bind in the future pipeline-bind phase. Storing
the desc as a side struct is a follow-up; for v1.1.0 the program
link is enough to validate the create chain.

### Loader

Added 12 new function pointers to `GLLoader`:

- `glCreateShader / glDeleteShader / glShaderSource / glCompileShader
  / glGetShaderiv / glGetShaderInfoLog`
- `glCreateProgram / glDeleteProgram / glAttachShader / glLinkProgram
  / glGetProgramiv / glGetProgramInfoLog`

All twelve are core in GL 2.0 and exposed via `wglGetProcAddress`
on all desktop drivers; the 1.1-fallback path in Wave 314 covers
the edge case where some drivers report them via `opengl32.dll`.

Two new predicates: `shader_valid()` + `program_valid()`.

## Rejected alternatives

- **Require SPIR-V via `glShaderBinary` + `glSpecializeShader`** —
  needs OpenGL-flavored SPIR-V (different from Vulkan-flavored)
  from glslang, which `cd::shader::ICompiler` doesn't currently
  emit. GLSL source path unblocks v1.1 today; SPIR-V path can
  arrive in v1.2.
- **Bake all `GraphicsPipelineDesc` state into the handle** — would
  require a separate `replay_pipeline_state(...)` helper that the
  bind code calls. Out of scope for this ship; pipeline-bind on GL
  is a follow-up.
- **Compile-time `static_assert` that the backend chose GLSL vs
  SPIR-V** — would force every caller to know which backend they're
  feeding. The runtime contract is clearer: pass the right bytes
  for the backend.

## Consequences

- OpenGL backend now compiles shaders + links programs end-to-end.
- The partial-backend `kNotImplemented` count drops by 4
  (shader_module create/destroy, pipeline_layout create/destroy,
  graphics_pipeline create/destroy — plus the matching destroy
  no-ops).
- Phase 145 (swapchain) is the last remaining OpenGL phase before
  the full hello_opengl triangle sample is possible.

## Open follow-ups

- Phase 145 — OpenGL swapchain via WGL_ARB_pixel_format +
  WGL_ARB_create_context_attribs + an FBO render target +
  `SwapBuffers`.
- Phase 148-full — hello_opengl_triangle wiring buffer + VAO +
  shader + program + draw call.
- Pipeline-state replay (raster, depth, blend, vertex layout) on
  bind — needs the command-buffer phase for OpenGL.
- SPIR-V via `GL_ARB_gl_spirv` once `cd::shader::ICompiler`
  gains an OpenGL target env.
