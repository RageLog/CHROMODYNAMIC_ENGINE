# ADR-20260524 / Wave 279 / v0.99.44 / Phase 114 — AsyncStreamer thread

## Status
Accepted — 2026-05-24

## Context

Phase 45.B shipped `cd::asset::StreamQueue` — a priority-queue
primitive for "what to load next" — but no worker thread actually
pumped it. Streaming-friendly asset loads stayed manual.

## Decision

New header-only `cd/asset/AsyncStreamer.hpp`:

- Owns a `StreamQueue` + `std::mutex` + `std::condition_variable`
  + a single `std::thread` worker.
- `start()` spawns the worker (idempotent).
- `enqueue(StreamRequest)` pushes + notifies the cv.
- Worker loop sleeps on the cv until a request arrives or
  `stopping_` is set; pops the highest-priority request, invokes
  the caller-supplied `LoadFn(AssetId) → bool` *outside* the lock
  (so concurrent enqueues aren't blocked by long loads), then
  marks the request complete or failed under the lock.
- `stop()` signals `stopping_`, notifies the cv, joins the
  worker. Idempotent — stopping a never-started streamer is a
  no-op.

`LoadFn = std::function<bool(AssetId)>` is the contract: caller
plugs in `AssetRegistry::load` or a VFS+decode chain.

Three new gtests:
1. `EnqueueAndComplete` — two requests, both reach `kComplete`,
   `load_fn` called ≥ 2 times.
2. `FailureMarksFailed` — load_fn returns false, request lands in
   `kFailed`.
3. `StopWithoutStartIsNoop` — destructor + double-stop safe.

## Rejected alternatives

- **N-thread pool.** Single worker keeps lock contention zero
  and is sufficient for typical asset streaming. Bump to a pool
  when profiling shows it; the queue + cv work the same.
- **Coroutine-based scheduler.** Adds a C++20 coroutine runtime
  + scheduler infrastructure for what is one thread + cv.
- **Reuse `cd::concurrency::Scheduler`.** The job system is
  designed for fork/join compute work; this is a long-lived
  worker that should hold its slot for the engine's lifetime.
- **Polling worker (no cv).** Wastes CPU when idle.

## Consequences

- `cd::asset` gains a header-only async streaming entry point.
  Engine code can wire `AssetRegistry::load` into a worker with
  three lines of glue.
- No dependency on `cd::concurrency`; just std::thread + mutex +
  cv. Keeps the layering DAG simple.
- Phase 115+ samples / editor can stream large assets without
  blocking the render thread.

## Validation

```
cmake --build --preset llvm-win-debug --target cd_test_asset
./build/llvm-win-base/bin/Debug/cd_test_asset.exe \
    --gtest_filter=AsyncStreamer.*:AssetRegistryEvict.*
```

5 / 5 pass (2 evict tests from Phase 113 + 3 new streamer tests).
Streamer tests complete in 18-34 ms wall time.
