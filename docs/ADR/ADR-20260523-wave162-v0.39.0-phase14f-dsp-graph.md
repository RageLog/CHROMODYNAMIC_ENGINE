# ADR — v0.39.0 / Wave 162 — Phase 14.F DSP graph

- Date: 2026-05-23

- Tag: v0.39.0
- Predecessor: ADR-20260523-wave161 (v0.38.0 editor viewport)

## Context

Phase 14.F per the wave156 plan: DSP graph + 3D positional polish.
The cd::audio library already ships WASAPI / ALSA / CoreAudio
backends + a `PositionalSource` with inverse-square attenuation
and ITD/ILD delay lines (Wave 79+). The missing layer was the
*generic* DSP graph — a tiny composable chain of biquads + gain
that any source can route through before the mixer hands the
buffer to the backend.

Marathon honesty: DSP graphs that *sound right* need human-ear
validation. v0.39.0 ships the *structure* + sample-level math
verification; perceptual tuning (HRTF calibration, reverb
parameter sweeps) lives in a later iteration where a human can
listen.

## Decision

Tag **v0.39.0**. Scope: header-only `cd::audio::DspGraph` with
`IDspNode` base + `GainNode` + `BiquadNode` (lowpass /
highpass), six unit tests that pin the per-sample math.

### What landed

- **`cd::audio::IDspNode`** — pure-virtual base. Every node
  implements `process(std::span<float>, std::uint32_t
  sample_rate)` for in-place processing, `reset()` to clear
  time state, and `label()` for diagnostics.
- **`cd::audio::GainNode`** — scalar multiply, linear amplitude.
- **`cd::audio::BiquadNode`** — Direct Form II Transposed
  biquad, parameterised by RBJ Cookbook formulas:
  - `kLowpass` and `kHighpass` variants.
  - Cutoff in Hz, Q (default 0.7071 = Butterworth).
  - Coefficients recomputed on cutoff/Q change or
    sample-rate change (cached otherwise).
  - `reset()` zeroes the z1/z2 state.
- **`cd::audio::DspGraph`** — ordered chain. `push<T>(unique_ptr)`
  returns a raw observer so callers can tune parameters
  without re-allocating. `process()` runs every node in
  insertion order; `reset()` resets all; `clear()` drops the
  chain.
- **6 new tests in `cd_test_audio`**:
  - `DspGraph.EmptyGraphIsIdentity` — no-op chain.
  - `DspGraph.GainNodeScalesEverySample` — direct math.
  - `DspGraph.LowpassAttenuatesHighFrequencySine` — 10 kHz
    sine through 1 kHz LP, peak < 0.1 in steady state.
  - `DspGraph.HighpassPreservesHighFrequencySine` — same
    sine through 1 kHz HP, peak > 0.8.
  - `DspGraph.ChainOrderProducesSameOutputForLinearNodes` —
    `gain · LP ≡ LP · gain` (linear-system commutativity).
  - `DspGraph.ResetClearsBiquadState` — step input followed
    by reset + zero input yields zero output.

### What deliberately did NOT land

- **HRTF node.** Analytical HRTF code lives in
  `cd::audio::AnalyticalHRTF` already. Wrapping it as an
  IDspNode is a small follow-up; the more interesting work
  is calibrating against measured HRTF datasets (CIPIC,
  HUTUBS), which needs human-ear validation.
- **Convolution reverb.** Requires impulse-response data
  + FFT for fast convolution. Out of scope for the
  structural pass.
- **DAG topology** (merges / splits / branches). The chain
  shape covers per-source pipelines; a real mixer DAG is
  its own primitive.
- **Real-time priority / lock-free queues.** The graph
  runs on whatever thread the caller hands it samples from;
  the WASAPI backend already manages thread priority via its
  own callback. Embedding the graph inside the audio
  callback path is a wiring decision per backend.
- **Sample CMakeLists update.** No new sample shipped; the
  unit tests are the marathon-shippable proof. A
  `hello_dsp_graph` interactive sample (sine wave through
  user-tunable cutoff knob) is a Phase-15 candidate when
  the audio output path is interactively wired.

## Rejected alternatives

- *Pull in a vendored DSP library (e.g. miniaudio's
  effects).* Rejected: ~200 LOC for 2 node types is below
  the vendor threshold; the engine's no-vendor policy on
  small primitives matches this case.
- *Use std::function for the process callback instead of
  IDspNode.* Rejected: state-bearing nodes (biquads) need
  named state that survives across process() calls; a
  class hierarchy is the right shape.
- *Allow process() to allocate.* Rejected: production
  audio callbacks must not allocate. The graph layer's
  ABI doesn't enforce noexcept (some derived nodes may
  want exceptions for parameter validation), but the
  default node implementations are allocation-free.
