# ADR — v0.44.0 / Wave 168 — Phase 15.C DXC / Shader Model 6

- Date: 2026-05-24
- Status: Accepted
- Wave: 168
- Predecessor: Wave 167 (v0.43.0 D3D12 descriptors)

## Context

Phase 14.C wired D3DCompile2 → SM5_1 DXIL for the D3D12 backend.
SM6+ targets (required for ray-tracing raygen/closesthit/miss,
mesh shaders, wave intrinsics, HLSL 2021 features) need DXC.
The Windows SDK 10.0.26100 ships dxcompiler.lib + dxcompiler.dll
+ dxil.dll, so no FetchContent is needed.

## Decision

Tag (deferred to Phase 15 close). Scope: extend `compile_hlsl` to
route SM5_1 through D3DCompile (existing) and SM6_0 / SM6_5
through DXC's IDxcCompiler3. Editor camera-direction bug fixed in
the same commit since both surfaces ride the same v0.44.0 build.

### What landed

- New `cd::rhi_d3d12::ShaderModel { kSM5_1, kSM6_0, kSM6_5 }` in
  the public header.
- `CompileOptions.model` defaults to kSM5_1 — every existing
  consumer (hello_d3d12_triangle, hello_d3d12_clear) compiles
  through the legacy path with no source change.
- `compile_sm5_d3dcompile()` — refactored old D3DCompile path.
- `compile_sm6_dxc()` — new DXC path:
  - `DxcCreateInstance(CLSID_DxcUtils / CLSID_DxcCompiler)`
  - `IDxcCompiler3::Compile(DxcBuffer source, args[], ...)`
  - Targets: `vs_6_0` / `ps_6_0` / `cs_6_0` / `gs_6_0` /
    `hs_6_0` / `ds_6_0` for SM6_0; `*_6_5` for SM6_5.
  - RT stages (RayGen / ClosestHit / AnyHit / Miss /
    Intersection / Callable) map to `lib_6_5`.
  - Mesh / Task stages map to `ms_6_5` / `as_6_5`.
  - HLSL 2021 enabled via `-HV 2021`.
  - Debug builds add `-Od -Zi`; release `-O3`.
  - Failure surfaces full DXC error blob via owning ErrorCode.
  - Missing dxcompiler.dll at runtime returns
    `kDxcUnavailable` (new error code).
- CMakeLists links `dxcompiler` alongside `d3dcompiler`. Both
  ship from `$WindowsSdkDir/Lib/<ver>/um/x64/`.
- Pragma fix: the existing
  `#pragma clang diagnostic ignored -Wlanguage-extension-token`
  in D3D12ShaderCompile.cpp covered only the include block; the
  DXC `IID_PPV_ARGS` call sites need the same. Push extended to
  wrap the entire TU; explicit pop at file bottom.

### Editor camera bug fix (rides v0.44.0)

User-visible: hello_editor's 3D viewport (Phase 14.E) appeared
empty in the v0.42.0 build. Root cause: the new free-fly
camera's initial yaw was π (= forward direction -X). The three
cubes sit at x ∈ {-1.6, 0, 1.6}, y=0, z=0; with eye at (0, 2, 5)
looking down -X, the cubes are behind the camera (sideways).
Fix: initial yaw = -π/2 (= forward -Z), eye pulled back to z=6.
Now opens looking straight at the cubes.

### What deliberately did NOT land

- **DXC redistribution.** dxcompiler.dll + dxil.dll are
  required at runtime. Currently consumers depend on the
  Windows SDK PATH or copy the DLLs alongside the .exe by
  hand. A CPack/installer wave will pick them up.
- **Auto-selecting SM6 when the device supports it.** The
  current path requires the caller to set
  `CompileOptions.model = kSM6_0`. A "pick best model" helper
  is small follow-up polish.

## Rejected alternatives

- *Vendor DXC via FetchContent of the GitHub release tarball.*
  Rejected: the Windows SDK already ships it; pulling a
  second copy doubles disk usage.
- *Move the entire compile_hlsl impl behind DXC.* Rejected:
  D3DCompile is still the right path for SM5 targets which
  most existing shaders use; keeping both is the pragmatic
  short-term shape.

## Consequences

- D3D12 backend can now produce DXIL targeting SM6 (RT, mesh
  shaders, HLSL 2021).
- Existing samples unchanged — kSM5_1 default keeps
  hello_d3d12_triangle on the legacy path.
- Editor 3D viewport is now visibly populated by the cubes
  (camera-direction bug closed).
- Phase 15.D opens next.
