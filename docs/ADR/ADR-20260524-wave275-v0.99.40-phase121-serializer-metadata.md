# ADR-20260524 / Wave 275 / v0.99.40 / Phase 121 — Serializer Metadata Round-Trip

## Status
Accepted — 2026-05-24

## Context

The Phase 14.A `serialize_scene` / `deserialize_scene` only round-tripped
`LocalTransform` data. Anything sample-side or game-side that needed
to attach entity name, tint colour, mesh kind, gameplay tags, etc.
had to maintain a parallel side-table — and as `hello_editor` showed
in Phase 103, that side-table got out of sync on save/load (entities
came back as `n_0/n_1/n_2` instead of `Cube/Sphere/Cone`).

## Decision

Two new templated overloads in `cd/scene/Serializer.hpp`:

- `serialize_scene_with(scene, write_extras)` — calls `write_extras(e, obj)`
  before emitting the canonical `id / translation / rotation / scale /
  parent` keys, so the caller can inject any extra JSON fields.
  Canonical keys win on collision.
- `deserialize_scene_with(scene, json, read_extras)` — same as
  `deserialize_scene` but calls `read_extras(entity, node_obj)` once
  per node after creating the entity, giving the caller a chance to
  pull custom fields off the JSON.
- Old `serialize_scene` / `deserialize_scene` kept as thin no-op-
  callback wrappers — fully backward compatible.

Forward-declares for the templates live near the top of the header
so the non-template wrappers can call them.

hello_editor migrated to the new API: save writes `name`, `tint`,
`mesh` keys; load reads them back through the callback and sets
`SceneEntity::name / tint / mesh` properly. Legacy saves without
those keys still load (callback falls back to the Cube/Sphere/Cone
seed sequence).

## Rejected alternatives

- **Bump `kSceneJsonVersion` to 2 and rename `serialize_scene`** —
  would force every existing user to migrate. The callback overload
  is additive and doesn't break the v1 format.
- **Component-driven serialization (each component type registers
  its own JSON schema)** — proper end-game solution but a bigger
  scope than this phase. The callback hook is the smallest delta
  that solves the immediate "name disappears on round-trip" bug.
- **Embed a `name` / `tint` directly in the serializer** — pulls
  string handling and arbitrary engine-side concepts into a header
  that was strictly transform-only. Callback keeps the serializer
  oblivious to "what extra means."

## Consequences

- `cd::scene::Serializer` API grows two templated functions; no
  link-line changes.
- Sample / tool code that needs per-entity metadata can now keep
  it round-tripping through the same JSON the canonical serializer
  produces.
- Phase 122 candidate: introduce a real `EntityName` ECS component
  so the engine has a one-true-source for names instead of every
  sample maintaining its own side-table.

## Validation

```
cmake --build --preset llvm-win-debug --target cd_sample_hello_editor
./build/llvm-win-base/bin/Debug/hello_editor.exe
# Save, close, relaunch, Load — sphere + cone names + meshes survive.
```
