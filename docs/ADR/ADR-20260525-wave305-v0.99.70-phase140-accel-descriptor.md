# ADR Wave-305 — Phase 140 DescriptorType::kAccelerationStructure (v0.99.70)

- **Date:** 2026-05-25
- **Status:** Accepted
- **Predecessor:** [ADR-20260525-wave304-v0.99.69-phase150-async-streamer-demo](./ADR-20260525-wave304-v0.99.69-phase150-async-streamer-demo.md)
- **Successor:** ADR Wave-306 (Phase 141 hello_rt real ray dispatch)
- **Tag:** v0.99.70

## Context

Phase 132 (Wave 293) added BLAS/TLAS create + build to the RHI.
Phase 135 added the RT pipeline. Phase 136 shipped hello_rt which
**creates** RT shaders + pipeline + SBT but **cannot dispatch rays**
because there was no way to bind the TLAS into a raygen shader —
the descriptor side of the chain was missing.

The blocking piece is a new `DescriptorType` enumerator + the backend
wiring needed to translate it into a `VkAccelerationStructureKHR` (or
DXR `RaytracingAccelerationStructure` SRV).

## Decision

Add `cd::rhi::DescriptorType::kAccelerationStructure` and:

1. **`DescriptorWrite` extension:** new `AccelStructureHandle accel`
   field, populated when the write type is `kAccelerationStructure`.
   Forward-include already pulls `Handles.hpp` so no new header
   dependency.

2. **Vulkan `map_descriptor_type`:** add the `VK_DESCRIPTOR_TYPE_*`
   `_ACCELERATION_STRUCTURE_KHR` case.

3. **Vulkan `update_descriptor_set`:** add a new switch case that
   chains a `VkWriteDescriptorSetAccelerationStructureKHR` via
   `pNext`. The struct (and the `VkAccelerationStructureKHR` it
   points at) live in two `std::vector`s reserved up-front so the
   pointers stay valid through the `vkUpdateDescriptorSets` call.

4. **D3D12 root-signature mapping:** acceleration structures bind
   as SRVs of a special `RAYTRACING_ACCELERATION_STRUCTURE` type.
   The root-signature **range** is plain SRV; the descriptor-write
   side fills in the `D3D12_SHADER_RESOURCE_VIEW_DESC` with the AS
   GPU virtual address. For Phase 140 we wire the range mapping;
   the write-side will arrive with Phase 142 (D3D12 DXR Tier 1.1).

## Rejected alternatives

- **Standalone `AccelDescriptorWrite` struct** — would require a
  parallel API path or a `std::variant`. The unified `DescriptorWrite`
  with an extra optional field keeps the caller API tidy at the cost
  of one unused 8-byte handle slot per non-AS write. Acceptable.
- **AS-as-buffer** — DXR Tier 1.0 lets you bind the AS as a raw
  buffer SRV. Vulkan does not. Going through the dedicated AS
  descriptor type works on both APIs once both ends are wired.
- **Synthesize the `pNext` payload at the call site** — would have
  pushed Vulkan-specific knowledge into engine code. Backend
  encapsulation matters more than the extra two vectors.

## Consequences

- The piece blocking real `vkCmdTraceRaysKHR` execution is now in
  place. Phase 141 (next phase) consumes it.
- D3D12 backend's `kNotImplemented` count is unchanged: the writes
  still need to actually fill in the SRV, which we defer with Phase
  142. The root-signature parity is gained today, the GPU dispatch
  parity arrives with 142.
- `hello_rt`'s leading docstring already names "DescriptorType::
  kAccelStructure wired" as the next deliverable, so the existing
  sample comment becomes accurate when Phase 141 lands.

## Open follow-ups

- Phase 141: storage-image output + TLAS descriptor set + real
  `dispatch_rays` in hello_rt.
- Phase 142: D3D12 DXR Tier 1.1 mirror — write-side AS SRV fill,
  StateObject helpers, ID3D12GraphicsCommandList4::DispatchRays.
