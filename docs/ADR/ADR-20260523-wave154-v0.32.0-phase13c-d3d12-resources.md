# ADR — v0.32.0 / Wave 154 — Phase 13.C D3D12 buffer + texture + swapchain

- Date: 2026-05-23
- Status: Accepted
- Wave: 154
- Tag: v0.32.0
- Predecessor: ADR-20260523-wave153 (v0.31.0 lavapipe golden infra)
- Phase 13 master: ADR-20260523-wave151-phase13-plan.md

## Context

Phase 12.B / v0.27.0 shipped the D3D12 backend's boot path —
ID3D12Device + IDXGIFactory6 + adapter selection + DIRECT command
queue + idle fence. Every other entry point on the 51-virtual
IDevice surface returned `kNotImplemented`.

Phase 13.C per the wave151 plan: ship the smallest set of methods
that lets a real `hello_d3d12_clear` sample render a color clear
end-to-end on the D3D12 path.

## Decision

Tag **v0.32.0**. Scope: buffer + texture + swapchain creation,
buffer upload/download, present, and a trivial command-list path.

### What landed

- **Buffer methods** — `create_buffer` / `destroy_buffer` /
  `upload_buffer` / `download_buffer`. Maps engine `MemoryUsage`
  to D3D12 heap types (DEFAULT / UPLOAD / READBACK) via
  `heap_type_for()`. Upload + download paths use Map + memcpy +
  Unmap; UPLOAD/READBACK only at v0.32.0 — a staging-buffer-based
  GpuOnly upload path is queued for a later wave.
- **Texture methods** — `create_texture` / `destroy_texture` for
  k2D textures with the format subset that the MVP renderer
  actually consumes (RGBA8 / BGRA8 + sRGB siblings, RGBA16/32
  float, D32/D24S8). Other texture types surface
  `kNotImplemented`; the format table grows one obvious-shape
  line per entry when a sample demands it.
- **Swapchain methods** — `create_swapchain` /
  `destroy_swapchain` / `acquire_next_image` / `present` /
  `swapchain_image` / `swapchain_image_view` /
  `swapchain_image_count`. Uses DXGI flip-model
  (`FLIP_DISCARD`) over `IDXGISwapChain3`. Per back-buffer the
  device creates a `D3D12_RENDER_TARGET_VIEW_DESC` on a
  dedicated RTV descriptor heap and registers the back-buffer
  as an engine `TextureHandle` + `TextureViewHandle` so sample
  code can hand it to the command-buffer clear path. The
  SRGB-format-on-UNORM-swapchain trick is wired so callers can
  ask for `kRGBA8Srgb` and still get a flip-model swapchain.
- **`D3D12CommandBuffer`** — a trivial `ICommandBuffer`
  implementation just sufficient for the clear case. Supports
  `begin` / `end` / `begin_render_pass` (with
  `LoadOp::kClear` → `ClearRenderTargetView` and the surrounding
  COMMON↔RENDER_TARGET↔PRESENT transitions) / `end_render_pass`.
  Everything else (PSO bind, draws, copies) is a no-op or
  `kNotImplemented`; the PSO surface is the Phase 14 candidate
  shape.
- **`create_command_buffer` + `submit`** — direct command-list
  per call (1 allocator + 1 list); `submit` invokes
  `ExecuteCommandLists`. Per-frame fence sync is the caller's
  job (the sample uses `wait_idle()` between frames, which is
  fine for clear-only).
- **`samples/hello_d3d12_clear`** — opens a 640×360 Win32 window,
  creates a 2-image swapchain, and renders a teal clear in a
  message-pump loop. Esc / window close exit; the env var
  `CD_D3D12_CLEAR_HEADLESS_FRAMES=N` caps the loop at N frames
  so CI can use it as a smoke binary. Verified on NVIDIA
  GeForce RTX 3080 Laptop GPU at v0.32.0:
  `[d3d12] clear loop OK — rendered 5 frame(s)`.

### What deliberately did NOT land

- **PSO + draw surface.** `create_graphics_pipeline` /
  `create_compute_pipeline` / `bind_pipeline` / `draw` /
  `draw_indexed` / `dispatch` all surface `kNotImplemented`.
  Closing them needs a HLSL → DXIL shader path
  (`D3DCompile2` or the new DXC) which is its own subsystem.
- **Descriptor sets.** D3D12's root signature + descriptor
  table / heap model is *not* a 1:1 with Vulkan's
  descriptor-set abstraction. Wiring it requires a small
  design pass (a root-sig builder + per-frame descriptor heap
  ring), which belongs in a later phase.
- **Staging-buffer-based GpuOnly upload.** A `DEFAULT` heap
  buffer can't be Mapped directly; uploading to it needs a
  staging UPLOAD buffer + a `CopyBufferRegion` + a fence
  signal. The `--memory-class` plumbing is in place; the
  staging dance is deferred.
- **Texture upload (CopyTextureRegion).** Same staging story.
  Phase 13.C explicitly excluded texture upload per the
  wave151 plan ("create_texture / destroy_texture — no upload
  for now"); the no-op preserved that scope.
- **SubmitDesc path with explicit semaphores / fences.** D3D12
  synchronization is fence-only at the queue level; mapping
  the cross-API SubmitDesc shape onto D3D12 wants the same
  semaphore-bridging story that the Metal backend will need.
  Deferred to the unified-sync wave.

## Rejected alternatives

- *Ship draws too — go all the way to a triangle.* Rejected: the
  PSO + DXIL compile + root-sig design is non-trivial and would
  delay v0.32.0 indefinitely. Clear-only is the smallest
  defensible end-to-end milestone (boot + swapchain + present
  proven on real hardware) and isolates the PSO surface as a
  clean next-wave target.
- *Reuse Vulkan's command-buffer abstraction directly with
  D3D12 backend implementing the same methods.* Already done at
  the interface level (`ICommandBuffer`). The D3D12-side
  command-buffer class is intentionally minimal — adding the
  full surface alongside `kNotImplemented` Result returns would
  hide the partial-implementation state from compile-time
  consumers. Stubs surface `kNotImplemented` loudly until the
  PSO wave; that's a feature.
- *Auto-detect swap-format SRGB and route via UNORM
  back-buffer transparently to the caller.* Implemented but
  with an explicit `swap_format` field in `SwapchainRecord` so
  the RTV creation knows the user's intent. The caller never
  sees the under-the-hood UNORM substitution.
- *Skip the sample, rely on a unit test.* Rejected: the v1.0
  rollback was caused by tests passing while the visible output
  was wrong. A sample that visibly clears to teal is the
  evidence; a unit test that asserts ClearRenderTargetView was
  called is not.

## Consequences

- v0.32.0 is the new latest SemVer marker.
- D3D12 path is the second working RHI backend (alongside
  Vulkan), opening the door to Phase-13.D-and-beyond
  cross-backend work.
- Phase 13.D (editor UI bridge → v0.33.0) opens next.
- Future PSO work in cd::rhi_d3d12 has a clean integration
  shape — the existing D3D12CommandBuffer skeleton can grow
  the draw/bind methods incrementally without touching the
  resource side.
