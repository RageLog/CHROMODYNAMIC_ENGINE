# ADR — v0.28.0 / Wave 149 — Phase 12.C editor undo/redo

- Date: 2026-05-23
- Status: Accepted
- Wave: 149
- Tag: v0.28.0
- Predecessor: ADR-20260523-wave148 (v0.27.0 D3D12 boot)

## Context

The `cd::editor` library already shipped:
- An integration shell (Editor class owning World + Scene + Input).
- Three widgets via `cd::editor_ui` (PropertyInspector,
  TransformGizmo, SceneTreeView).
- Hand-routed input through the widget tree.

What was missing — every editor's most basic primitive — was an
undo/redo command stack. Without it, gizmo / inspector edits go
straight to the live scene with no way to reverse them.

Phase 12.C per Wave 142 was "editor stack maturation → v0.28.0".

## Decision

Tag **v0.28.0**. Scope: the undo/redo primitive + concrete commands
for the three transform mutations editors actually emit.

### What landed

- **`cd::editor::ICommand`** — pure-virtual base. Each subclass
  captures enough state to undo itself; the editor doesn't need to
  know command types at compile time, so gameplay / plugin code can
  ship their own.
- **`cd::editor::EditHistory`** — bounded LIFO of unique_ptr<ICommand>.
  `Config` carries max_entries (default 128) and max_bytes (default
  4 MiB); push() applies immediately, evicts oldest when caps fire.
  `next_undo_label()` / `next_redo_label()` directly drive UI menu
  strings.
- **`cd::editor::TranslateCommand` / `ScaleCommand` / `RotateCommand`**
  — three concrete commands targeting cd::scene::LocalTransform.
  TranslateCommand stores a delta and adds/subtracts; ScaleCommand
  stores the pre-apply scale vector to restore on revert; RotateCommand
  overwrites the quaternion (matches inspector/gizmo UX which writes
  a new pose in one shot, not a delta).
- **8 new gtests** cover push-apply semantics, undo+redo round-trip,
  push-after-undo-discards-redo, entry-cap eviction at the bound,
  clear() wiping both stacks, and the three transform commands'
  round-trips against a real cd::scene::Scene + cd::ecs::World.

### What deliberately did NOT land

- **Editor sample integration** — a `hello_editor` sample wiring
  the EditHistory into an interactive ImGui window. The existing
  cd::ui-based Editor class doesn't render through ImGui; bridging
  is a separate decision (port cd::ui to ImGui, or write a fresh
  ImGui editor that re-uses World/Scene). Defer to Phase 13.
- **Coalescing** — successive translations of the same entity could
  collapse into one history entry. Out of scope; deferred.
- **Persistence** — save/restore history across editor sessions.
  Deferred (would require cd::asset_json serialization of every
  command type, which becomes a versioning headache).
- **Multi-pane dock layout / asset browser / 3D viewport** — these
  are UX work, hard to validate without a human in the loop.
  Deferred to Phase 13 hardening.

The Phase 12.C scope in Wave 142 said "scene tree + asset inspector
+ undo/redo + dock layout + hello_editor sample". This v0.28.0 ships
only the **undo/redo primitive** because every other item carries
UX-validation risk the marathon has no human to absorb. The primitive
itself is testable headlessly + composable from any future editor
front-end.

## Rejected alternatives

- *Ship hello_editor sample driven by ImGui.* Rejected: the existing
  cd::editor uses cd::ui (not ImGui); writing a parallel ImGui
  editor doubles the surface and the choice should go through a
  human review.
- *Add coalescing in the same wave.* Rejected: coalescing has
  policy questions (time-window vs. command-type matching vs. user
  flag) that benefit from real editor usage feedback first.
- *Skip the transform commands and ship only the EditHistory base.*
  Rejected: an empty primitive with no concrete users is harder to
  validate. Three concrete commands prove the abstraction works
  end-to-end and let future commands copy the pattern.

## Consequences

- v0.28.0 is the new latest SemVer marker.
- cd::editor now has the undo/redo primitive any editor UX layer
  needs as a foundation.
- The "real interactive editor" (ImGui bridge, dock layout, asset
  browser, hello_editor sample) is queued for Phase 13.
- Phase 12.D (ray tracing + mesh shaders) opens next.
