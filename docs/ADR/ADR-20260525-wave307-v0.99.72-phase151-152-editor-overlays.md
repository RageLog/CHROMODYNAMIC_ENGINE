# ADR Wave-307 — Phase 151+152 selection outline + axis gizmo overlays (v0.99.72)

- **Date:** 2026-05-25
- **Status:** Accepted
- **Predecessor:** [ADR-20260525-wave306-v0.99.71-phase141-hello-rt-real-dispatch](./ADR-20260525-wave306-v0.99.71-phase141-hello-rt-real-dispatch.md)
- **Successor:** ADR Wave-308 (Phase 143-148 OpenGL backend chain)
- **Tag:** v0.99.72

## Context

Phase 115 (Wave 283) shipped `cd::editor::SelectionOutline` state
primitive and Phase 116 (Wave 284) shipped `cd::editor::AxisGizmo`
state primitive. Both had no editor-side consumer — the MARATHON
SUMMARY listed them under "Outstanding integration":

> Editor selection outline + axis-translation gizmo

This phase wires both into `hello_engine` as ImGui foreground-draw
overlays. No new render pass; no new shader.

## Decision

### Phase 151 — SelectionOutline (kWireframe style)

Each frame:

1. Mirror `selected` index into `outline.set(entities[selected].handle)`.
2. For every entity in `outline.entities()`, project its world
   position through the per-frame VP into pixel space.
3. Draw a colored circle + crosshair via
   `ImGui::GetForegroundDrawList()->AddCircle / AddLine`.
4. Circle radius shrinks with distance (∝ 1/clip.w).
5. Style is driven from `OutlineStyle::kWireframe` (kStencilEdge and
   kJumpFlood remain future work — they need real GPU passes).

Defaults: warm orange `(1.0, 0.55, 0.05)`, thickness 1.5, opacity 1.0.

### Phase 152 — AxisGizmo (translation, ImGui interaction)

Each frame, when an entity is selected and the gizmo is visible:

1. Project gizmo origin + `(target + axis_dir * 1.5)` endpoints for
   X / Y / Z to pixel space.
2. Draw three colored arrows (red/green/blue) with arrowheads via
   `dl->AddTriangleFilled`.
3. Hover test: perpendicular distance from mouse pixel to each
   axis line segment; pick the closest within
   `gizmo.hover_tolerance_pixels (= 8.0)`.
4. On left-click + axis hover (and not over any ImGui UI item):
   call `gizmo.begin_drag(axis, target)`, snapshot the screen
   mouse anchor + the world-space starting position.
5. While dragging: compute mouse screen-delta, project it onto the
   on-screen axis direction (dot product), convert px→world via
   `kAxisLen / on_screen_px_length`, apply to the active axis
   component, drive the live position, and update `gizmo.update_drag`.
6. On mouse-up: `gizmo.end_drag()` returns the total delta; roll
   back the live mutation and push a `cd::editor::TranslateCommand`
   so the EditHistory undo stack stays consistent.

New palette command `95 — Gizmo: Toggle Visibility`.

## Rejected alternatives

- **Real GPU outline pass (kStencilEdge / kJumpFlood)** — needs a
  new render-target + post-process shader. Out of scope for an
  editor-polish phase; the wireframe-overlay is the engine's
  documented "cheapest" outline style.
- **Full mouse-ray-vs-axis-cylinder in 3D** for gizmo picking —
  the perpendicular-distance test in screen space is robust enough
  at this scale and avoids inventing ray APIs.
- **Push a TranslateCommand on every mouse-move sample during drag**
  — would spam EditHistory with hundreds of micro-commands per drag.
  Single command on release is the standard editor pattern.
- **Drive gizmo by world-space ray test (depth-correct)** — would
  not change the visible behavior at the camera distances
  hello_engine uses; the screen-space approach picks the right
  axis on every test we did.

## Consequences

- Marathon's WAVE C (editor polish) is complete.
- Both Phase-115 and Phase-116 engine primitives now have visible
  consumers.
- The TransformCommands / EditHistory undo flow is exercised by an
  interactive widget (was only exercised by inspector-driven edits
  before).

## Open follow-ups

- Real GPU outline pass (kStencilEdge or kJumpFlood) once the engine
  ships a post-process framework.
- Rotation + scale gizmos (separate state machines + UI affordances).
- Snap-to-grid / snap-to-axis modifier-key support during drag.
