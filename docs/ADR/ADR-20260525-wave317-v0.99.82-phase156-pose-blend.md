## Context

Phase 5/S4.2.b shipped the skeletal primitives long ago:
`Skeleton`, `Pose`, `SkinnedClip` with per-joint keyframe sampling,
and `compute_skinning_matrices` for GPU upload. The MARATHON deferral
(Wave-310) noted that the engine had no skinned-mesh asset to drive
end-to-end character animation.

The missing piece between "sample a single clip" and "production
character controller" is **pose blending** — every game does this
to transition between idle ↔ walk ↔ run or layer an upper-body
action onto locomotion. This phase adds the math; the GPU upload
+ skinned-mesh asset format remain v1.2+ work.

## Decision

New header `cd/anim/PoseBlend.hpp` (header-only):

```cpp
namespace cd::anim {

cd::math::Transformf lerp_transform(const Transformf& a,
                                    const Transformf& b, float t) noexcept;

void blend_pose(const Pose& a, const Pose& b, float weight, Pose& out);

void blend_pose_into(Pose& target, const Pose& b, float weight,
                     const std::function<bool(std::size_t)>& joint_filter = {});

void additive_apply(const Pose& base, const Pose& additive, float weight,
                    Pose& out);

}  // namespace cd::anim
```

### Semantics

- **`lerp_transform`**: lerp position + scale, slerp rotation.
- **`blend_pose(a, b, w, out)`**: out[i] = lerp(a[i], b[i], w) for
  every joint in the common prefix. Output is sized to
  `min(a.size, b.size)`.
- **`blend_pose_into(target, b, w, filter)`**: in-place version with
  an optional joint filter for upper/lower-body layering. The filter
  callback returns true for joints that should blend, false to skip.
- **`additive_apply(base, additive, w, out)`**: treats `additive`'s
  joint locals as DELTAS from bind pose. Position += delta × w;
  scale lerps from base toward (base × delta); rotation slerps
  from base toward (delta × base). Common for "breathing" or
  "head tilt" overlays.

### Reasoning

- **Joint-by-joint lerp + slerp** matches the convention every
  modern engine uses (Filament, production engines, production engine, Bevy, raylib, Godot).
- **Filter callback** keeps the API minimal — no separate
  `PoseMask` class. Callers compose layered animation by writing
  one lambda per body region.
- **Additive treats deltas explicitly** — the engine doesn't
  pre-compute "additive clips" at import time; the runtime
  consumes any pose as additive if the caller chooses.

## Test result

6 new tests in `cd_test_anim` pin the contract:

- `PoseBlend.WeightZeroReturnsLeft`
- `PoseBlend.WeightOneReturnsRight`
- `PoseBlend.WeightHalfLerpsLinearly`
- `PoseBlend.FilterSkipsExcludedJoints`
- `PoseBlend.AdditiveWithWeightZeroIsBase`
- `PoseBlend.AdditiveWithWeightOneAppliesFullOffset`

All green; 58/58 ctest surface still passing.

## Rejected alternatives

- **Single `Pose blend(a, b, w)` returning by value** — would
  allocate a fresh vector per call. The in/out reference signature
  lets callers reuse a scratch Pose across frames.
- **Quaternion-only blending** (skip position + scale) — a real
  pose carries all three transform components; partial blending
  would force callers to interleave with manual position lerp.
- **AnimationStateMachine class** — out of scope for this phase.
  The primitives this header ships are the building blocks any
  state-machine layer would use; designing the state machine on
  top is a follow-up.

## Consequences

- The engine now has the math for character animation transitions
  + layered actions.
- Combined with the existing `SkinnedClip::sample`, callers can
  build a frame loop like:
  ```cpp
  Pose idle, walk, out;
  idle_clip.sample(t_idle, idle);
  walk_clip.sample(t_walk, walk);
  blend_pose(idle, walk, transition_weight, out);
  compute_skinning_matrices(skel, out, gpu_matrices);
  ```
- The MARATHON_SUMMARY skeletal-anim bullet is now infrastructure-
  complete for v1.1.

## Open follow-ups

- Skinned glTF importer + skinned-mesh asset format.
- GPU-side skinning matrix UBO/SSBO upload + vertex shader path.
- `AnimationStateMachine` driving blend weights based on velocity
  / input state.
