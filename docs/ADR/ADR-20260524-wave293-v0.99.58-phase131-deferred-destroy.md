# ADR-20260524 / Wave 293 / v0.99.58 / Phase 131 — DeferredDestroy queue

## Status
Accepted — 2026-05-24

## Context

The Vulkan AS-build cmd path (next phase) needs to allocate
transient scratch buffers per build, and the build's GPU work
keeps reading those buffers until the frame's submit fence
completes. The buffer can't be destroyed at end-of-command-buffer
recording — it has to be destroyed once the GPU is done with it.

This same pattern recurs for:

- staging buffers used for inline upload-then-discard,
- query pools released after readback,
- intermediate cubemap render targets used once,
- transient AS scratch buffers (immediate trigger).

## Decision

New header-only `cd/rhi/DeferredDestroy.hpp`:

- `DeferredDestroy::enqueue(frame_id, std::function<void()>)` — queue an
  action to run once `flush_completed(f)` is called with
  `f >= frame_id`.
- `flush_completed(last_completed_frame)` — walks the queue,
  invokes + drops every action whose frame_id is satisfied.
  Returns fire count.
- `flush_all()` — used at device shutdown after a `wait_idle()`.
- `pending()` — diagnostic.

Backend code constructs one `DeferredDestroy` on the device,
command buffers / device methods push into it via a reference.
The renderer's per-frame epilogue (after the in-flight wait /
reset) calls `flush_completed(current_frame)`.

## Rejected alternatives

- **Per-command-buffer destroy list.** Doesn't work — a command
  buffer is recorded once but may be replayed across multiple
  frames; the destroy has to be keyed by submit frame, not
  recording.
- **Per-resource fence parameter.** Forces every destroy call site
  to plumb a fence around. The deferred queue centralises the
  bookkeeping.
- **`std::vector` instead of `std::deque`.** Both work; `deque`
  for iterator stability across `erase` mid-walk (we drop matched
  entries during the flush iteration).

## Consequences

- `cd::rhi` gains one header-only utility (44 LoC).
- Phase 132 (Vulkan cmd-buffer AS build BLAS) becomes a pure-
  additive override that pushes the scratch destroy into the
  queue.
- Build still verified clean.

## Validation

```
cmake --build --preset llvm-win-debug
```

Full engine + 33 samples + tools rebuild clean. The new header is
unconsumed today; sole purpose is to land the type so Phase 132
can use it.
