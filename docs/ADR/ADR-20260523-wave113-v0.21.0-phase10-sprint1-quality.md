# ADR — v0.21.0 / Wave 113 — Phase 10 Sprint 1 (Quality leg complete)

- Date: 2026-05-23
- Status: Accepted
- Wave: 113
- Tag: v0.21.0

## Context

v0.20.0 closed Phase 8 at 7/7 and opened Phase 10 with one Quality-leg
item shipped (cd::diag assertion macros, Wave 107). Sprint 1's stop
condition (per Wave 106's ADR) is:

> Foundation tier exposes a structured diagnostics + logging + formatting
> stack that crash-triages itself and renders cleanly in Doxygen.

Five more waves landed between v0.20.0 and v0.21.0 to satisfy that:

- **Wave 109** `cd::core::format(ErrorCode)` + domain/code name registry.
  Library boundaries can now produce log-friendly error strings
  ("core::InvalidArgument: x must be >= 0") without polluting ErrorCode
  with name fields.
- **Wave 110** `cd::log::RingBufferSink` — bounded in-memory observer
  for the last N LogRecords, designed for crash-handler triage. Wraps
  on overflow, mutex-guarded snapshot, header-only because cd::log is
  INTERFACE.
- **Wave 111** `cd::log::install_panic_dump_handler` — wires a
  RingBufferSink into cd::diag's panic path so the last N log records
  flush to stderr right before the structured PanicInfo. cd::log now
  depends on cd::diag (one-way, as the layering demands).
- **Wave 112** `docs/Modules.dox` — Doxygen module hierarchy so the
  sidebar groups APIs by subsystem. Foundation tier broken into
  core/diag/log/math/mem/concurrency/io/platform/time/profile/events/
  vfs/plugin; render tier into rhi/cluster; plus asset, world, script,
  runtime, imgdiff at the top. Zero-warning Doxygen build verified.

## Decision

Tag **v0.21.0**, closing Phase 10 Sprint 1 (Quality leg). The Foundation
tier now exposes the integrated stack required by the stop condition:
asserts that panic into typed PanicInfo (Wave 107), structured error
codes that pretty-print across library boundaries (Wave 109), a log
mirror that survives a crash (Wave 110), a panic handler that dumps
the mirror (Wave 111), and a Doxygen module tree the API renders into
cleanly (Wave 112).

## Rejected alternatives

- *Make ErrorCode carry its own name strings.* Rejected: ErrorCode is
  passed by value across hot fallible boundaries; bloating it with
  pointer-sized name fields per code costs every call site. A runtime
  registry is touched only on the cold formatting path.
- *Build the panic handler with a captured sink (std::function).*
  Rejected: cd::diag's handler signature is a free function pointer for
  ABI stability across library boundaries. The bridge uses an inline
  std::atomic<RingBufferSink*> instead — no std::function, no captures,
  works across DLL boundaries.
- *Skip Doxygen modules and let everything render flat.* Rejected: the
  engine is already at ~55 libraries (per CMake summary); without a
  group tree the Doxygen sidebar is unreadable.

## Consequences

- Phase 10 Sprint 1 stop condition met. Sprint 1 closes.
- Sprint 2 (Docs leg) opens next: README polish, ARCHITECTURE.md with
  a dependency-DAG diagram, per-subsystem doc/ pages, opt-in @ingroup
  tags on public headers so the Modules tree fills out.
- v0.20.0 → v0.21.0 → … → v1.0.0 path still on track. No carry-over
  from Sprint 1 into Sprint 2.
- All 58 ctest targets remain green on ninja-debug.
