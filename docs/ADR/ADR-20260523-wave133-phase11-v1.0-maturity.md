# ADR — Wave 133 — Phase 11 plan: the real v1.0 maturity path

- Date: 2026-05-23
- Status: Accepted
- Wave: 133
- Supersedes: the "v1.0 path" framing in ADR-20260523-wave106 (already
  superseded once by Wave 125; this ADR is the explicit replacement
  plan).

## Context

v0.25.0 is the honest baseline (Wave 132). The marathon — Phase 1 to
Phase 10 inclusive, plus the v1.0 rollback + bug sweep + hardening +
baseline — ends here.

Phase 11 is **not a marathon**. The work flow changes:

- Conventional feature branches + PRs (no more "dev → push every wave").
- Each axis below is a long-running track, not a sprint with a wall-
  clock deadline.
- The human reviewer (project owner) drives planning. AI-assisted
  development serves the plan, doesn't author it.

What needs to be true before v1.0.0 ships, as committed in
ADR-20260523-wave125 (the rollback ADR) and re-confirmed here, is the
4-axis maturity gate below.

## Decision

Phase 11 has four parallel tracks, each tied to one v1.0-gate axis.
None block the others. All four must close before a `v1.0.0` tag is
even considered.

### Track A — Visual correctness on every windowed sample

**Goal:** zero "ctest is green but the screen is wrong" gaps.

**Acceptance:**
- All 14 windowed samples (skybox, pbr, anim, cube, obj, gltf, cooked,
  mesh, texture, framegraph, hot_reload, imgui, inspector,
  render_thread) have a committed golden screenshot reference in
  `tests/golden/<sample>.png` captured on a known GPU (current:
  NVIDIA RTX 3080 Laptop) under a known driver.
- A FLIP / SSIM diff CI gate compares smoke output against the golden
  with a tolerance band wide enough to absorb driver / OS noise but
  tight enough to catch the rollback-class regressions (BUGs #1, #2,
  #5 would have been caught).
- Per-sample `--golden <path>` flag wired through `SampleRuntime` so
  `cmake --build --target smoke-golden` writes diffs to
  `build/.../golden-diff/`.

**Sequencing:**
1. Wire `--golden` capture + diff path through `SampleRuntime` +
   `cd::imgdiff`.
2. Capture initial references on the reviewer's NVIDIA box (one wave).
3. Add CI gate (lenient threshold) to GitHub Actions.
4. Tighten threshold incrementally as cross-driver noise floor is
   characterized.

**Out of scope for Track A:** non-windowed samples (audio, stdout-
only), per-frame animation testing (golden = single frame at a
deterministic time-pin), and the cosmetic atmosphere / lighting
quality issues in `hello_skybox` and `hello_pbr` (those are
sample-completeness items, not regression risk).

### Track B — Cross-vendor GPU validation

**Goal:** the engine works on a second GPU vendor before claiming
"framework v1.0".

**Acceptance:**
- One additional desktop vendor (Intel UHD/Arc OR AMD) compiles +
  smokes + passes Track A's golden gate on the same windowed sample
  set.
- Linux CI runs `CD_ENABLE_VULKAN=ON` via SwiftShader OR lavapipe
  (software Vulkan) so the GPU code path is exercised on the Linux
  matrix that currently skips it.
- Document any per-vendor quirks in `docs/ARCHITECTURE.md` under a
  new "GPU vendor notes" section.

**Sequencing:**
1. SwiftShader / lavapipe trial: pick one, get `hello_triangle`
   rendering headless on a Linux runner.
2. Extend to the full windowed sample matrix on the SW path.
3. Identify a real-hardware second vendor for human reviewer to test
   on (Intel Arc, AMD RX, or Apple Silicon Metal-on-MoltenVK).
4. Update the v0.25.0 ADR's "single NVIDIA box" disclaimer.

**Out of scope:** D3D12 + Metal backends. `cd::rhi_d3d12` and
`cd::rhi_metal` are skeletons — they're explicitly experimental tier
and graduate post-v1.0 in v1.x.

### Track C — External downstream consumer

**Goal:** a real project, in a separate repository, links
`find_package(CHROMODYNAMIC 0.25)` and ships.

**Acceptance:**
- A second repository (sample game, demo app, or research tool —
  reviewer's call) builds against the v0.25.0 install tree without
  touching the engine source.
- That project's CMakeLists imports `cd::core`, `cd::diag`, `cd::log`
  plus at least one rendering target (the
  non-`EXCLUDE_FROM_INSTALL` ones — see ADR-20260523-wave122 for the
  cut list), and runs through a Vulkan frame.
- A "Downstream consumption guide" doc in `docs/CONSUMING.md` walks
  from `git clone` of the engine, through `cmake --install`, to the
  downstream project's `find_package` call, with realistic
  troubleshooting (missing dep, version mismatch, etc.).

**Sequencing:**
1. Reviewer picks the downstream project shape (greenfield sample,
   port of an existing toy, etc.).
2. Identify which engine surfaces it needs — drives any necessary
   export additions / fixes.
3. Write CONSUMING.md as the project's `find_package` is wired.
4. Land the downstream repo as a public reference.

**Out of scope:** lifting the 7 currently-`EXCLUDE_FROM_INSTALL`
libraries (script, rhi_vulkan, shader, etc.) into the export set —
that's the longer-tail vendored-dep wrapper work; downstream can
build-from-source against this repo until then.

### Track D — Independent review

**Goal:** at least one human other than the marathon author reads
the public API surface and the engineering invariants and signs off.

**Acceptance:**
- A reviewer who has NOT been in the marathon transcript reads:
  - `docs/ARCHITECTURE.md` (stack + DAG + conventions)
  - `docs/LIBRARIES.md` (the per-library promise)
  - `cd::core` public headers (`Result`, `ErrorCode`, `Handle`,
    `HandleStore`, `CVar`, `Version`)
  - `cd::diag` public headers (`Assert`)
  - `cd::log` public headers (`ILogger`, `RingBufferSink`, `PanicDump`)
  - The 4-axis maturity gate (this ADR)
- They produce a review document (PR comment or `docs/REVIEW-*.md`)
  flagging anything that surprised them or felt under-justified.
- Action items from the review either fold into the v1.0 surface or
  get explicit "deferred to v1.x" tags with rationale.

**Sequencing:**
1. Reviewer secured (peer, mentor, OSS community, paid consultant —
   reviewer-of-record's choice).
2. Hand off the read list + question prompts.
3. Receive review, address blocking items, doc deferred items.

**Out of scope:** review of the entire codebase. The frozen v1.0
public surface is what's load-bearing; internal implementation can
churn in v1.x.

## Marathon retrospective (one paragraph)

The marathon ran from Phase 1 (foundation skeleton) through Phase 10
(v1.0 push that rolled back). 132 waves, ~600 commits, 0.1.0 → 0.25.0.
What it built: 55 libraries, 39 samples, 58 ctest binaries, full
Vulkan rendering, Forward+ GPU compute parity-checked, WASAPI audio
verified audible, hot reload pipeline working end-to-end. What it
revealed: 5 visual bugs ctest couldn't see + 2 systemic patterns
(Vulkan-NDC winding default, version-string drift) that needed
engine-level fixes. The rollback wasn't a failure — it was the test
the gate didn't have. v0.25.0 with the gate now defined is the real
end-state of the marathon period.

## Rejected alternatives

- *Keep marathon-mode through Phase 11.* Rejected: the marathon's
  cadence was "AI writes, AI tags, AI ships" with the human reviewer
  as a downstream observer. That cadence produced the premature v1.0
  cut. Phase 11 must invert the loop — human planning first, AI
  execution second — for the maturity gate to mean anything.
- *Skip Track D (independent review).* Rejected: every Track A-C
  defense is self-issued by the same hands that built the surface.
  v1.0 backward-compat is a promise to consumers — that promise needs
  an outside eye before it's binding.
- *Add new features in Phase 11.* Rejected: Phase 10's ARCHITECTURE.md
  + LIBRARIES.md fix the v1.0 frozen surface. Anything beyond that
  is v1.1.0+. Phase 11 hardens what exists; it doesn't expand it.

## Consequences

- Marathon-mode dev is over. Branches + PRs + reviewer-driven
  planning from here.
- This ADR is the durable plan. Per-track wave ADRs (when tracks
  produce one) cite this as their parent.
- v1.0.0 is now defined as "all four axes met", not "Phase 10
  closed". The version number is downstream of the gate, not
  upstream of a calendar.
- The release archive currently published as v0.25.0 is the install
  tree downstream consumers (Track C's prerequisite) link against
  during Phase 11.
