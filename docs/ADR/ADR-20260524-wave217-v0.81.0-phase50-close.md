## Karar

### 50.A — `cd/editor/SelectionSet.hpp`
Editor seçim state'i:
- Sorted-vector backing (küçük N için cache locality kazanır).
- `add` / `remove` / `contains` (lower_bound O(log n)).
- `primary()` — most-recently-added; inspector tek-entity gösterimi
  için (multi-select olsa bile).
- `clear()`, `empty()`, `size()`, `entries()`.

Storage Entity::id üzerinden (generation tutmaya gerek yok —
caller entity destroy'ında remove yapmalı).

### 50.B — `cd/asset/LoadProfile.hpp`
Per-asset load-time telemetri:
- `record(id, micros)` — append sample + running stats.
- `total_us(id)` / `count(id)` / `mean_us(id)` — O(1) lookup.
- `slowest(n)` — top-N slowest sample (full scan + sort).
- `clear()`, `sample_count()`.

ProfilerView (Phase 16'da gelen ImGui widget) bunu beslesin →
"hangi asset baking pipeline'da en yavaş" göstergesi.

### Test hygiene (4. tekrar)
Phase 50 anon-namespace include trap'i bir kez daha karşımıza çıkardı:
test_editor.cpp'de CommandPalette include'u Phase 32'de anon namespace
içine konmuştu. Bu wave'de yeni eklenen SelectionSet `cd::ecs` ve
`cd::editor::SelectionSet`'i kullanmak istediğinde nested
`::{anon}::cd::editor` namespace'i (CommandPalette'in nested açtığı)
parent `::cd::editor`'i şadowluyordu.

Final cleanup: tüm editor include'ları (`CommandPalette`, `EditHistory`,
`TransformCommands`, `SelectionSet`) file-top'a taşındı. Bu artık
marathon kuralı: **header include'ları HER ZAMAN file-top, anon
namespace içinde include yasak**.

## Reddedilen alternatifler

- **SelectionSet için `std::unordered_set<Entity>`**: Entity'nin
  `std::hash` özelleştirmesi yok; sorted-vector hem hash maliyetinden
  kaçar hem small-N için daha hızlı.
- **LoadProfile'ı atomic-counter ile thread-safe yapmak**: telemetri
  zaten single-producer (asset thread); caller external lock alır
  veya per-thread profile birleştirir.
