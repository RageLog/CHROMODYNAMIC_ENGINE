# ADR Wave-301 — Phase 149 Renderer::submit_draws (v0.99.66)

- **Date:** 2026-05-25
- **Status:** Accepted
- **Predecessor:** [ADR-20260525-wave300-v0.99.65-phase139-hello-engine-fixes](./ADR-20260525-wave300-v0.99.65-phase139-hello-engine-fixes.md)
- **Successor:** ADR Wave-302 (Phase 153 Frustum::contains_sphere)
- **Tag:** v0.99.66

## Context

Phase 108 (Wave 280) shipped `cd::render::DrawBucket` — a SortKey-keyed
draw-call container with a `sort()` + `emit_all(cmd)` API following
Christer Ericson's "Order your graphics draw calls" pattern. The
bucket has been tested in isolation since Phase 108 but had **no
consumer** at the Renderer level — callers had to grab the
`FrameContext::command_buffer` manually and call `bucket.emit_all`
themselves.

The MARATHON_SUMMARY.md "Outstanding integration" list explicitly
called this out:

> Renderer::submit_draws using SortKey for ordering

This phase closes that gap.

## Decision

Add a one-liner method to `cd::render::Renderer`:

```cpp
[[nodiscard]] cd::core::Result<void> submit_draws(DrawBucket& bucket);
```

Semantics:

- Returns `render_errors::kFrameInFlight` if called outside an active
  `begin_frame()` / `end_frame()` pair.
- Otherwise replays the bucket against the active frame's command
  buffer via `bucket.emit_all(*frames_[slot].cmd)`.
- Does **not** clear the bucket — caller decides whether to clear or
  reuse for the next frame.

Forward-declares `DrawBucket` in `Renderer.hpp` to keep the header
inclusion graph thin; full include lives in `Renderer.cpp`.

Two new tests pinned in `cd_test_render`:

- `Renderer.SubmitDrawsRejectsOutsideFrame` — invariant guard
- `Renderer.SubmitDrawsReplaysBucketInSortedOrder` — verifies
  ascending-key emit order across a full begin_frame/end_frame
  cycle on a real GPU

Both pass on the Vulkan ICD; total renderer suite remains green.

## Side fix

Surfaced a pre-existing latent bug in `SortKey.hpp`: the `<=>` default
needs `<compare>`, which was previously masked by transitive includes.
Adding `<compare>` directly to the header makes it self-contained.

## Rejected alternatives

- **`submit_draws(DrawBucket&, ICommandBuffer&)`** — would let callers
  target a non-primary command buffer (secondary cmd / compute queue).
  Deferred: no current caller needs it and the simpler 1-arg form
  covers the showcase use case.
- **`submit_draws(DrawBucket&&)`** (sink) — would have hidden the
  decision about whether the bucket is cleared. Reference-in keeps
  ownership clear and lets callers decide.
- **Auto-clear after emit** — would force a reallocation on the next
  frame unless callers also call `reserve()`. Idiomatic ECS-style
  draw streams reuse the bucket frame-to-frame, so we leave clear
  to the caller.

## Consequences

- Apps that hold a `Renderer` no longer need to reach into
  `FrameContext::command_buffer` to drive a sorted draw pass.
- `DrawBucket` is now a first-class engine primitive on equal footing
  with the rest of `cd::render`.
- The marathon's WAVE A pending list is one shorter.

## Open follow-ups

- Wire DrawBucket into the actual `hello_engine` mega-showcase as a
  scene draw pass once Material v2 lands (Phase 155 IBL touches the
  same area).
- A SECONDARY-cmd-buffer overload may be useful for compute / RT
  bucketing — left for a future phase.
