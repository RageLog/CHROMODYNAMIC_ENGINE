# ADR — v0.24.0 / Wave 122 — Install pipeline + find_package consumer

- Date: 2026-05-23
- Status: Accepted
- Wave: 122
- Tag: v0.24.0

## Context

v0.23.0 closed Sprint 3 (CI / Platform leg) with a tag-driven
`release.yml` workflow that produces per-platform archives but no
install tree to put in them. Sprint 4's stop condition per Wave 106's
ADR has four items:

1. CHANGELOG.md cleanup
2. v1.0.0-rc.1 tag
3. CMake package config (install + `cd_targets.cmake` export)
4. `find_package(CHROMODYNAMIC)` downstream smoke

Item 3 is structurally load-bearing: items 1, 2, and 4 all assume an
install tree exists. Sprint 4 begins by paying that off.

## Decision

Tag **v0.24.0** with the install pipeline landed:

- **Wave 121** CMake install + find_package(CHROMODYNAMIC) export.
  `cd_add_library` gains `EXCLUDE_FROM_INSTALL` + sets `EXPORT_NAME` to
  the short library name so the exported imported target is `cd::core`,
  not `cd::cd_core`. New `cmake/CDInstall.cmake` provides
  `cd_finalize_install()` (called once from the top-level CMakeLists)
  to configure `CHROMODYNAMICConfig.cmake.in`, write the SemVer-aware
  `ConfigVersion.cmake`, install the `CHROMODYNAMICTargets` export set
  with namespace `cd::`, and ship docs into `share/doc/CHROMODYNAMIC`.
  `CD_ENABLE_INSTALL` defaults ON for top-level builds, OFF for
  subdirectory consumers — so vendored builds don't try to install.

- **tests/find_package_smoke/** end-to-end smoke: configure against
  the staged install prefix, link `cd::core` + `cd::diag` + `cd::log`,
  exercise one symbol from each (format(ErrorCode), CD_VERIFY,
  RingBufferSink::snapshot()), exit 0. Verified locally:

      cmake --install build/ninja-base --prefix .../install-staging
      cmake -S tests/find_package_smoke -B .../find-package-smoke \
            -DCMAKE_PREFIX_PATH=.../install-staging
      → "smoke OK — formatted=core::NotFound: smoke, ring size=1"

### Per-target install opt-outs

Seven libraries are deliberately excluded from the export set because
their public headers leak FetchContent paths or they transitively
depend on excluded libs:

| Library              | Reason                                              |
|----------------------|-----------------------------------------------------|
| `cd::imgui_backend`  | vendored dear-imgui                                 |
| `cd::script`         | vendored Lua                                        |
| `cd::rhi_vulkan`     | vendored volk + Vulkan-Headers + VMA                |
| `cd::shader`         | vendored glslang + SPIRV                            |
| `cd::rhi_native`     | depends on `cd::rhi_vulkan`                         |
| `cd::cluster_gpu`    | depends on `cd::shader`                             |
| `cd::material`       | depends on `cd::shader`                             |

Downstream consumers who need any of these build from source against
this repo. Foundation + asset tier + non-shader render bits (cluster
CPU, framegraph, camera, async_submit, ibl) + ECS/scene/physics/etc.
are all in the export set.

## Rejected alternatives

- *Promote the vendored deps into the export set.* Rejected: that
  forces downstream consumers to install volk / Vulkan-Headers /
  glslang / Lua in compatible versions at the same install prefix,
  which defeats the "drop-in framework" claim. Building-from-source
  for the Vulkan/shader/script tier is the simpler contract.
- *Skip install entirely and only support build-from-source.*
  Rejected: a SemVer-tagged engine that can't be `find_package`'d
  isn't a v1.0 framework, it's a fork tree. The install gate is the
  release contract.
- *Use CMake's BUILD_INTERFACE / INSTALL_INTERFACE wrap on every
  vendored include path.* Rejected as scope-creep for Sprint 4 first
  wave: every vendored dependency would need an export wrapper and
  the project layout would change for all seven listed libraries.
  Filed as Phase 11 polish if the demand surfaces.

## Consequences

- The install tree shipped is what `release.yml` packages — the
  Wave 119 archives will now carry a usable `include/`, `lib/`,
  `lib/cmake/CHROMODYNAMIC/` payload.
- Sprint 4 next: CHANGELOG cleanup pass + v1.0.0-rc.1 tag. The rc.1
  cuts directly off this branch once the cleanup wave is in.
- v1.0.0 GA tag follows rc.1 soak.
- All 58 ctest targets remain green on ninja-debug. find_package
  smoke exits 0 against the staged install prefix.
