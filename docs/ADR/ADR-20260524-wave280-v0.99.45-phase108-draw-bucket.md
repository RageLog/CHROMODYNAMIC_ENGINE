# ADR-20260524 / Wave 280 / v0.99.45 / Phase 108 — DrawBucket SortKey integration

## Status
Accepted — 2026-05-24

## Context

Phase 36 shipped a 64-bit packed `SortKey` (layer / pass / blend /
material id / depth bits / user) for ordering draw calls per
Christer Ericson's 2008 article, but no consumer actually paired
keys with submissions. Samples still issued draws in iteration
order, which works at three entities and breaks at any meaningful
scene size (state-thrash, alpha-blend overdraw out of order).

## Decision

New header-only `cd/render/DrawBucket.hpp`:

- `DrawItem { SortKey, std::function<void(ICommandBuffer&)> emit }`.
- `DrawBucket` accumulates items in any order, `sort()` stable-
  sorts by key (idempotent, marks `sorted_` flag), `emit_all(cmd)`
  replays in order.
- Deferred callbacks rather than packed PSO/VB/IB structs because
  call sites already have per-material / per-mesh closures that
  know how to push the correct vertex buffer and push constants.
- `clear()` keeps capacity for reuse; `reserve()` lets callers
  pre-size.

## Rejected alternatives

- **Method on `Renderer`** (`Renderer::submit_draws(span<DrawItem>)`).
  Couples the bucket to renderer lifecycle; standalone class lets
  any tool/sample stage draws against any ICommandBuffer.
- **Packed `DrawCmd` struct (PSO+VB+IB+push-bytes-blob).** Smaller
  per-item footprint but duplicates the per-material binding
  knowledge that already lives in caller code. Acceptable trade
  for a small engine; AAA-scale would revisit.
- **In-place radix sort on bare uint64.** Faster but caller still
  needs the emit callback; stable std::sort is fine at the
  expected item count.

## Consequences

- `cd::render` gains its first sort-integrated draw primitive.
- Samples / framegraph passes can stuff draws into a bucket from
  any order (e.g., per-archetype ECS iteration) and let the
  bucket put them in front-to-back / back-to-front order without
  the call site caring.
- 3 new gtests verify ascending order, clear-resets-sorted, and
  stable-sort behaviour on equal keys.
