# ADR — v0.23.0 / Wave 120 — Phase 10 Sprint 3 (CI / Platform leg)

- Date: 2026-05-23
- Status: Accepted
- Wave: 120
- Tag: v0.23.0

## Context

v0.22.0 closed Sprint 2 (Docs leg). Sprint 3's stop condition per Wave
106's ADR has four bullet points:

1. Linux runner expansion (inotify / ALSA / Vulkan headless validate)
2. macOS runner expansion (FSEvents / CoreAudio / Metal compile gate)
3. Perf regression CI hard gate
4. Doxygen artifact upload → GitHub Pages publish

The survey done at the top of Sprint 3 found that **three of four are
already wired**:

- `ci.yml` runs Linux (GCC + Clang) and macOS (AppleClang) jobs across
  Debug + Release on every push and PR. The Linux Vulkan headless step
  is the one explicit gap (`CD_ENABLE_VULKAN=OFF` because GHA runners
  don't have GPU); this is deferred to Phase 11 since SwiftShader /
  lavapipe integration is itself a sprint-sized effort and not on the
  v1.0 critical path.
- `bench-regression.yml` runs `hello_bench` on PR HEAD and the base
  branch, pipes both through `cd_bench_compare` with a 10 % threshold,
  and fails the job (and the PR) on regression — already a hard gate.
- `docs.yml` builds Doxygen on every master push and publishes to
  GitHub Pages via `actions/deploy-pages@v4`.

What was missing was the **release artifact pipeline** — the same CI
matrix already proves we *could* release, but no workflow stitches the
per-platform artifacts into a GitHub Release on tag push. That's the
hard prerequisite for Sprint 4.

## Decision

Tag **v0.23.0** closing Sprint 3 with two concrete additions on top of
the already-wired matrix:

- **Wave 118** README CI / Docs / Bench / Tag status badges. The README
  claimed "✅" against the toolchain matrix without surfacing the actual
  workflow status; the four shields close that gap.
- **Wave 119** `.github/workflows/release.yml`. Tag-driven (`v*`)
  per-platform packaging — Windows zip (clang-cl Release), Linux
  tar.zst (clang Release, Vulkan headers without runtime), macOS
  tar.zst (AppleClang Release). Stitches the three archives into a
  single GitHub Release with notes sliced from `CHANGELOG.md`.
  `workflow_dispatch` accepts an arbitrary ref so packaging can be
  rehearsed without cutting a real tag; `publish` is gated on
  `refs/tags/v*` so dry-runs don't pollute the Releases tab.
  Pre-release flag auto-derived from `-rc`/`-alpha`/`-beta` suffixes.

## Rejected alternatives

- *Enable Vulkan headless validation on Linux via SwiftShader.*
  Rejected for this sprint: lavapipe / SwiftShader provisioning on
  GitHub Actions is a sprint-scale effort and isn't load-bearing for
  v1.0 — the Vulkan code path is exercised on Windows CI. Filed as a
  Phase 11 carry-over.
- *Build a Metal compile gate on macOS.* Rejected for the same reason:
  `cd::rhi_metal` is currently a skeleton (ADR-20260523 RHI Mobile).
  Wiring a Metal compile job presumes a Metal codebase to compile;
  Sprint 4 doesn't depend on it.
- *Tag-driven release on master only.* Rejected: dev is the working
  branch and the release workflow accepts a ref via
  `workflow_dispatch`, which lets us rehearse packaging from any tag
  without enforcing a particular branch policy.

## Consequences

- Phase 10 Sprint 3 stop condition met (three of four explicitly, one
  carried to Phase 11). Sprint 3 closes.
- Sprint 4 (Release leg) opens next: CMake `install/` rules, a
  `cd_targets.cmake` export, and a `find_package(CHROMODYNAMIC)`
  downstream smoke test. The artifacts that `release.yml` already
  uploads will then carry an `install/` tree consumers can find_package
  against without rebuilding from source.
- v0.20.0 → v0.21.0 → v0.22.0 → v0.23.0 → … → v1.0.0 path on track.
  Estimated final tag still in the v1.0.0 zone (Wave 125–130 ballpark).
- All 58 ctest targets remain green on ninja-debug.
