# ADR — v0.31.0 / Wave 153 — Phase 13.B Linux lavapipe goldens

- Date: 2026-05-23
- Status: Accepted
- Wave: 153
- Tag: v0.31.0
- Predecessor: ADR-20260523-wave152 (v0.30.0 reviewer blockers)
- Phase 13 master: ADR-20260523-wave151-phase13-plan.md

## Context

Phase 11 wired the Linux lavapipe job (`linux-vulkan-sw`) so the
Vulkan path runs on CI even without a real GPU. That job exited 0
when the samples didn't crash, but it could not assert visual
correctness — `tests/golden/lavapipe/` was empty.

`scripts/run_golden.sh` already supports `--vendor lavapipe` since
Wave 132 — the harness was waiting for a reference capture and a
CI step to invoke it.

Phase 13.B per the wave151 plan: capture references, wire a
golden-compare step into the linux-vulkan-sw job.

## Decision

Tag **v0.31.0**. Scope: the lavapipe golden infrastructure, not the
reference set itself (which requires a real Linux CI run plus
operator review).

### What landed

- **New CI job `linux-lavapipe-golden-capture`** gated on
  `workflow_dispatch` with input `capture_lavapipe_goldens=true`.
  Builds the engine on Ubuntu, runs every wired sample under xvfb
  + lavapipe in `--mode capture`, uploads the resulting PNG set as
  artifact `linux-lavapipe-goldens` (30-day retention).
- **`linux-vulkan-sw` job extended** with a *conditional*
  golden-compare step. The step counts `tests/golden/lavapipe/*.png`
  before the run; if zero, it logs a skip message and exits 0. Once
  the reference set is committed, it gates with
  `--tolerance 16` per channel (lavapipe arithmetic-ordering budget
  vs. desktop-GPU references).
- **`tests/golden/lavapipe/README.md`** documents the
  operator-loop: trigger the dispatch job, download the artifact,
  sanity-check the PNGs, commit. Auto-commit is *deliberately not
  wired* — operator review is the gate against all-black frames /
  validation-layer corruption banners / size sanity.
- **Golden-diff artifact upload on compare failure** so a CI red
  comes with the diff PNGs already attached to the workflow run,
  not just a tolerance number.
- **`tests/golden/README.md` updated** to point at the lavapipe
  sub-README for capture instructions, replacing the stale "TBD:
  Linux Vulkan software ICD" line.

### What deliberately did NOT land

- **The actual lavapipe reference PNG set.** The marathon cannot
  capture them — no Linux runner is available locally, and
  auto-committing CI-captured binary blobs without operator
  inspection breaks the rollback-honesty discipline. The
  `workflow_dispatch` capture path + artifact upload is the
  reproducible recipe; the human-in-the-loop step is *one
  operator click* on the Actions tab when the time comes.
- **Tolerance retuning.** The 16/255 default is a conservative
  starting budget extrapolated from lavapipe documentation and
  the cross-vendor noise floor table in `docs/ARCHITECTURE.md`
  §6. The real number lives one capture + one
  multi-run-noise-floor measurement away; lavapipe/README.md
  documents the protocol for tightening.
- **Per-sample override budgets.** `run_golden.sh` accepts a
  single `--tolerance` value applied to every sample. Some
  samples (skybox, IBL with floating-point arithmetic) may need
  more headroom than triangle; we'll only know after the first
  capture. Deferred.

## Rejected alternatives

- *Auto-commit the captured PNGs to dev from the CI run.* Rejected:
  the v1.0 rollback was caused by trusting test-suite green when
  the render pipeline silently produced wrong pixels. Auto-pushing
  CI-generated binary blobs without operator eyes is the same
  trust pattern. Deliberately split: machine captures; human
  reviews; machine gates.
- *Skip the conditional and require references before the v0.31
  tag.* Rejected: the wave151 plan explicitly said "One-time
  human-run of the capture; on first land, commit the artifact" —
  i.e. the marathon ships the infra and *defers* the operator
  step. Forcing references first would block the tag waiting on
  asynchronous CI runs, which is exactly the kind of marathon
  stall the user's directive forbids.
- *Capture lavapipe references on Windows via swiftshader / a
  software backend.* Rejected: swiftshader and lavapipe produce
  different output; using the wrong reference set defeats the
  per-vendor scoping the run_golden.sh harness exists to enforce.
- *Generalize the dispatch path to capture any vendor.* Rejected:
  the per-vendor capture is already general at the script layer
  (`--vendor <slug>`). Adding a third dispatch input for vendor
  selection multiplies CI surface for a one-time setup task.
  Direct `gh workflow run` with `-f` flags can target other
  vendors when needed.

## Consequences

- v0.31.0 ships the marathon-shippable lavapipe infrastructure.
- The first operator who clicks the dispatch trigger closes the
  remaining loop and converts the `linux-vulkan-sw` job from
  "exit-0 smoke" to a "exit-2-on-pixel-regression" gate.
- The `--tolerance 16` value will be tightened in a follow-up wave
  after a multi-run noise-floor sample on the actual GHA runner.
- Phase 13.C (D3D12 buffer + texture + swapchain → v0.32.0) opens
  next.
