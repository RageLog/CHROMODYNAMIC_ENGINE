# ADR Wave-300 — Phase 139 hello_engine post-ship fixes (v0.99.65)

- **Date:** 2026-05-25
- **Status:** Accepted
- **Predecessor:** [ADR-20260524-wave299-v0.99.64-phase138-hello-engine](./ADR-20260524-wave299-v0.99.64-phase138-hello-engine.md)
- **Successor:** ADR Wave-301 (Phase 149 DrawBucket wire-up)
- **Tag:** v0.99.65

## Context

Phase 138 shipped `samples/hello_engine` as the mega-showcase. User
ran it and flagged three follow-ups:

1. **FPS not displayed** — no readout in the Counters panel.
2. **Ctrl+Shift+P chord did not fire** — palette only opened via F1.
3. **WASAPI sound never played** — backend was constructed but no
   clip was loaded / no voice played.
4. **Mute toggle did not actually mute** — the bool flipped but voice
   volume stayed at 0.65.

## Decision

Patch `samples/hello_engine/main.cpp` in-place with four small, surgical
edits — no engine-level API change required:

- **FPS readout:** `1.0/dt` printed in Counters panel beside `dt` and
  frame number. Guards against `dt<=0` on first frame.
- **Ctrl+Shift+P chord:** track `mod_ctrl` and `mod_shift` at the
  platform event layer (the engine's `ImGui` backend was not always
  forwarding modifier state via `IsKeyChordPressed`). Logs a
  `[debug] P keydown ctrl=… shift=…` line so future regressions are
  visible. F1 retained as the reliable fallback. A
  **"Open Command Palette"** button was also added to the Scene panel
  so the palette is accessible without any hotkey.
- **WASAPI live playback:** construct `make_wasapi_audio_backend()`,
  pre-render 2 seconds of the DSP chain (Mixer + Compressor +
  Reverb + LowPass + Limiter) into an `AudioBuffer`, upload it as a
  `ClipHandle`, and play with `loop=true` at 0.65 volume.
- **Mute fix:** "Audio: Toggle Mute" command now drives
  `audio_backend->set_volume(live_voice, audio_muted ? 0.0F : 0.65F)`
  in addition to toggling the bool. Volume change is audible
  immediately on the next audio frame.

The pre-rendered loop approach is intentional: WASAPI backend exposes
a clip-based API (Phase 157 will add a push-stream API). The 2 s loop
is long enough that the seam is barely audible at 44.1 kHz given the
reverb tail.

## Rejected alternatives

- **Block on Phase 157 push-stream API** — would have left hello_engine
  silent for the rest of the marathon. Pre-rendered loop is good
  enough for the showcase.
- **Strip Ctrl+Shift+P entirely, keep only F1** — F1 alone is reliable
  but the chord is a real product feature (Phase 138 added it via
  `ImGui::IsKeyChordPressed`). Debug log + button preserves both
  paths.
- **Computed FPS as a running EWMA** — a single-frame `1/dt` is fine
  for a showcase; the user only needs to see it doesn't drop.

## Consequences

- hello_engine now demos all five subsystems audibly + visually:
  render (panels + grid), input (chord + button), audio (looping DSP
  output), net sim (latency stats), editor (palette + inspector).
- The mute toggle is now a real e2e test of `cd::audio` voice-volume
  control.
- Phase 157 (continuous push-stream API) is now demoted from
  blocker to nice-to-have: marathon can proceed.

## Open follow-ups

- Phase 157 (push-stream WASAPI) still worth doing for production
  use; the loop seam is audible at low reverb settings.
- Modifier state in the engine ImGui backend should be wired
  bidirectionally so `ImGui::IsKeyChordPressed` works without the
  platform-side shadow tracking we added here.
