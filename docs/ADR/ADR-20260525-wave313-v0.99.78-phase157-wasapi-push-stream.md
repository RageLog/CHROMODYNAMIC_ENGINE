# ADR Wave-313 — Phase 157 WASAPI push-stream API (v0.99.78)

- **Date:** 2026-05-25
- **Status:** Accepted
- **Predecessor:** [ADR-20260525-wave312-v0.99.77-phase158-160-wave-h-deferral](./ADR-20260525-wave312-v0.99.77-phase158-160-wave-h-deferral.md)
- **Successor:** ADR Wave-314 (Phase 155 IBL or Phase 145-148 OpenGL chain)
- **Tag:** v0.99.78
- **Reclaim:** WAVE F item from v0.99.75 deferral.

## Context

`cd::audio::IAudioBackend` previously exposed only a Clip+Voice
contract: upload a precomputed PCM buffer, then `play` it. Useful
for sound effects + ambient loops, but it forces callers to
pre-render anything they want to hear — no microphone passthrough,
no streaming network voice, no procedural synthesis.

Phase 157 was deferred from v1.0 (ADR Wave-310) on the reasoning
that the clip-based loop in `hello_engine` was good enough for the
v1.0 demo. With v1.0 in the bag (per Wave-311 readiness report),
this is the first v1.1 deferred item reclaimed by the marathon.

## Decision

Extend `IAudioBackend` with a four-method push-stream API:

```cpp
struct StreamTag {};
using StreamHandle = cd::core::Handle<StreamTag>;

[[nodiscard]] virtual cd::core::Result<StreamHandle>
create_stream(uint32_t channels, uint32_t sample_rate, float volume = 1.0F);

[[nodiscard]] virtual cd::core::Result<void>
push_stream_samples(StreamHandle, span<const float>);

virtual void destroy_stream(StreamHandle);

[[nodiscard]] virtual size_t stream_pending_frames(StreamHandle) const noexcept;
[[nodiscard]] virtual size_t stream_count() const noexcept;
```

Backends that don't yet support streaming inherit the default
implementations which return `kBackendError`. Only `WasapiBackend`
overrides them in this phase.

### WasapiBackend implementation

- Per-stream record (`StreamRec`) holds channel count, sample rate,
  volume, an interleaved-float `std::vector` queue, and a read offset.
- `push_stream_samples` appends to the queue under the same
  `state_mu_` mutex that guards clips + voices.
- `mix_frames_` was already a per-device-frame loop; the addition
  is one accumulator pass that pulls one frame per stream + advances
  the read offset, falling back to silence when the queue underruns.
  Channel mismatches are handled via the same broadcast pattern
  voices use.
- Queue compaction kicks in once the read offset exceeds 8192 to
  keep memory bounded under steady-state streaming.
- `destroy_stream` is the explicit cleanup; a missing destroy leaks
  the queue until backend tear-down.

### Sample-rate behavior (documented limitation)

The current mix loop walks the queue one source-frame per device
frame — same as the existing clip path. This means a stream
created with `sample_rate=22050` plays back at device-rate pitch,
not at the source's nominal pitch. A follow-up phase (`AudioStreamer`
source type with a per-stream resampler) will fix this; current
callers can pre-resample to the device rate (typically 48 kHz).

+ `GTEST_SKIP` when no WASAPI device is available):

- `WasapiPushStream.CreateAcceptsValidParamsAndPushAppendsToQueue`
- `WasapiPushStream.RejectsInvalidCreateArgs`
- `WasapiPushStream.PushToUnknownStreamRejected`

All pass; 58/58 total test surface still green.

## Rejected alternatives

- **Per-stream worker thread** that pulls from a lock-free queue —
  would lower mix-loop contention but adds threading complexity
  for a use case where the queue is rarely the bottleneck.
- **Free function `audio_push_stream(...)`** outside the IAudioBackend
  contract — would bypass polymorphism + lose the null/file-sink
  fallback path.
- **Block on backend not yet supporting streaming** — would force
  the file-sink + null backends to implement a meaningless stub.
  Default `kBackendError` returns let callers gate at runtime.
- **Async push via async_push_stream coroutine** — out of scope;
  the current `vector::insert` under a mutex is fast enough for
  the 60 Hz frame budget at typical packet sizes (a few hundred
  bytes).

## Consequences

- The first v1.0-deferred item is reclaimed. v1.1 milestone now has
  one bullet shipped: WASAPI push-stream.
- `IAudioBackend` virtuals: 11 total (+4 new push-stream methods).
  Default returns mean ABI-compatible for existing backends.
- Next v1.1 candidates (per ordering rule): OpenGL swapchain/shader/
  pipeline chain (Phase 145-148), then IBL (155), then D3D12 DXR
  (142), then skeletal anim (156).

## Open follow-ups

- `AudioStreamer` source type: an adapter that consumes a
  network/disk/synthesis source and pushes into a stream handle.
- Per-stream resampler for source rate ≠ device rate.
- Lock-free queue variant for the mix-loop side once contention
  shows up in profiling.
