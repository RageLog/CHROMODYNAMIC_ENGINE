# ADR-20260524 / Wave 270 / v0.99.35 / Phase 103 — Editor Live Drag + Primitive Meshes

## Status
Accepted — 2026-05-24

## Context

Phase 102 widened the Inspector and restructured its labels, but the
user kept finding workflow friction in two more places:

1. **"cumede cube spherede kure ve cone da koni gormek istiyorum"** —
   all three demo entities (named "Cube", "Sphere", "Cone") were
   actually rendered with the same red/green/blue-tinted **cube mesh**.
   The names suggested different shapes; the viewport delivered three
   recoloured cubes.

2. **"editorde apply istemiyorum gercdek zamanli uygilansin. birde
   0 1 butonlari ise yaramiyor"** — every transform field required
   typing a delta + clicking *Apply*, with reset SmallButtons that
   only zeroed the slider state without touching the entity. The
   expected behaviour is what every modern editor does: drag a value
   and watch the entity move in real time; undo/redo still snapshots
   the final delta.

A third bug surfaced from the user's screenshot:

3. **`docs.yml` YAML linter** reported "Value 'github-pages' is not
   valid" on the GitHub Pages deployment `environment.name`. This is
   a false-positive — the Microsoft GitHub Actions VSCode extension
   validates the field against the *live* repo environments list, and
   `github-pages` only appears in that list after the repo's
   `Settings → Pages → Source` is switched to "GitHub Actions" (which
   auto-creates the reserved environment).

## Decision

### Procedural sphere + cone meshes in `hello_editor`

- Introduce a single `MeshCpu` struct holding `CubeVertex` arrays so
  the existing material/pipeline keeps working unchanged.
- `make_sphere(stacks, slices)` builds a unit-radius UV-sphere of
  radius 0.5 (matching cube ø). Per-vertex colour is the normal
  mapped to a pastel RGB (`pos * 0.5 + 0.5`) so the sphere reads as
  3D before the per-entity tint multiplies in.
- `make_cone(slices)` builds an apex at +Y 0.5, a base disk at -Y 0.5,
  separate ring vertices for the side fan and the base disk so each
  surface can hold its own colour without sharing a vertex.
- `SceneEntity::MeshKind { kCube, kSphere, kCone }` enum, set from
  the entity name at spawn-time via `mesh_kind_from_name()`.
- Draw loop groups by mesh kind and binds each VB/IB pair once per
  group (one bind-vertex / bind-index call per kind, not per entity).
  Pedagogical for three entities; matters for hundreds.

### Live-drag Inspector

- Drop all three `Apply` buttons and the `0`/`1` reset
  `SmallButton`s. Position, Scale, and Rotation now use
  `ImGui::DragFloat3` widgets that write directly to the entity's
  `LocalTransform` every frame the user is dragging.
- Snapshot the pre-drag value on `ImGui::IsItemActivated()` (the
  first frame the widget receives input). Restore that pre-drag
  value on `ImGui::IsItemDeactivatedAfterEdit()` and push a single
  delta `TranslateCommand` / `ScaleCommand` / `RotateCommand` through
  the existing `EditHistory`. Undo/redo therefore still walk the
  same `Command` chain; the only change is that the user sees the
  drag happen live instead of accumulating in a Delta-then-Apply
  buffer.
- For rotation, the slider edits absolute Euler degrees re-derived
  from the quaternion every frame the widget is NOT active.
  An `editing` guard freezes that derivation while the user drags
  so atan2/asin round-trip jitter can't pull the slider out from
  under the user. ZYX intrinsic Euler convention matches the old
  Apply-Euler block exactly (`q = qz * qy * qx`).

### `docs.yml` YAML schema workaround

- Add `# yaml-language-server: $schema=...` directive at the top of
  `docs.yml`. Pinning the schema to schemastore's `github-workflow.json`
  reins in the Red Hat YAML extension's validation.
- Quote `name: "github-pages"` so any string-literal-only schema
  validators are happier.
- `.vscode/settings.json` gains a `yaml.schemas` map binding
  `.github/workflows/*.yml` to the same schemastore schema, plus
  `github-actions.workflows.pinned.refresh.enabled: false` to stop
  the Microsoft GitHub Actions extension from re-querying the repo's
  environments list on every refresh.
- The Microsoft GitHub Actions extension still consults its own
  live-environment list and may keep flagging the field locally
  until the user enables Pages in the repo's `Settings → Pages →
  Source: "GitHub Actions"` (which auto-provisions the
  `github-pages` deployment environment). Documented in the ADR;
  the CI workflow itself works unchanged.

## Rejected alternatives

- **Per-axis sliders + Apply button** — keeps history clean but the
  user explicitly asked for live drag. The `IsItemDeactivatedAfterEdit`
  pattern gives both: live preview + single undoable delta.
- **One Command per drag frame** — would spam EditHistory with
  hundreds of micro-commands per slider drag and bloat the undo
  stack. The pre-drag snapshot pattern collapses each user action
  into one command.
- **Free-form mesh registry** — could match arbitrary names to
  meshes via a `std::unordered_map<std::string, MeshKind>`. Overkill
  for three entity types; the `mesh_kind_from_name` switch is
  explicit and readable.
- **Disable YAML extension entirely** — would silence the warning at
  the cost of every other workflow's validation. The schema pin
  scopes the fix to just the GitHub Actions files.

## Consequences

- `hello_editor` now draws a recognisable cube, sphere, and cone
  side-by-side; the Inspector is a real direct-manipulation editor
  with undo/redo on drag release.
- Engine library code untouched — `cd::editor::TranslateCommand` /
  `ScaleCommand` / `RotateCommand` are reused as-is. Sample-side
  changes only.
- `.vscode/settings.json` workspace settings are checked into the
  repo; YAML linter behaviour now consistent across contributors.

## Validation

```
cmake --build --preset llvm-win-debug --target cd_sample_hello_editor
./build/llvm-win-base/bin/Debug/hello_editor.exe
```

User confirmed: live drag works, primitive meshes render correctly.
docs.yml `environment.name` workaround in place; final silencing
requires the user to enable GitHub Pages in repo settings.
