# ADR — Wave 125 — v1.0.0 + v1.0.0-rc.1 rollback

- Date: 2026-05-23
- Status: Accepted (supersedes ADR-20260523-wave123 & wave124)
- Wave: 125
- Tag delta: `v1.0.0` deleted, `v1.0.0-rc.1` deleted; HEAD = 0.25.0 (in-progress)

## Context

ADR-20260523-wave124 declared v1.0.0 GA based on:
- 58/58 ctest green on ninja-debug
- find_package(CHROMODYNAMIC 1.0.0) consumable from a staged install prefix
- Doxygen zero-warning build
- Windows × 4 toolchain CI matrix + Linux + macOS

The decision was **flawed**. After cutting both tags, a manual smoke
test of all 43 hello_* sample binaries (run one at a time, with the
user observing what actually appeared on screen, not just exit codes)
surfaced bugs that ctest could never catch:

| # | Sample | Observation |
|---|---|---|
| 1 | `hello_skybox` | 5578 frames rendered; output uniform black. Analytical atmosphere shader / UBO / VP-inverse suspect. |
| 2 | `hello_pbr` | 5×5 metallic/roughness sweep: rows visually identical (no roughness sweep), columns shift base color but no specular Fresnel / spec lobe. No metallic behaviour visible anywhere on the grid. |
| 3 | `hello_hot_reload` | Hot reload mechanism sound (23 reloads OK, 6 fails recovered without crash) BUT glslang error message encoding broken — raw bytes printed to console instead of UTF-8. |
| 4 | `hello_inspector` (minor) | Selecting `root_a` shows empty inspector panel; selecting `root_b` correctly shows transform fields. Special-case render skip or identity-transform UI bug. |
| 5 | `hello_anim` | "Keyframe-driven cube" — cube faces look translucent (back faces visible through front); colours washed out vs. `hello_cube`. Suspect negative-scale keyframe (winding flip) OR alpha-blend leak OR depth/cull pipeline state mismatch with `hello_cube`. |

Beyond the named bugs the smoke also surfaced softer observations:
- `hello_obj` / `hello_cooked`: ambient term ≈ 0, unlit faces approach black (cosmetic; sample's purpose is "OBJ load + draw", not lighting)
- `hello_imgui`: profile HUD header contains a glyph the default ImGui font can't render (renders as `?`)
- Several samples hard-code "v0.1.0" in their banners instead of reading PROJECT_VERSION (drifted from the actual project version)

## Decision

**Roll back both v1.0.x tags**, **rename Phase 10's "v1.0 path" framing
as premature**, and **redefine what v1.0 actually requires**.

Concrete:

1. Delete `v1.0.0` + `v1.0.0-rc.1` locally and on origin. (User-driven.)
2. CMakeLists.txt: `VERSION 1.0.0` → `VERSION 0.25.0`. The next tag
   will be `v0.25.0` after the bug sweep + hardening pass lands.
3. CHANGELOG.md: replace the v1.0.0 + rc.1 sections with a single
   "ROLLED BACK" note pointing to this ADR.
4. The v1.0 maturity gate (below) replaces the Wave 106 ADR's
   stop-conditions for the v1.0 promise.

### v1.0 maturity gate (real)

The previous gate was effectively "my CI matrix is green." That is
necessary but **not sufficient**. The real gate has four orthogonal
axes:

#### Axis A — Visual correctness (this is the gap that bit us)

- Every windowed sample produces the **visually correct output** at
  least once on a real GPU, verified by a human or a golden-image
  diff (FLIP / SSIM) tolerance check, not by `exit == 0`.
- Skybox, PBR sweep, animation, scene graph, inspector all
  pixel-checked against a reference.
- Pipeline state setup (depth, cull, blend, color write mask) audited
  for cross-sample consistency.

#### Axis B — Cross-hardware validation

- The Vulkan render path is validated on **at least two GPU vendors**
  (e.g. NVIDIA + Intel/AMD). The current marathon's GPU parity check
  was done on a single NVIDIA RTX 3080 Laptop. A single-vendor v1.0
  is a v1.0-on-that-vendor, not a framework v1.0.
- Linux CI runs with `CD_ENABLE_VULKAN=ON` via SwiftShader / lavapipe
  (headless software Vulkan) so the GPU code path is exercised on
  non-Windows runners.

#### Axis C — Real downstream consumer

- At least one **non-trivial** application built against
  `find_package(CHROMODYNAMIC)` from a different repository, not from
  the smoke harness in this tree. The find_package smoke at
  `tests/find_package_smoke/` links `cd::core + cd::diag + cd::log`
  only — three foundation libraries out of 55. That's "the install
  tree exists", not "the framework is usable."

#### Axis D — Independent review

- At least one human other than the marathon author reads the public
  API surface and the engineering invariants and signs off. The
  ARCHITECTURE.md commitments (frozen / experimental tiers, freeze
  scope, ABI stability promise) need a second pair of eyes that has
  not been steeped in the marathon's narrative.

A v1.0.0 tag without all four axes met is a publish gesture, not a
release.

## Rejected alternatives

- *Tag a v1.0.1 patch with the bug fixes and call it good.* Rejected:
  the bugs aren't isolated patch material; they reveal a categorical
  hole in our acceptance criteria (visual correctness was never part
  of the gate). Patch-tagging would paper over the deeper miss.
- *Keep the v1.0.0 tag and add a known-issues list.* Rejected: v1.0
  has community connotations (stable API, ready for downstream
  adoption). Shipping it with five known visual bugs trades short-term
  signal for long-term credibility loss. The honest move is to
  un-ship.
- *Delete the rollback ADRs and pretend the marathon ended at
  v0.24.0.* Rejected: the rollback IS the lesson. Keeping the
  superseded wave-123 + wave-124 ADRs alongside this one preserves
  the chain — what was claimed, what was found, what was corrected.

## Consequences

- The marathon's narrative "Phase 10 closes; v1.0 ships" is corrected
  to "Phase 10 surface frozen for hardening; v1.0 deferred to a real
  maturity gate."
- Phase 10 reopens with a new sprint — Sprint 5 (Hardening) — driven
  by the 5 bugs above plus pattern-search for their cousins.
- Wave 123 + Wave 124 ADRs are marked superseded (header status flip
  in a follow-up commit) but retained in the archive.
- The CI surface, install pipeline, ARCHITECTURE.md, ADR archive,
  badges, release.yml — none of these are rolled back. They remain
  load-bearing infrastructure. Only the **claim** of v1.0 stability
  is withdrawn; the **substrate** that supports v1.0 stays.
- Tag-driven release.yml will fire on the next `v*` tag push. The
  next legitimate tag is `v0.25.0` after Sprint 5 closes.

## What this ADR commits us to

1. Bug sweep — fix all 5 bugs above, with at least one screenshot of
   the corrected output committed as a golden reference.
2. Hardening pass — search for cousins of each bug (hardcoded version
   strings, ambient lighting consistency, per-sample pipeline state
   audit, font/glyph coverage).
3. Baseline tag `v0.25.0` — the honest "this is what works visually,
   verified by human + smoke harness" milestone.
4. Phase 11 opens — the v1.0 maturity gate work (cross-vendor GPU
   testing, downstream consumer, independent review).
