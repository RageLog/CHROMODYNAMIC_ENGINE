## Reddedilen alternatifler

- **PBR shader integration in Sprint 2:** PBR material uses
  graphics pipeline + fragment shader; cluster buffer binding +
  per-fragment light loop is meaningful work that deserves its
  own sprint. Phase 9 Sprint 3.
- **Skip the readback path (Wave 102) and dispatch-only:**
  Parity verification needs CPU readback. Without it the GPU
  pipeline could silently produce wrong results; runtime
  validation is the integrity gate.
- **Compile shader offline (glslangValidator → .spv):** Adds a
  build-time toolchain step. Runtime compile via the existing
  cd::shader infrastructure is simpler + the shader source ships
  inside the .cpp (single source of truth).

## Açık sorular

- **Phase 9 Sprint 3 timing — PBR shader cluster integration:**
  Existing PBR fragment shader needs an additional descriptor set
  binding for the cluster_offsets + light_indices buffers, plus
  the per-fragment light-list loop. Material system ADR update
  required.
- **Headless / CI GPU validation:** SwiftShader / LLVMpipe
  software Vulkan loaders could let GitHub Actions runners
  exercise hello_gpu_cluster without dedicated GPU hardware.
  Sprint 9+ candidate.
- **Indirect dispatch / persistent thread pattern:** The current
  shader has light_count in a uniform — at extreme light counts
  (~thousands) per-thread iteration becomes the bottleneck.
  Persistent-thread groups + atomic counters are an optimisation
  Phase 10 candidate.
