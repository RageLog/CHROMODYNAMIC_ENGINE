# ADR-20260524 wave197 — v0.59.0 Phase 28 close

## Bağlam

Marathon devam ediyor. Phase 27'de math (slerp) ve physics (Triangle barycentric)
katmanlarına header-only primitive eklendi. Phase 28, math katmanında **Vec2**
operasyonları için boşluğu kapatmayı hedefler: `Vec2f` tipi `Vector.hpp`'de zaten
vardı ama length / normalize / lerp / dot yardımcıları yoktu — UI math, screen-space
picking, ve texture-coord operasyonları için bunlara ihtiyacımız var.

## Karar (Phase 28.A — Vec2Ops)

`engine/foundation/math/include/cd/math/Vec2Ops.hpp` yeni header:
- `length_v2`, `length_sq_v2`
- `normalize_v2` (zero-length guard ile)
- `lerp_v2` (t ∈ [0,1] clamp ile)
- `dot_v2`

Vec3 muadilleri `Vector.hpp` içinde paralel olarak yaşamaya devam ediyor; Vec2
yardımcıları ayrı bir header'a çıkartıldı çünkü çoğu çağıran site sadece
Vec2 ile çalışıyor (UI / screen-space) ve tam Vector.hpp'yi include etmek
istemiyor (ama şu an Vector.hpp zaten Vec2f tanımını içerdiği için
`#include <cd/math/Vector.hpp>` bağlılığı korundu — gelecekte Vec2 tanımı
ayrı bir `Vec2.hpp`'ye çıkartılabilir).

## Test

`engine/foundation/math/tests/test_math.cpp`:
- `Vec2Ops.Length3_4_Is5` — Pisagor: √(3²+4²) = 5
- `Vec2Ops.NormalizeProducesUnitLength` — length sonrası ≈ 1
- `Vec2Ops.LerpHalfwayIsMidpoint` — t=0.5'te (a+b)/2
- `Vec2Ops.DotProduct` — (1,2)·(3,4) = 11

`ctest --preset ninja-debug --output-on-failure` → **58/58 PASS** (öncekiyle aynı,
yeni 4 case `cd_test_math` içinde sayılıyor).

## Reddedilen alternatifler

- **Vec2/Vec3/Vec4 helper'larını tek dosyada birleştirmek**: include hijgienic
  açıdan daha temiz ama UI-only çağıran site Vec3/Vec4 swizzle'larını da
  pull etmek zorunda kalırdı — gereksiz template instantiation maliyeti.
- **Free function yerine member fonksiyon**: `Vec2f::length()` daha güzel ama
  `Vec` template aggregate olarak tasarlandı (designated init ile)
  — member fn eklemek aggregate'ı bozar.
