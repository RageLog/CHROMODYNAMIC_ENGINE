# ADR — v1.0.0 / Wave 124 — General Availability

- Date: 2026-05-23
- Status: Accepted
- Wave: 124
- Tag: v1.0.0

## Context

v1.0.0-rc.1 cut at Wave 123. The rc.1 ADR set the soak window
expectation explicitly:

> The soak window between rc.1 and GA is short by design — the
> marathon has been compiling, testing, and find_package-checking
> this surface for the past five sprints; rc.1 is a publish gate,
> not a destabilising re-test.

No surface change between rc.1 and GA. The marathon footprint is
unchanged (55 libraries, 40 samples, 58 ctest binaries, 100 % green
on ninja-debug, find_package(CHROMODYNAMIC 1.0.0) resolving cleanly
against the staged install prefix).

## Decision

Tag **v1.0.0**. Phase 10 closes; the v1.0 stability promise is in
effect. CHANGELOG section heading flips from
"v1.0.0-rc.1 — Release candidate" to "v1.0.0 — General Availability";
the body content is identical because the surface is identical.

### What the v1.0 promise binds

For every library on the frozen list in the rc.1 ADR
(ADR-20260523-wave123), the v1.x line guarantees:

- No removal of public symbols.
- No incompatible signature changes (return type, parameter list,
  noexcept-ness).
- No silent semantic change to documented behaviour.

Additions are allowed in minor (1.x.0) releases. Bug-fix patches
(1.0.x) carry no API delta.

The experimental tier (cd::rhi_metal skeleton, cd::rhi_d3d12 minimal,
cd::editor*, cd::script binding helpers) is explicitly outside the
freeze; those graduate in v1.x point releases.

## Rejected alternatives

- *Long rc.1 soak (weeks).* Rejected: the rc.1 ADR already addressed
  this — five Phase 10 sprints of CI + install + find_package
  exercising plus 100 % ctest greenness is the actual soak. A calendar
  delay would not surface a defect that 58 gtest binaries + the
  downstream find_package smoke missed.
- *Re-cut as rc.2 with cosmetic CHANGELOG cleanup.* Rejected: the
  CHANGELOG's MD024 duplicate-heading warnings are intentional
  per-release convention and not a release blocker. Cosmetic markdown
  polish is post-v1.0 hygiene.
- *Bump to 1.0.1 instead and never tag 1.0.0.* Rejected: 1.0.1
  implies a patch over 1.0.0; without a published 1.0.0 the semver
  ladder doesn't anchor.

## Consequences

- The `v1.0.0` tag triggers `.github/workflows/release.yml`. The tag
  lacks any `-rc/-alpha/-beta` suffix, so the workflow's `prerelease`
  flag is false and the GitHub Release becomes the latest-release
  pointer.
- The Phase 10 line under `docs/ADR/ADR-20260523-wave106-phase10-...md`
  closes. Phase 11 opens next; the carry-over items are:
  - Linux Vulkan headless validate (SwiftShader / lavapipe).
  - macOS Metal compile gate.
  - Vendored-dep export wrappers (BUILD_INTERFACE / INSTALL_INTERFACE)
    so the seven currently-excluded libraries can re-enter the
    find_package surface in v1.x.
  - cd::rhi_metal / cd::rhi_d3d12 / cd::editor stabilisation toward
    v1.x freeze.
- Marathon ends here. Post-v1.0 work happens in the conventional
  feature-branch + PR cadence rather than the dev-marathon flow.
