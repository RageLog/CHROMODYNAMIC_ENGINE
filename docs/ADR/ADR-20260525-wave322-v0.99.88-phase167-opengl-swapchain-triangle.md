# ADR Wave-322 — Phase 167 OpenGL swapchain + visible triangle (v0.99.88)

- **Date:** 2026-05-25
- **Status:** Accepted
- **Predecessor:** [ADR-20260525-wave321-v0.99.87-phase165-light-system](./ADR-20260525-wave321-v0.99.87-phase165-light-system.md)
- **Successor:** ADR Wave-323
- **Tag:** v0.99.88

## Context

WAVE D scope (Wave-308) deferred Phase 145 (OpenGL swapchain). Phase
148-lite (Wave-314) + Phase 146/147 (Wave-315) brought the OpenGL
backend to resource-creation completeness. Last missing piece for a
visible draw: bind the engine swapchain to a real OS window + drive
SwapBuffers.

## Decision

### `create_swapchain` (real implementation)

Two paths:

- **External window**: `desc.window_handle` is a real HWND. Acquire
  its HDC, install a `PIXELFORMATDESCRIPTOR` matching the GL
  context, re-bind via `wglMakeCurrent(hdc, hglrc_)`. Store in a
  new `SwapchainRec { hwnd, hdc, width, height, owns_dc=true }`.
- **Headless / dummy window**: `desc.window_handle == nullptr`.
  Reuse the device's own dummy window+HDC. Useful for tests + the
  pre-window probe path.

### `acquire_next_image`

Returns image index 0 (single-image swapchain — GL has no
multi-buffer abstraction at the engine level; GDI handles
double-buffering internally).

### `present`

Calls `SwapBuffers(hdc_)` to flip the back buffer.

### `destroy_swapchain`

Releases the DC if `owns_dc`.

### `upload_buffer`

Wires the previously-stubbed DSA path: `glNamedBufferSubData`.

### `hello_opengl_triangle` sample

End-to-end visible draw:

1. `cd::platform::create_window` (640×480 Win32 window).
2. `cd::rhi_opengl::create_gl_device` (boots GL on dummy window).
3. `device.create_swapchain({window_handle: HWND, ...})` — binds GL
   to the real window's HDC.
4. Raw GL: VAO + VBO with `[pos.xy, col.rgb]` per vertex, vertex +
   fragment shader, linked program.
5. 120-frame loop: pump events, `acquire_next_image`, animated
   clear color, `glDrawArrays(GL_TRIANGLES, 0, 3)`, `present`.

The draw call uses raw GL (no `ICommandBuffer` for OpenGL yet —
that's a v1.3+ phase). The sample mixes cd::rhi (device + buffer +
swapchain + present) with raw GL (draw) deliberately — the engine's
GL command-buffer abstraction is out of scope.

[gl] adapter: NVIDIA GeForce RTX 3080 Laptop GPU/PCIe/SSE2
[gl] swapchain bound to native HWND
[gl] entering frame loop (120 frames)...
[gl] hello_opengl_triangle done — visible OpenGL triangle drawn.

Visible RGB-vertex-color triangle on screen for 2 seconds. Clean
exit. 59/59 ctest surface still green.

## Rejected alternatives

- **Multi-image swapchain backed by FBOs** — extra texture rounds
  per frame for what GDI already gives us via `SwapBuffers`.
  Acceptable simplification.
- **Full GL command-buffer abstraction in this phase** — would
  triple the diff size. The raw-GL draw call in the sample is
  honest about that scope decision.
- **wglCreateContextAttribsARB upgrade** — would let us request GL
  4.6 core profile explicitly. The current driver returns 4.6
  compatibility by default on every Windows adapter we've tested;
  the upgrade is a v1.3 polish item.

## Consequences

- OpenGL backend now has every resource path of value: buffer (137),
  texture (143), sampler (144), shader (146), pipeline (147),
  swapchain (167). Only the command-buffer abstraction is missing.
- `hello_opengl_triangle` proves end-to-end OpenGL works on this
  host's RTX 3080.
- WAVE D items 145, 148 reclaimed (the Wave-308 deferral note can
  be pruned in a future doc pass).

## Open follow-ups

- OpenGL ICommandBuffer abstraction (record + replay state changes
  + draw calls).
- `wglCreateContextAttribsARB` for explicit version + debug context.
- Vsync control via `wglSwapIntervalEXT`.
- Multi-window swapchain support (currently single-window).
