# ADR — v0.43.0 / Wave 167 — Phase 15.B D3D12 descriptor sets

- Date: 2026-05-24
- Status: Accepted
- Wave: 167
- Tag: v0.43.0
- Predecessor: ADR-20260524-wave166 (v0.42.0 editor WASD)

## Context

The D3D12 backend's `create_descriptor_set_layout` /
`allocate_descriptor_set` / `update_descriptor_set` /
`bind_descriptor_set` were stubs returning kNotImplemented (or
silent no-ops) since v0.27.0. Without them, D3D12 samples were
limited to inline vertex data + no constant buffers. Phase 15.B
closes the gap.

## Decision

Tag **v0.43.0**. Scope: real descriptor-set surface on D3D12,
short-listed to CBV + 2D-texture SRV (the common case).
Sampler / UAV / cube SRV remain on the deferred list.

### What landed

- **`DescriptorSetLayoutRecord`** stores the full
  `DescriptorSetLayoutBinding[]` + counts (view/sampler).
- **`PipelineLayoutRecord`** carries the root signature plus
  the table-parameter index list so `bind_descriptor_set`
  knows where to bind each set.
- **`DescriptorSetRecord`** carries the layout handle, the
  CPU-heap slot offset, and the view count.
- **`create_pipeline_layout` rewritten** — builds one
  `D3D12_DESCRIPTOR_TABLE` root parameter per descriptor-set
  layout. Within each table, separate ranges per type
  (CBV / SRV / UAV) are produced from the layout bindings.
  Sampler-only layouts are skipped (deferred to a sampler
  wave). Empty PipelineLayoutDesc still produces a valid
  signature so hello_d3d12_triangle keeps working.
- **`allocate_descriptor_set` real impl** — lazily creates a
  4096-slot CPU-visible CBV/SRV/UAV heap; bump-allocates
  `view_count` slots per set.
- **`update_descriptor_set` real impl** —
  - CBV (`kUniformBuffer` / `kUniformBufferDynamic`) →
    `CreateConstantBufferView` with size aligned up to 256.
  - SRV 2D (`kSampledImage`) →
    `CreateShaderResourceView` with `D3D12_SRV_DIMENSION_TEXTURE2D`
    + default 4-component swizzle.
  - Other descriptor types return `kNotImplemented` with a
    diagnostic naming the v0.43.0 short-list.
- **`bind_descriptor_set` real impl** — copies the set's
  descriptors from the CPU heap into a per-frame
  GPU-visible heap (16k-slot ring buffer that wraps on
  overflow, relies on the sample's `wait_idle()` between
  frames), then calls `SetDescriptorHeaps` +
  `SetGraphicsRootDescriptorTable(set_index, gpu_handle)`.

### What deliberately did NOT land

- **Sampler descriptor heap.** D3D12 requires samplers in a
  separate heap; the abstraction needs a second GPU-visible
  heap + a coordinated bind. Deferred.
- **UAV writes.** `D3D12_UAV_DIMENSION_*` + counter buffers
  + dynamic stride. The full UAV story wants a real
  compute-pipeline sample to drive it.
- **Cube + array SRVs.** Only Texture2D today. Cube /
  Texture2DArray dimensions land alongside their first
  sample consumer.
- **Slot reclamation on `destroy_descriptor_set`.** Bump
  allocator without a free-list; the 4k CPU + 16k GPU caps
  are generous for the marathon-shippable use case. A slab
  allocator with free-list lands in a future renderer-
  architecture wave.
- **`hello_d3d12_cube` consumer sample.** Held for v0.44.0
  (Phase 15.C / DXC) so SM6-compiled shaders can drive
  the descriptor binding from day one.

## Rejected alternatives

- *Implement everything (samplers, UAVs, cube SRVs)
  in one wave.* Rejected: scope creep. The CBV + Texture2D
  SRV short-list covers ~80% of common forward-renderer
  needs; the rest land alongside their first consumer.
- *Skip the GPU-visible heap copy and bind the CPU heap
  directly.* Not possible — D3D12 disallows shader-visible
  reads from non-`HEAP_FLAG_SHADER_VISIBLE` heaps.
- *Use root CBVs (`D3D12_ROOT_PARAMETER_TYPE_CBV`) instead
  of tables.* Rejected: root CBVs work but don't compose with
  the engine's set-layout abstraction (sets carry mixed
  types). The descriptor-table path matches the Vulkan
  side semantics.

## Consequences

- v0.43.0 is the new latest SemVer marker.
- D3D12 samples can now bind constant buffers and 2D textures.
- `hello_d3d12_triangle` keeps working (empty
  PipelineLayoutDesc → empty root sig).
- Phase 15.C (DXC / SM6 → v0.44.0) opens next.
