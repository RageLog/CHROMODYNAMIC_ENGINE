# ADR-20260524 / Wave 273 / v0.99.38 / Phase 107 — PropertyDrawer

## Status
Accepted — 2026-05-24

## Context

hello_editor Phase 103 settled on a "drag widget edits LocalTransform
live; on release we push a single delta command to EditHistory"
pattern. The bookkeeping (snapshot pre-drag value on
`IsItemActivated`, mark a release flag on `IsItemDeactivatedAfterEdit`,
restore the pre-drag value before pushing the command) is 6–8 lines
per property. Every future inspector panel that wants live drag has
to reproduce it, and any tweak (e.g. epsilon for "did this drag
matter?") drifts across copies.

## Decision

New `cd::editor::PropertyDrawer.hpp`:

- `template<T> struct DragSession { pre_drag; armed; release_pending; }`
- `observe(current, is_activated_fn, is_released_after_edit_fn)` —
  captures pre-drag on activation, raises release_pending on edit
  completion.
- `consume_release(out_target)` — single-shot read of the release
  flag, writes the pre-drag value back to the caller so they can
  rewind + push a clean command.
- `drag_delta_significant(a, b, eps)` — convenience for skipping
  no-op pushes when the user clicked but didn't actually drag.
- Function-pointer parameters for ImGui's `IsItemActivated` /
  `IsItemDeactivatedAfterEdit` so this header does NOT pull in
  imgui.h. Consumers `#include <imgui.h>` first, then pass
  `&ImGui::IsItemActivated` and `&ImGui::IsItemDeactivatedAfterEdit`.
- `DragSessionVec3` + `DragSessionFloat` typedefs for the two
  shapes the inspector uses today.

## Rejected alternatives

- **Pull in imgui.h directly.** Smaller call site but forces every
  cd::editor consumer to also link / find_package(imgui). The
  function-pointer pattern keeps cd::editor's public surface
  imgui-agnostic.
- **Embed the drag command construction in the helper.** Looks
  cleaner at first glance but couples PropertyDrawer to every
  Command type the editor ships (TranslateCommand, ScaleCommand,
  RotateCommand, plus future ones). Free-function approach lets the
  caller construct any command type with the delta the session
  produced.
- **Coroutine-style "edit transaction" wrapper.** Overkill for an
  ImGui pattern that already runs once per frame.

## Consequences

- hello_editor's three inline drag-session blocks can collapse to a
  three-line each call (Phase 121 follow-up).
- Any future panel (light inspector, material inspector, animation
  curve editor) gets undo/redo via the same primitive.
- `cd::editor` header surface grows by one file; no link-line
  changes.

## Validation

```
cmake --build --preset llvm-win-debug --target cd_editor
```

Compiles clean. Sample-side migration deferred — the existing
hello_editor inline pattern is exactly what the helper distills, so
they're already in sync semantically.
