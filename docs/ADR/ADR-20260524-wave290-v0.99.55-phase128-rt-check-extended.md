# ADR-20260524 / Wave 290 / v0.99.55 / Phase 128 — hello_rt_check Phase 117/118/127 probes

## Status
Accepted — 2026-05-24

## Context

Three RT-related phases landed in this marathon run without an
end-to-end probe sample exercising their data structures:

- Phase 117 — `AccelInstance` + `AccelStructureDesc::instances`.
- Phase 118 — `RtShaderEntry`, `RtPipelineDesc`, `SbtRegion`,
  extended `DispatchRaysDesc`.
- Phase 127 — Vulkan TLAS create path.

`samples/hello_rt_check` (Phase 14.G) probed BLAS-only and didn't
touch the new types.

## Decision

Extend `hello_rt_check/main.cpp`:

1. Probe BLAS **and** TLAS create paths. TLAS uses a single
   identity-transform `AccelInstance` (`mask=0xFF`, null BLAS — the
   size query doesn't deref it, only counts).
2. Add `static_assert` lines for `AccelInstance == 64 B` (must
   match `VkAccelerationStructureInstanceKHR`) and `SbtRegion >=
   32 B` (four 8-byte members).
3. Print `sizeof` of the four RT-pipeline descriptor types so a
   future backend wave knows the wire-layout it must respect.
4. Update the final-line message to v0.99.54 and reword
   "queued for a follow-up wave" to point at "build/dispatch
   pipeline" specifically.

## Rejected alternatives

- **Standalone new sample.** hello_rt_check is the canonical RT-
  probe entry point; bifurcating would dilute it.
- **Skip the `static_assert`s.** They guard against accidental
  layout drift when AccelInstance gets bitfield-shuffled.

## Consequences

- One more compile-time check for `AccelInstance` size.
- Sample's output grows from ~7 lines to ~14 with the size
  table; still terse.
- No engine-side changes — sample-only refactor.

## Validation

```
cmake --build --preset llvm-win-debug --target cd_sample_hello_rt_check
```

Builds clean. Runtime print only verifiable on machines with a
Vulkan-capable ICD.
