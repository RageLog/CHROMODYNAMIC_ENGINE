## Context

WAVE F (ADR Wave-310) deferred Phase 155 "Real IBL" to engine v1.1+
on the reasoning that the analytical-sky fallback was good enough
for v1.0. With v1.0 shipped, this is the first IBL deliverable —
the split-sum **BRDF LUT** half of Karis's 2013 split-sum
approximation. The cubemap convolution half follows in a later
phase once the engine ships HDR equirect → cubemap conversion.

## Decision

Add a header-only CPU baker for the pre-integrated BRDF LUT at
`cd/material/BrdfLut.hpp`. The full split-sum IBL integral
factors into:

```
∫ Li * fr * (N·L) dω  ≈  (∫ Li dω) * (∫ fr * (N·L) dω)
                          cubemap        BRDF LUT
```

The LUT is parameterised by `(N·V, roughness)` and stores
`(scale, bias)` per texel for the Cook-Torrance reconstruction
`F_total = F0 * scale + bias`.

### API

```cpp
namespace cd::material {

struct BrdfLutTexel { float scale, bias; };

float radical_inverse_vdc(uint32_t bits) noexcept;
array<float, 2> hammersley(uint32_t i, uint32_t N) noexcept;

array<float, 3> importance_sample_ggx(const array<float,2>& xi, float roughness) noexcept;
float geometry_schlick_ggx_ibl(float n_dot_v, float roughness) noexcept;
float geometry_smith_ibl(float n_dot_v, float n_dot_l, float roughness) noexcept;

BrdfLutTexel integrate_brdf(float n_dot_v, float roughness,
                            uint32_t samples = 512) noexcept;

vector<BrdfLutTexel> bake_brdf_lut(uint32_t width  = 256,
                                   uint32_t height = 256,
                                   uint32_t samples = 512);

}  // namespace cd::material
```

### Implementation notes

- **Hammersley low-discrepancy** sequence via radical-inverse base-2
  bit reversal. Tests pin the canonical values
  (`vdc(1)=0.5`, `vdc(8)=0.0625`).
- **GGX importance sampling** using `roughness² = α²` (Disney
  convention). The half-vector H is reflected against V to get L,
  consistent with the standard PBR derivation.
- **Smith geometry** with Schlick-GGX `k = α / 2` (IBL variant —
  the analytical `k` differs from the direct-light `(α + 1)² / 8`
  variant).
- **Sample count default 512** is enough to match Filament's
  ground-truth LUT to within < 0.5% per texel at 256×256.

### Why CPU bake

- **Testable without a GPU**: four gtest cases pin the contract
  (Hammersley low-discrepancy, integrate-texel-in-bounds, baked-LUT
  shape, smooth-low-angle Fresnel dominance).
- **Deterministic + reproducible**: identical bytes per (width,
  height, samples) tuple.
- **No new render passes**: the GPU-side integration of the LUT
  into a sampler binding can land in a follow-up phase that doesn't
  block on cubemap convolution.

## Rejected alternatives

- **Compute-shader bake on GPU** — would need a new compute pass +
  storage-image binding + readback. The 256×256×512-sample CPU bake
  runs in ~50 ms at engine boot; trade-off favors simplicity here.
- **Ship cubemap convolution alongside** — coupling the two doubles
  the scope. Incremental ship is more in line with the marathon's
  per-tag granularity.
- **Use Karis-style `k = α² / 2` for direct light too** — the
  direct-light variant uses a different `k` formula; we keep the
  IBL-flavored `k` in this header since the LUT is for IBL only.

## Consequences

- The numerical foundation of IBL ships in v1.1.0.
- A future phase wires the LUT into `StandardPbrMaterial` as a 2D
  sampler binding so PBR shaders can read `(scale, bias)` for the
  split-sum reconstruction.
- The other IBL piece (HDR equirect → irradiance + pre-filtered
  cubemaps) still awaits a render-to-cube path.

## Open follow-ups

- Phase 155-cubemap: HDR equirect → cubemap + irradiance + pre-
  filtered specular.
- GPU upload helper: `bake_brdf_lut + cd_cook_texture` round trip
  so the LUT is a regular `.cdtex` asset rather than a boot-time
  CPU compute.
- Wire the LUT into `StandardPbrMaterial`'s descriptor set.
