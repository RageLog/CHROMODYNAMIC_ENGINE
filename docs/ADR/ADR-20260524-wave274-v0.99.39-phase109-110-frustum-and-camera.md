# ADR-20260524 / Wave 274 / v0.99.39 / Phase 109+110 — Frustum::contains_sphere + SceneCameraController

## Status
Accepted — 2026-05-24

## Context

Two small but explicit pending items from the marathon outstanding list:

1. **`Frustum::contains_sphere`.** The frustum primitive (Phase 29.C)
   shipped `intersects(Frustum, Aabb)` for bounding-box culling but
   omitted the cheaper bounding-sphere test. Many cull loops want to
   reject by sphere first and only fall back to AABB when the sphere
   says "maybe."

2. **CameraController integration into `cd::scene`.** OrbitController
   (Phase 14.E) is camera-only; it doesn't know about scene entities.
   Editor / viewer code re-implements the "follow entity X" hook
   inline every time.

## Decision

### Phase 109 — `Frustum::contains_sphere` + `fully_contains_sphere`

Two new free functions in `cd::scene`:

- `contains_sphere(f, center, radius)` — inclusive. Returns false
  iff the sphere is fully outside any plane (signed distance <
  -radius). One scalar compare per plane; no AABB construction.
- `fully_contains_sphere(f, center, radius)` — strict. Returns true
  only when the sphere clears every plane by at least its radius.
  Useful for "trivially-accept" cases that skip per-object draws.

Five new unit tests in `test_scene.cpp` covering centre-inside,
far-outside, plane-touching, partial overlap, and strict-only
acceptance.

### Phase 110 — `cd::scene::SceneCameraController`

Header-only facade that wraps `OrbitController` with a follow hook:

- `attach(camera, scene, target_entity = {})` — bind camera + scene
  pair, optionally also bind a target entity to follow.
- `update(dt)` — pulls the target entity's world translation into
  `camera.target` every frame; then runs `OrbitController::apply`
  (or `update_auto` if auto-spin is enabled).
- Forwards `drag(dx, dy)` and `zoom(delta)` to the underlying
  controller so the input layer doesn't change.

## Rejected alternatives

- **Free `contains_sphere(planes_span, center, radius)`** — would
  let any 6-plane structure use it. Keeping the function bound to
  `Frustum` is consistent with the existing `intersects(Frustum,
  Aabb)` signature; consumers wanting a generic plane test can
  build their own from `signed_distance(Plane, Vec3f)`.
- **First-person `FreeFlyController` in scene** — pending separate
  phase (Phase 14.E roughly did this in hello_editor, but the
  pattern hasn't been formally lifted to engine). Out of scope here.
- **Aware of `WorldTransform.matrix.column(3)` accessor** — the
  Scene's `WorldTransform` uses `matrix[3][0..2]` raw indexing today;
  not adding a helper just for this controller.

## Consequences

- `cd::scene` grows by one inline header (no `.cpp`); no link order
  changes.
- `cd::camera` untouched; `SceneCameraController` is in `cd::scene`
  because it depends on `Scene::world_transform()`. Layering stays
  intact (scene depends on camera, not the other way around).
