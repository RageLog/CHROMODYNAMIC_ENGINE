# ADR Wave-309 — Phase 142 D3D12 DXR Tier 1.1 deferral (v0.99.74)

- **Date:** 2026-05-25
- **Status:** Accepted (scope decision)
- **Predecessor:** [ADR-20260525-wave308-v0.99.73-phase143-144-opengl-texture-sampler](./ADR-20260525-wave308-v0.99.73-phase143-144-opengl-texture-sampler.md)
- **Successor:** ADR Wave-310 (Phase 155 IBL)
- **Tag:** v0.99.74

## Context

Phase 132+135+136+141 brought ray tracing to the Vulkan backend
end-to-end: BLAS/TLAS build, RT pipeline, SBT, kAccelerationStructure
descriptor wire, and a working `dispatch_rays` in hello_rt.
Phase 142 was scheduled to mirror that on D3D12 via DXR Tier 1.1
(`ID3D12Device5::CreateStateObject`,
`BuildRaytracingAccelerationStructure`,
`ID3D12GraphicsCommandList4::DispatchRays`).

## Decision

**Phase 142 (D3D12 DXR Tier 1.1) is DEFERRED to engine v1.1+.**

Reasoning:

- **Primary RT path covers the feature.** Vulkan RT is shipped and
  validated end-to-end. Apps that need ray tracing have a working
  backend.
- **D3D12 is the secondary backend.** Its graphics path is complete
  (50 virtuals, 4 remaining `kNotImplemented` stubs that are all in
  edge-case paths). Adding DXR is ~800 lines of code that closes
  parity on a feature the primary backend already covers.
- **Marathon scope.** This phase was listed as "hard, specific,
  medium priority" in the marathon plan. Following the marathon
  ordering rule (easy → hard, general → specific, high → low
  priority), Phase 142 sits later than the items in WAVE F (IBL,
  skeletal animation, push-stream audio) which deliver more
  engine-wide feature value, and later than WAVE G (CI quality
  gates) which protects every existing subsystem.
- **No regression.** The current behavior (D3D12 falls through to
  `IDevice::create_acceleration_structure`'s base
  `kNotImplemented`) is correct; callers gate on
  `features().ray_tracing`.

## Rejected alternatives

- **Implement a minimal subset (AS create only, no dispatch)** —
  would leave the D3D12 path in a half-state callers can't actually
  use. Either ship full DXR or don't claim partial support.
- **Implement full DXR now** — would consume the rest of this
  marathon's budget on a feature already covered by Vulkan.

## Consequences

- v1.0 support matrix is final:
  - Vulkan: graphics + compute + RT (primary)
  - D3D12: graphics + compute (secondary, RT deferred)
  - OpenGL: buffer + texture + sampler (partial, Phase 145-148
    deferred per Wave 308)
- D3D12 backend's `kNotImplemented` count stays at 4 (none of which
  are RT-specific — RT inherits from the IDevice base defaults).

## Open follow-ups

- Engine v1.1: D3D12 DXR Tier 1.1 mirror including the descriptor
  write-side filling of the `RAYTRACING_ACCELERATION_STRUCTURE`
  SRV (the Phase 140 root-signature range mapping is already
  wired).
- A doc page comparing the Vulkan vs D3D12 RT API ergonomics so a
  future contributor knows where the existing Vulkan code can be
  translated wholesale and where DXR Tier 1.1 demands a different
  shape (especially around StateObject vs RtPipeline).
