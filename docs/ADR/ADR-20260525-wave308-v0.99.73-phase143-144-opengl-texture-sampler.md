# ADR Wave-308 — Phase 143/144 OpenGL texture + sampler (v0.99.73) + WAVE D scope decision

- **Date:** 2026-05-25
- **Status:** Accepted
- **Predecessor:** [ADR-20260525-wave307-v0.99.72-phase151-152-editor-overlays](./ADR-20260525-wave307-v0.99.72-phase151-152-editor-overlays.md)
- **Successor:** ADR Wave-309 (Phase 142 D3D12 DXR)
- **Tag:** v0.99.73

## Context

Phase 137 (v0.99.63) shipped the OpenGL backend's first real
endpoint — DSA `create_buffer` via WGL extension loading. The
roadmap then listed Phases 143-148 (texture, sampler, swapchain,
shader compile path, pipeline state, sample) as remaining work.

The bigger architectural question for v1.0: **what production
value does a half-implemented OpenGL backend ship?** Vulkan is the
primary modern backend; D3D12 has been the secondary mirror. The
engine's library-oriented goal does not require OpenGL for any
ship-blocker — it's a *third* backend, not a *replacement* path.

## Decision

1. **Phase 143 + 144 land in this tag:**
   - `create_texture` / `destroy_texture` via DSA
     `glCreateTextures` + `glTextureStorage2D`. Format map covers
     RGBA8, BGRA8, R8, D24S8, D32 (subset; expand as consumers
     appear).
   - `create_texture_view` / `destroy_texture_view` — OpenGL has
     no separate view object, so the view handle is a thin
     alias over the same texture id.
   - `create_sampler` / `destroy_sampler` via DSA
     `glCreateSamplers` + `glSamplerParameteri`. Maps
     `SamplerFilter` / `SamplerMipmapMode` / `SamplerAddressMode`
     onto the GL constants.
   - `GLLoader` extended with seven new function-pointer slots
     (`glCreateTextures`, `glTextureStorage2D`,
     `glTextureStorage3D`, `glCreateSamplers`, `glSamplerParameteri`,
     plus delete variants). Loader has new `texture_valid()` /
     `sampler_valid()` predicates so endpoints fall back to
     `kNotImplemented` gracefully on drivers lacking DSA 4.5.

2. **Phase 145 / 146 / 147 / 148 are DEFERRED to engine v1.1+:**
   - **145 swapchain**: needs WGL_ARB_pixel_format +
     WGL_ARB_create_context_attribs + `wglSwapIntervalEXT`,
     a real framebuffer object as the render target, image
     acquire/present semantics that mirror Vulkan, and
     out-of-date/resize handling. Substantial work, not on the
     v1.0 critical path.
   - **146 shader compile path**: GLSL goes directly to the GL
     pipeline (no SPIR-V intermediate the way Vulkan uses), so
     `cd::shader::ICompiler` cannot be reused — needs a GL-specific
     compile path. Out of scope for v1.0.
   - **147 pipeline state**: GL has no PSO object; pipeline state
     would be captured into a `GLPipeline` struct and replayed
     into a stream of `glUseProgram` / `glBindVertexArray` /
     state-mask calls on bind. Doable but expensive without 145+146.
   - **148 hello_opengl sample**: blocked on the above.

   The deferral is **explicit**, not silent. The marathon plan
   listed these phases; this ADR is the formal record that v1.0
   ships with Vulkan-primary + D3D12-secondary, and OpenGL stays
   as Phase-137/143/144 partial.

## Rejected alternatives

- **Skip OpenGL entirely** — the existing Phase 137 buffer code
  would rot. Texture + sampler bring the backend to a coherent
  "resource creation" milestone even without draw.
- **Implement full OpenGL backend in marathon scope** — would
  consume hours that the marathon needs for higher-value work
  (D3D12 DXR, IBL, CI gates).
- **Mark OpenGL as removed** — leaves the door open for v1.1
  contributors to finish 145-148 without losing the foundation.

## Consequences

- OpenGL backend: buffers (137) + textures (143) + samplers (144).
  D3D12 backend: full graphics + RT pipeline. Vulkan backend:
  full graphics + RT pipeline with TLAS dispatch.
- The engine v1.0 documentation will state the support matrix
  explicitly: Vulkan = primary; D3D12 = secondary; OpenGL = partial.

## Open follow-ups

- Engine v1.1: pick up Phases 145-148.
- A `hello_opengl_resources` smoke test that exercises 137+143+144
  (creates a buffer, a texture, a sampler, exits) — minimal but
  proves the partial backend boots cleanly. Optional; not required
  for v1.0.
