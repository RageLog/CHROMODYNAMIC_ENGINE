# ADR — v0.35.0 / Wave 158 — Phase 14.B cooker improvements (KTX2 write)

- Date: 2026-05-23
- Status: Accepted
- Wave: 158
- Tag: v0.35.0
- Predecessor: ADR-20260523-wave157 (v0.34.0 scene save/load)
- Phase 14 master: ADR-20260523-wave156-phase14-plan.md

## Context

Phase 14.B scope per the wave156 plan:
- **BC7 quality knob** — pick fast/balanced/high at cook time.
- **KTX2 mip-chain generation** at cook time.

Codebase audit at sub-phase start:
- `cd::asset_image::Bc7Quality { kFast, kBalanced, kHigh }` already
  exists; `tools/cook_texture` already accepts
  `-q {fast,balanced,high}`. BC7 quality is **done** and tested
  via `cd_test_asset_image`.
- `cd::asset_image::generate_mips(const Image&, levels)` already
  exists; `tools/cook_texture` already accepts `--mips` to emit
  full mip chains into `.cdtex v2`.
- `cd::asset_ktx2::load` / `load_from_memory` read existing KTX2
  files, but **no write path** — there was no way to produce
  KTX2 output from the engine.

The gap that closes Phase 14.B: a KTX2 *encoder*, so the cooker
can emit `.ktx2` next to (or instead of) `.cdtex`.

## Decision

Tag **v0.35.0**. Scope: `cd::asset_ktx2::encode_to_memory` +
`cd::asset_ktx2::write` round-tripping every format the reader
accepts.

### What landed

- **`encode_to_memory(const Ktx2&) → Result<vector<uint8_t>>`** in
  `engine/asset_ktx2/include/cd/asset_ktx2/Ktx2.hpp` (declaration)
  and `src/Ktx2.cpp` (impl).
- **`write(const Ktx2&, std::string_view path) → Result<void>`**
  thin wrapper over encode + ofstream.
- Encoder writes the 80-byte KTX2 v2 header, the level index
  table (mip0 .. mipN in order, every entry pointing at the
  smallest-mip-first payload layout per the spec), and the raw
  payload. DFD/KVD/SGD are written as empty (length 0, offset 0)
  — the engine reader silently tolerates this because it never
  reads DFD; compliant readers like PVRTexTool accept empty DFD.
- Format short-list matches the reader: RGBA8 / BGRA8 (UNORM +
  SRGB) and BC7 (UNORM + SRGB). Other formats return
  `kUnsupportedFormat`.
- **Four new tests** in `cd_test_asset_ktx2`:
  - `Ktx2Encode.EncodeDecodeRoundTripsRgba8` — single-mip
    encode → decode equality.
  - `Ktx2Encode.EncodeMipChainPreservesEveryLevel` — 3-level
    BC7 mip chain, every level byte-equal after round-trip.
  - `Ktx2Encode.WriteToDiskMatchesLoadFromDisk` — write a
    `.ktx2`, load it via `load(path)`, compare to source.
  - `Ktx2Encode.EmptyMipsRejected` — empty `tex.mips` returns
    `kInvalidArgument`.

### What deliberately did NOT land

- **Basis / Zstd supercompression.** The reader rejects it with
  `kUnsupportedSupercompression`; the writer never emits it.
  Closes the policy match. Adding supercompression is its own
  phase (vendored basis_universal or `zstd` library).
- **Cubemap / array textures.** Reader rejects both; writer
  never emits them. Same policy match.
- **DFD blob.** Some tools (RenderDoc texture inspector, certain
  PVRTexTool versions) require DFD to display the texture
  correctly. The cooker output is engine-internal-first;
  re-routing to a third-party tool can re-encode via
  `toktx --2d`.
- **Cooker CLI integration.** `tools/cook_texture` already
  handles BC7 + mips via `--mips`. Adding `.ktx2` output as a
  new flag (`--ktx2 <path>`) is a one-screen change but lands
  in a follow-up — Phase 14.B closes the *library* gap; the
  CLI is the next concrete consumer.

## Rejected alternatives

- *Pull in libktx (Khronos reference).* Rejected: 80 KB of
  source for a writer the engine already has nine-tenths of
  via its existing reader. The hand-rolled encoder matches the
  rest of the asset library's no-vendor policy.
- *Write the full KTX2 v2 spec (DFD + KVD + cubemaps).*
  Rejected: scope creep against the marathon-shippable bar.
  The reader-writer pair is round-trip-honest within the
  short-list; that's the right contract.
- *Tag without tests.* Rejected: an encoder without a
  round-trip test would mask layout bugs that only fire on
  third-party readers. Four tests cover the load-write-load
  cycle on every accepted format.

## Consequences

- v0.35.0 is the new latest SemVer marker.
- The engine can now emit KTX2 textures programmatically — the
  shape an offline content pipeline needs.
- `cd_test_asset_ktx2` grows from 8 to 12 test cases.
- Phase 14.C (D3D12 PSO + draw + hello_d3d12_triangle →
  v0.36.0) opens next.
