# ADR-20260524 / Wave 268 / v0.99.33 / Phase 101 — Demo Reel

## Status
Accepted — 2026-05-24

## Context

After Phase 100 closed the marathon with 103 tags and ~170 header-only
primitives across the engine, the user asked to **see** the work before
continuing integration. Many subsystems (audio DSP, net replication,
editor command palette) had unit tests but no end-to-end sample that a
person could just run and observe behaving.

The 49 existing `hello_*` samples lean toward the render pipeline
(Vulkan triangle → cube → mesh → PBR → skybox → framegraph → editor).
The non-render subsystems were under-represented in demo form even
though they shipped substantial primitives during the marathon
(`cd::audio::Mixer/Compressor/Reverb/LowPass/Limiter`, `cd::net::*`,
`cd::editor::CommandPalette`).

## Decision

Add three headless console demos and one walkthrough document:

1. **`samples/hello_audio_chain`** — wires Mixer → Compressor →
   SimpleReverb → LowPass → Limiter in a real DSP graph, drives it
   with a deterministic square + noise-burst test source, writes the
   chain output to a WAV the user can play, prints compressor gain
   reduction + limiter activity + peak-after-chain telemetry.

2. **`samples/hello_net_sim`** — wires SnapshotBuffer, DeltaWriter,
   LatencyStats, Throttle in a 2-second offline replication
   simulation. Server orbits an entity at 60 Hz; outbound traffic is
   token-bucket-throttled to 30 pkt/s; channel applies 10 % loss + 30
   to 90 ms variable latency; client interpolates 100 ms behind the
   newest snapshot. Prints a per-second table of sent/recv/dropped,
   raw-vs-wire bytes, RTT EWMA + jitter, interp lookup count.

3. **`samples/hello_command_palette`** — registers 34 editor-style
   commands with the Phase 31 `cd::editor::CommandPalette`, runs
   queries (`save`, `trs`, `tog`, `view`, `rndshd`, `rdc`,
   `xyz_no_match`), prints the ranked top-5 of each so the FZF
   subsequence scoring is visible. Invokes the top match to verify
   the callback path.

4. **`docs/DEMO_REEL.md`** — a categorized index of all 49 samples
   with run commands, a recommended 10-minute walkthrough order, and a
   subsystem-to-sample cross-reference.

Wire all three new samples into `samples/CMakeLists.txt` so the
`samples` build target picks them up.

## Rejected alternatives

- **Big "everything" demo binary.** A single `hello_all` that drives
  audio + net + editor would mix unrelated APIs in one main() and
  obscure the per-subsystem signal. The marathon convention is one
  primitive per phase, one sample per concept.
- **GUI app that exercises the palette interactively.** That belongs
  in the editor frontend (still pending in MARATHON_SUMMARY's
  outstanding-items list). A headless print proves the registry +
  ranking work without coupling to ImGui yet.
- **Recording video / GIFs.** The user asked to **run** the demos.
  Adding generated artifacts to the repo would bloat it and rot.

## Consequences

- Engine compresor header (`cd/audio/Compressor.hpp`) had a latent
  warnings-as-errors bug — `std::max` was used without including
  `<algorithm>`, and the `log10` chain implicitly promoted float to
  double. Both surfaced when the new sample was first compiled.
  Patched to a one-liner branch + explicit float overload of
  `std::log10`. No behavioural change.
- `hello_audio_chain` exposed that the soft-knee Limiter has ~10
  samples of attack lag at 0.2 ms attack constant — a transient on a
  hot signal can briefly exceed the threshold. Captured in the sample
  source as a tuning note; the demo signal was calmed to a realistic
  level so the chain still ends well under ±1.
- DEMO_REEL.md becomes the canonical entry point for "show me what
  the engine can do" rather than `MARATHON_SUMMARY.md` (which is the
  developer-facing changelog).

## Validation

```
cmake --build --preset llvm-win-debug --target \
    cd_sample_hello_audio_chain \
    cd_sample_hello_net_sim \
    cd_sample_hello_command_palette
./build/llvm-win-base/bin/Debug/hello_audio_chain.exe       # OK, peak=0.84
./build/llvm-win-base/bin/Debug/hello_net_sim.exe          # OK, 87% delivery, 79.8% wire/raw
./build/llvm-win-base/bin/Debug/hello_command_palette.exe  # OK, 34 cmds, ranking correct
```

All 33 existing `hello_*.exe` binaries continue to build clean (samples
target green). No engine API changes; the Compressor fix is internal
to its header.
