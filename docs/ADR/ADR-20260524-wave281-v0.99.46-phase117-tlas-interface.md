# ADR-20260524 / Wave 281 / v0.99.46 / Phase 117 — TLAS interface contract

## Status
Accepted — 2026-05-24

## Context

Phase 17.A landed real BLAS construction via
`vkCreateAccelerationStructureKHR` + VMA-backed AS storage. TLAS
support was deferred — `AccelStructureDesc` only described BLAS
triangle geometry. To wire `vkCmdBuildAccelerationStructuresKHR`
for the top-level structure in a future phase, the engine needs
to express an instance list.

## Decision

Extend the RHI descriptor surface only — no Vulkan backend code in
this phase. The actual `create_acceleration_structure(TLAS)` /
`build_acceleration_structure(TLAS)` implementations land in Phase
118 alongside the RT pipeline.

New `cd::rhi::AccelInstance` POD mirrors
`VkAccelerationStructureInstanceKHR` and
`D3D12_RAYTRACING_INSTANCE_DESC`:

- `transform[12]` — 3x4 row-major (column 3 = translation).
  Identity-default.
- `blas` — target BLAS handle.
- `instance_id : 24` — exposed to closest-hit / any-hit shader as
  `InstanceCustomIndex`.
- `mask : 8` — visibility mask (TraceRays cullMask `&` this).
- `hit_offset : 24` — SBT hit-group offset.
- `flags : 8` — `VkGeometryInstanceFlagsKHR` bits.

`AccelStructureDesc` gains an `instances` span (ignored unless
`kind == kTopLevel`).

## Rejected alternatives

- **Implement the whole Vulkan TLAS now.** Build sizes query +
  scratch buffer + instance buffer upload +
  `vkCmdBuildAccelerationStructuresKHR` is a 200+ line Vulkan
  block; the marathon discipline keeps each phase atomic. The
  interface lands first; the implementation lands second.
- **Pack `AccelInstance` to the exact Vulkan bit-layout
  (`VkAccelerationStructureInstanceKHR`).** Tempting because the
  GPU eventually sees that layout, but exposes a Vulkan-specific
  struct in the cross-backend RHI surface. Backend translation
  is the right boundary.
- **Separate `TlasDesc` struct.** Splits BLAS and TLAS into two
  descriptor types and forces a parallel `create_blas` /
  `create_tlas` API. The shared `AccelStructureDesc` keeps the
  IDevice surface small.

## Consequences

- `cd::rhi::AccelInstance` is now public; consumers can prepare
  instance lists before the Vulkan backend wires the build path.
- No backend code changes — full engine + 33 samples + cook tools
  still build clean.
- Phase 118 candidate: Vulkan TLAS implementation that consumes
  `AccelStructureDesc::instances` (instance buffer upload, build-
  sizes query, BLAS device-address translation, scratch buffer,
  `vkCmdBuildAccelerationStructuresKHR`).

```
cmake --build --preset llvm-win-debug
```

Full engine + all samples + tools build green (345/345 targets).
