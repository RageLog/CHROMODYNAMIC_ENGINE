## Context

User feedback: "light ile ilgili hic bir somut gelistirme yok state of
art metadolojilerle piyasadaki engelismis yapiyi sun." The existing
`cd::scene::Light` (Phase 83.A) was minimal: enum + position/dir/
color/intensity/range/cone. No physical units, no clustered
shading, no shadow primitives, no area lights, no color-temperature
support.

This phase ships a dedicated `cd::light` library implementing the
production engine lighting model used by Frostbite (Real Shading
2014), Filament 1.x, , , and id
Tech 6/7.

## Decision

New header-only library `cd::light` under `engine/render/light/`:

### `Light` (112 B, std140-packed)

```cpp
struct Light
{
    Vec3f position;        float range;
    Vec3f direction;       float intensity;       // lumens / lux
    Vec3f color;           float color_kelvin;    // CCT
    float cos_inner_cone, cos_outer_cone, inv_cone_range, _pad;
    Vec3f area_tangent;    float area_width;
    Vec3f area_bitangent;  float area_height;
    int32_t shadow_slot;   uint32_t ies_profile;
    LightType type; uint8_t flags; uint16_t _pad; uint32_t _pad;
};
```

Five `LightType` enumerators: **Directional**, **Point**, **Spot**,
**RectArea**, **DiskArea**. Five constructor helpers (`directional`,
`point`, `spot`, `rect_area`, …) handle normalization + pre-
compute (cone reciprocal, area-light orthonormal basis).

### `ColorTemperature` — CCT (Kelvin) → linear sRGB

Krystek 1985 polynomial fit (CIE 1931 xy → XYZ → sRGB via Lindbloom
matrix). Covers 1000-15000 K — handles every common preset:
candle/firelight (1900), tungsten (2700), halogen (3200),
daylight (5500), D65 (6500), overcast (7000), shade (10000).

### `Attenuation` — Frostbite-style physical falloff

- **Distance**: windowed inverse-square — `(1 - (d/range)^4)^2 / (d^2 + eps)`
- **Spot cone**: smoothstep-squared between inner/outer cosines
- **Lumens → intensity**: `Phi / (4π)` (point), `Phi / (2π(1 - cos(outer)))` (spot)
- **Lux**: directional passes through (illuminance drives shading directly)

### `ClusterGrid` — Forward+ / clustered shading

Olsson et al. 2012 "Clustered Deferred and Forward Shading". Splits
the camera frustum into a 3D grid (default 16×9×24 = 3456 cells,
matches Doom 2016 / Eternal tuning):

- 16×9 screen-space tiles (16:9 aspect).
- 24 logarithmic Z slices (`slice = floor(log(z/near)/log(far/near)*N)`).
- Each cell carries up to 32 light indices + an overflow counter.

`assign(light_index, light, view_pos)` adds the light to every
cluster cell its sphere/cone overlaps. Directional lights touch
every cell.

### `CascadedShadow` — CSM for the directional light

Practical Split Scheme (Zhang 2006) with λ-blended uniform+log
splits. Per cascade:

- Slice frustum corners (NDC → world via inverse VP).
- Bounding-sphere-fit ortho box (Persson 2009, texture-stable).
- Light-space view × ortho projection matrix.

Up to 4 cascades (configurable). Same shape production's
`r.Shadow.CSM.MaxNumCascades` default uses.

## Test coverage

18 tests across 5 suites, all green:

- `Light`: packed-layout assert + 4 type-specific construction checks.
- `ColorTemperature`: D65 ~white, warm ~ red-dominant, cool ~ blue-dominant.
- `Attenuation`: distance zero-at-range, cone in/out invariants, lumens
  formula matches Frostbite §6.2 within 0.5%.
- `ClusterGrid`: sizing, directional touches every cluster, logarithmic
  Z mapping.
- `CascadedShadow`: practical splits monotonic, cascade count matches.

## Rejected alternatives

- **Extend `cd::scene::Light`** — would pollute scene with rendering
  internals (CSM, clusters). Dedicated library keeps scene focused
  on entity / hierarchy.
- **GPU-side cluster build (compute shader)** — common in AAA, but
  CPU-side is simpler for v1 and only ~3 KB SSBO upload per frame.
  Migrate to GPU compute when clustered-deferred shading lands.
- **Stochastic Lights (Reservoir-Sampled ReSTIR)** — production engines/Lumen
  territory. Out of scope; the clustered Forward+ baseline ships
  first.
- **Anisotropic area lights** (linearly-transformed cosines / sphere
  lights / IES web sampling) — Heitz 2016 LTC is on the v1.3 roadmap;
  the storage slots (`area_tangent`/`area_bitangent`/`ies_profile`)
  are in place so the runtime can extend without an ABI break.

## Consequences

- Engine now has a SOTA lighting baseline matching what AAA
  production engines ship today.
- The light record is GPU-friendly (std140-packed at 7×16 = 112 B);
  ready to upload as an SSBO with no manual repacking.
- `cd::scene::Light` (Phase 83.A) kept untouched for back-compat;
  callers can migrate at their leisure.
