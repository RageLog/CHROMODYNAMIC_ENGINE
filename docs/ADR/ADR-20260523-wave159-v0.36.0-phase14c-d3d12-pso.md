# ADR — v0.36.0 / Wave 159 — Phase 14.C D3D12 PSO + draw + triangle

- Date: 2026-05-23
- Status: Accepted
- Wave: 159
- Tag: v0.36.0
- Predecessor: ADR-20260523-wave157 (v0.34.0 scene save/load) and
  ADR-20260523-wave158 (v0.35.0 KTX2 encode), plus the v0.35.1
  hello_editor layout polish patch.
- Phase 14 master: ADR-20260523-wave156-phase14-plan.md

## Context

After v0.32.0 the D3D12 backend could create buffers, textures, a
swapchain, and clear a back-buffer. Every shader / pipeline /
descriptor entry point still returned `kNotImplemented`. Phase 14.C
per the wave156 plan: close the PSO + draw surface so a real
hello_d3d12_triangle sample renders end-to-end.

## Decision

Tag **v0.36.0**. Scope: HLSL→DXIL compile helper +
`create_shader_module` + `create_pipeline_layout` (empty root
signature) + `create_graphics_pipeline` + the
`D3D12CommandBuffer` draw surface (bind_graphics_pipeline /
bind_vertex_buffer / bind_index_buffer / set_viewport /
set_scissor / draw / draw_indexed) + a
`samples/hello_d3d12_triangle` sample.

### What landed

- **`cd::rhi_d3d12::compile_hlsl(const CompileOptions&)`** —
  new public header `D3D12ShaderCompile.hpp`, impl in
  `D3D12ShaderCompile.cpp`. Wraps `D3DCompile2` from
  d3dcompiler.dll. Targets Shader Model 5_1 (vs_5_1 / ps_5_1 /
  cs_5_1 / etc.). On compile failure surfaces the full error
  blob via the owning ErrorCode message — caller sees the
  exact HLSL diagnostic. Non-Windows builds surface
  `kBackendUnavailable` immediately.

- **`D3D12Device::create_shader_module`** — stores the bytecode
  blob + stage + entry point on the device side. Handle keyed
  on `next_id_++`; lookup map maintained alongside the existing
  buffer / texture / swapchain tables. (DXC / Shader Model 6
  bytecode also flows through this path; only the *compiler*
  is SM5-bound at v0.36.0.)

- **`D3D12Device::create_pipeline_layout`** — empty root
  signature (no parameters) with
  `D3D12_ROOT_SIGNATURE_FLAG_ALLOW_INPUT_ASSEMBLER_INPUT_LAYOUT`.
  Serialized via `D3D12SerializeRootSignature`, created via
  `CreateRootSignature`. Sufficient for hello_d3d12_triangle
  (inline vertex data, no CBV); descriptor-table / CBV layout
  is a later wave.

- **`D3D12Device::create_graphics_pipeline`** — translates
  `cd::rhi::GraphicsPipelineDesc` to
  `D3D12_GRAPHICS_PIPELINE_STATE_DESC`:
  - VS / PS bytecode from the recorded ShaderModuleRecords.
  - Optional GS wired when present.
  - RasterizerState: PolygonMode → FillMode, CullMode (None /
    Front / Back, FrontAndBack → None with a "draw nothing"
    caveat), FrontFace → FrontCounterClockwise.
  - BlendState: opaque single-attachment default.
  - DepthStencilState: opt-in via
    `depth_attachment_format != kUndefined`.
  - Topology type mapped to triangle / line / point.
  - Vertex input layout: every `VertexAttribute` becomes a
    `D3D12_INPUT_ELEMENT_DESC` with semantic
    `TEXCOORD<location>`. (Picking TEXCOORD as the
    universal semantic name means HLSL inputs declare
    `float3 pos : TEXCOORD0` regardless of what `location`
    means in the engine — matches the Vulkan-side convention
    where attributes are pure-numeric `layout(location=0)`.)
  - Color attachment formats + depth/stencil format from the
    descriptor's dynamic-rendering hints.
  - Cached `D3D_PRIMITIVE_TOPOLOGY` on the
    `GraphicsPipelineRecord` so `bind_graphics_pipeline` can
    invoke `IASetPrimitiveTopology` at bind time.

- **`D3D12CommandBuffer` draw surface** — replaces v0.32.0
  no-ops with real implementations:
  - `bind_graphics_pipeline`: SetPipelineState +
    SetGraphicsRootSignature + IASetPrimitiveTopology.
  - `bind_vertex_buffer`: D3D12_VERTEX_BUFFER_VIEW via the
    buffer's GPU virtual address. (Stride hard-coded to 24
    bytes for v0.36.0 — the engine's `bind_vertex_buffer`
    signature doesn't carry stride; a follow-up wave adds it.
    Triangle sample uses 24-B vertices so it round-trips
    correctly.)
  - `bind_index_buffer`: D3D12_INDEX_BUFFER_VIEW, U16 vs U32
    format select.
  - `set_viewport` / `set_scissor`: thin wrappers.
  - `draw` / `draw_indexed`: DrawInstanced / DrawIndexedInstanced.

- **`to_dxgi_format` extension** — added `kRGB32Float`,
  `kRG32Float`, `kR32Float`, `kRG32Uint`, `kR32Uint` so
  vertex-attribute formats translate correctly. (The PSO
  create call failed with E_INVALIDARG before this fix
  because `RGB32Float` mapped to `DXGI_FORMAT_UNKNOWN` and
  the input layout was therefore invalid.)

- **`samples/hello_d3d12_triangle`** — 640×360 Win32 window
  + flip-model swapchain + inline HLSL VS/PS + colored
  triangle. End-to-end verified on NVIDIA RTX 3080 Laptop:
  ```
  [d3d12] adapter=NVIDIA GeForce RTX 3080 Laptop GPU
  [d3d12] shaders compiled (VS=14496 B, PS=14376 B)
  [d3d12] PSO + root signature OK
  [d3d12] vertex buffer uploaded (72 B)
  [d3d12] triangle OK — rendered 24558 frame(s)
  ```
- **`CullMode::kFrontAndBack`** handled in D3D12 switch (maps
  to NONE — D3D12 has no equivalent and culling both sides
  equals "draw nothing"). Previous Phase-13.C code was
  -Werror -Wswitch incomplete; now exhaustive.

### What deliberately did NOT land

- **Shader Model 6 (DXC).** D3DCompile2 only emits up to
  SM5_1. DXC (dxcompiler.dll + dxil.dll) needs vendoring and
  brings its own headers. Phase 15 candidate.
- **Descriptor sets / CBVs / SRVs / UAVs on the root
  signature.** The empty root signature shipped here is the
  minimum that makes inline-vertex-data triangles draw. A
  descriptor-table builder + per-frame descriptor heap ring
  comes with the descriptor-set wave.
- **Compute pipeline.** `create_compute_pipeline` still
  surfaces `kNotImplemented`. Closely related to the
  PSO path but the descriptor-set requirement makes it
  worth its own wave alongside the descriptor work.
- **`bind_vertex_buffer` stride parameter.** D3D12 needs
  stride per binding (Vulkan stores it on the pipeline). The
  current cd::rhi signature doesn't carry it through; v0.36.0
  hard-codes 24 bytes as a triangle-sample workaround. Adding
  stride is a small cross-backend ABI change deferred until
  multiple samples actually need different strides.

## Rejected alternatives

- *Pull in DXC for SM6 support.* Rejected: scope creep against
  the marathon-shippable bar. SM5 covers the triangle case
  and every PBR shader the engine currently runs through
  glslang+SPIR-V; matching that coverage on D3D12 doesn't
  require SM6.
- *Skip the inline HLSL in the sample; require pre-compiled
  DXIL bytecode.* Rejected: making the sample build-time-
  dependent on an HLSL compile would add a CMake custom
  command, a separate DXIL output, and a runtime-load step.
  Runtime D3DCompile keeps the sample self-contained and
  mirrors the engine's "shaders are hot-compilable" property
  that Vulkan-side glslang gives for GLSL.
- *Default to clockwise vs. CCW based on Vulkan-NDC
  convention.* The engine default is `front_face =
  kClockwise` (per ADR-20260523-wave131). D3D12 also defaults
  to CW = front. The translation in `create_graphics_pipeline`
  honors the descriptor verbatim — Vulkan-side samples that
  pre-flip Y via the vertex shader produce CW triangles
  at the rasterizer, which D3D12 sees the same way. No
  per-backend convention divergence.

## Consequences

- v0.36.0 is the new latest SemVer marker.
- The D3D12 backend goes from "clear-only" (v0.32.0) to
  "draws triangles via the standard cd::rhi
  ICommandBuffer surface". The bind / draw call sequence
  is the same on Vulkan and D3D12 — the triangle sample's
  body is the proof.
- Phase 14.D (reliable channel + replication → v0.37.0)
  opens next.

  rendered visually equivalent output on the same machine
