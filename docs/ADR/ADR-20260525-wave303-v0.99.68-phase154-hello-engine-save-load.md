# ADR Wave-303 — Phase 154 hello_engine scene save/load round-trip (v0.99.68)

- **Date:** 2026-05-25
- **Status:** Accepted
- **Predecessor:** [ADR-20260525-wave302-v0.99.67-phase153-frustum-contains-sphere](./ADR-20260525-wave302-v0.99.67-phase153-frustum-contains-sphere.md)
- **Successor:** ADR Wave-304 (Phase 150 AsyncStreamer demo)
- **Tag:** v0.99.68

## Context

`cd::scene::Serializer` already supported per-entity metadata via the
`serialize_scene_with` / `deserialize_scene_with` template overloads
(Phase 121). `hello_editor` exercised this round-trip but `hello_engine`,
the marathon's mega-showcase, only had a `kind_from_name` helper marked
`[[maybe_unused]]` and no Save/Load palette entries.

## Decision

Add two palette commands to `hello_engine`:

- `80 — Scene: Save` writes `hello_engine.cdscene.json` next to the
  binary, pretty-printed. Per-entity metadata serialized:
  - `name` (string)
  - `kind` (string — Cube / Sphere / Cone / Cylinder / Torus)
  - `tint` (3-float array)
- `81 — Scene: Load (replace world)` destroys the current
  `SceneEntity` list, deserializes the file, repopulates `entities`
  with name/kind/tint pulled back from the JSON, clears the
  `EditHistory` (the old undo entries no longer reference valid
  entities), and resets the selection to entity 0.

The save file format is the same canonical v1 the rest of the engine
uses — `cd::asset_json::parse` for read, `cd::asset_json::serialize`
for write.

## Round-trip guarantees

After Save then Load, every entity in `entities` retains:

- transform (position, rotation, scale) via canonical serializer
- name, primitive kind, tint via `WriteExtras` / `ReadExtras`
- parent linkage via canonical serializer

The original ECS Entity ids are NOT preserved — a fresh world assigns
new slot ids. `IdMap` returned by deserialize maps old → new ids;
hello_engine doesn't use it (no external refs to remap).

## Rejected alternatives

- **Append-load** (deserialize without destroying current entities) —
  would double the entity count each load, useful for "import" but
  confusing as the default "Load" semantic. Save/load round-trip
  expects identity, so we go with replace-world.
- **Hot-reload on file change** — would be nicer in an editor but
  hello_engine is a one-window showcase. The palette command is
  enough.
- **Binary serializer** (cd/scene/BinarySerializer.hpp) — faster but
  harder to debug for a showcase. JSON is the right call for a
  demo file you might want to hand-edit.

## Consequences

- hello_engine now fully exercises both ends of the scene serializer
  template API.
- `hello_engine.cdscene.json` is `.gitignored` already (added when
  hello_editor's round-trip landed).
- The "save/load" pending-integration bullet from the marathon plan
  is closed.

## Open follow-ups

- Wire SceneCameraController state (orbit yaw/pitch, follow target id)
  into the save file so reload restores the full viewport.
- Save/restore audio mute + net-sim enabled flags as ephemeral session
  state — possibly via a separate `hello_engine.session.json`.
