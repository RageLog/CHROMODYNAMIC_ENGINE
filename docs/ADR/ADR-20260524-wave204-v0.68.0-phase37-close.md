## Bağlam

Phase 37, render katmanına klasik draw-call sıralama primitive'i ve
core'a RAII arena scope helper'ı ekler. İkisi de marathon'un başından
beri "olsa iyi olur" listesindeydi.

## Karar

### 37.A — `cd/render/SortKey.hpp`
Christer Ericson'un "Order Your Graphics Draw Calls Around!" (2008)
yaklaşımı: 64-bit paketlenmiş anahtar, tek `std::sort` pass'iyle
opaque-front-to-back + transparent-back-to-front sıralamasını verir.

Bit dağılımı (yüksekten alçağa):
- 2 bit layer (opaque/skybox/transparent/ui)
- 4 bit pass index (layer içinde 16 alt-geçiş)
- 2 bit blend group (off/alpha/additive/premultiplied)
- 24 bit material id (16M material)
- 24 bit depth bits (caller pre-flip yapar)
- 8 bit user disambiguation lo

Toplam = 64 (2+4+2+24+24+8). Tip safe enum class'lar (SortLayer / SortBlend)
ile API kullanım hatası en aza inecek.

### 37.B — `cd/core/ArenaScope.hpp` + `FrameAllocator::rewind(mark)`
FrameAllocator artık `rewind(mark)` API'ye sahip — `used()` snapshot'ını
saklayıp ileride o noktaya sarıp atmaya izin verir.

`ArenaScope` RAII tip: ctor snapshot alır, dtor `rewind` çağırır.
Iç içe `ArenaScope` LIFO pop sırasıyla doğru çalışır (her scope kendi
snapshot'ına sarar). Trivially-destructible payload zorunluluğu
korundu — `reset()` ile aynı kontrat.

## Test

- SortKey: LayerBitsAtTopOrderLayers, MaterialIdRecoverable,
  DepthBitsRecoverable, AscendingSortGroupsByLayerThenMaterialThenDepth — 4 case.
- ArenaScope: RewindsToConstructionMark, NestedScopesPopLifo,
  FrameAllocator::RewindRestoresMark — 3 case.

`ctest --preset ninja-debug` → **58/58 PASS**.

## Reddedilen alternatifler

- **128-bit sort key**: bgfx 64-bit kullanıyor; daha fazla bit
  gerekirse ileride genişletilebilir, ama 64-bit RHI hot-path'lerde
  tek-register karşılaştırma → radix sort uyumlu. 16M material +
  16M depth bin yeterli.
- **`std::unique_ptr<std::byte[]>` üzerine yeni LinearArena yazmak**:
  FrameAllocator zaten o iş — `rewind` ekleyince hâlâ aynı sınıf,
  yeni tip eklemek karışıklık yaratır.
