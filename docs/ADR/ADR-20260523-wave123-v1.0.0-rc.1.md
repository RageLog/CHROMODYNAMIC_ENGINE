# ADR — v1.0.0-rc.1 / Wave 123 — Release candidate cut

- Date: 2026-05-23
- Status: Accepted
- Wave: 123
- Tag: v1.0.0-rc.1

## Context

v0.24.0 landed the install pipeline + downstream `find_package` smoke,
which was the last structural prerequisite for the v1.0 baseline.
Sprint 4's remaining items per the Wave 106 plan were:

1. CHANGELOG cleanup (cosmetic, non-blocking — per-release sections
   are already correctly structured; MD024 duplicate-heading is the
   intentional convention).
2. v1.0.0-rc.1 tag (this wave).
3. CMake package config (shipped in Wave 121).
4. find_package downstream smoke (shipped in Wave 121).
5. v1.0.0 GA after rc.1 soak (next wave).

The release contract is met: the engine builds clean on the four
Windows toolchains and three POSIX runners, all 58 ctest targets are
green, the install tree is `find_package`-consumable, and the
documentation pipeline produces zero warnings.

## Decision

Cut **v1.0.0-rc.1** off `dev` HEAD. Project version bumps 0.24.0 →
1.0.0. The `-rc.1` suffix marks the soak; `release.yml` derives the
GitHub Release `prerelease=true` flag from the suffix automatically,
so the tag does not promote to the latest-release pointer.

### Frozen surfaces (stable since v1.0)

Per the Wave 106 ADR's open question on backward-compat scope:

- `cd::core` — Result, ErrorCode, ErrorFormat, Handle, HandleStore,
  CVar, Version. Frozen ABI within v1.x.
- `cd::diag` — PanicInfo, PanicHandler, CD_ASSERT / CD_VERIFY /
  CD_PANIC. Frozen.
- `cd::log` — ILogger, LogRecord, RingBufferSink, PanicDump bridge.
  Frozen.
- `cd::math` — Vec / Mat / Quat / SIMD primitives. Frozen.
- `cd::mem` — Handle store, allocator primitives. Frozen.
- `cd::time`, `cd::events`, `cd::vfs`, `cd::profile`, `cd::config`,
  `cd::platform`, `cd::plugin`, `cd::bench` — frozen.
- `cd::asset.*` — registry + import surfaces frozen. Internal cooker
  formats (.cdmesh / .cdtex) versioned independently.
- `cd::rhi` — IDevice, ICommandBuffer, IBuffer descriptors frozen.
  Backend implementations (rhi_vulkan/d3d12/metal/native) may still
  evolve in patch releases.
- `cd::ecs`, `cd::scene` — frozen.
- `cd::imgdiff` (FLIP / SSIM / PSNR) — frozen.

### Experimental / may evolve in v1.x

- `cd::rhi_metal` — currently a skeleton (ADR mobile RHI).
- `cd::rhi_d3d12` — minimal subset; missing tier-1 features.
- `cd::editor`, `cd::editor_ui` — early stage; UI layer may shift.
- `cd::script` — Lua binding helpers are still stabilizing.

## Rejected alternatives

- *Skip rc.1 and ship v1.0.0 GA directly.* Rejected: the v1.0 promise
  binds backward-compat on every frozen surface above. A soak window
  exists so downstream consumers can compile against the install tree
  and surface integration bugs before the GA tag commits the promise.
- *Bump to v0.25 first and burn another marathon iteration.* Rejected:
  the install + find_package gate is the last structural item that
  changes anything load-bearing for v1.0. Further v0.x bumps would be
  feature breadth, which Phase 10 explicitly traded away for v1.0
  stability.
- *Ship the experimental surfaces (editor, rhi_metal, rhi_d3d12) as
  v1.0-stable.* Rejected: stable means "will not break". The
  experimental tier graduates in v1.x point releases as it stabilises;
  forcing it into the v1.0 ABI freeze would either pin half-baked APIs
  forever or require a v2.0 break on the first cleanup.

## Consequences

- The `v1.0.0-rc.1` tag triggers `.github/workflows/release.yml`. The
  workflow's `prerelease` flag is derived from the `-rc` suffix, so
  the GitHub Release is published as a pre-release — it shows up
  under "Releases" but the latest-release pointer still points at the
  last GA (currently v0.24.0).
- The next wave is v1.0.0 GA: bump the project version to drop the
  `-rc.1` suffix (CMake doesn't carry pre-release suffixes natively),
  CHANGELOG section flip from "Release candidate" to "GA", tag.
- The soak window between rc.1 and GA is short by design — the
  marathon has been compiling, testing, and find_package-checking
  this surface for the past five sprints; rc.1 is a publish gate, not
  a destabilising re-test.
