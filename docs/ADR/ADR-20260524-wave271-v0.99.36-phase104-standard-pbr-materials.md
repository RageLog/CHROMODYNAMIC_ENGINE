# ADR-20260524 / Wave 271 / v0.99.36 / Phase 104+105 — StandardPbr + AnalyticalSky materials

## Status
Accepted — 2026-05-24

## Context

The hello_pbr v5 sample shipped a Cook-Torrance + GGX + Schlick-Fresnel +
Smith-G fragment shader with analytical-sky split-sum IBL and an ACES
tonemap, plus a fullscreen-triangle skybox using the same 3-band
atmospheric palette. The shader strings lived inside the sample TU.

Marathon Phase 104+105 lifts both into engine-side header-only assets
so any sample / tool can bind the same canonical shaders without
reproducing 200 lines of GLSL.

## Decision

Two new header-only includes under `cd::material`:

1. **`cd/material/StandardPbrMaterial.hpp`**
   - `kStandardPbrVS` / `kStandardPbrFS` — GLSL source strings.
   - `StandardPbrPush` POD (128 B) — matches the push-constant layout
     the shader expects: `mat4 mvp + vec4 albedo + vec4 mr_amb +
     vec4 camera_pos + vec4 light_dir`.
   - The three-light rig (warm key + cool fill + warm back-rim),
     roughness-aware Fresnel ambient (Lazarov 2013), and ACES
     Narkowicz tonemap are baked into the fragment shader.

2. **`cd/material/AnalyticalSkyMaterial.hpp`**
   - `kAnalyticalSkyVS` / `kAnalyticalSkyFS` — GLSL source strings.
   - `AnalyticalSkyPush` POD (64 B) — `cam_right / cam_up / cam_fwd /
     sun_dir` vec4 quartet that the fragment shader uses to
     reconstruct world-space rays per fragment without a matrix
     inverse.
   - Same 3-band palette as `StandardPbrFS::sample_env` so IBL
     reflections from PBR spheres agree with the sky behind them.

`hello_pbr/main.cpp` now consumes both engine headers and the file-
local shader literals are deleted (~228 lines stripped). Behaviour
identical; ~280 fewer lines of duplicated GLSL across the repo
already (hello_skybox + hello_pbr would otherwise each carry their
own copy).

## Rejected alternatives

- **`.glsl` files on disk + runtime load.** Adds a file-IO dependency
  to every consumer; header-only string literals keep the engine
  static-link-friendly and avoid runtime path discovery.
- **Shader hash + cache layer in cd::shader.** Phase 16-17 has a
  compile cache already; not the bottleneck. The duplication problem
  was the original-source ownership, not compile time.
- **Param block (lighting parameters) as a UBO.** Would generalize
  the three-light rig to caller-driven values. Out of scope —
  hello_pbr's key/fill/rim balance is the artist-pleasing default;
  any sample wanting a different lighting setup can fork the shader
  string.

## Consequences

- `cd::material` header set grows from { Material, PbrParams } to
  { Material, PbrParams, StandardPbrMaterial, AnalyticalSkyMaterial }.
- `hello_pbr` becomes a thin demo wiring `cd::material::Material::create`
  to the engine shader sources — the sample now reads more like a
  showcase of how-to-bind-the-engine, not a re-implementation of PBR.
- Future samples / tools that want a "stock PBR sphere" just include
  the header and forward `albedo, metallic, roughness, light_dir` to
  the existing push block.

## Validation

```
cmake --build --preset llvm-win-debug --target cd_sample_hello_pbr
./build/llvm-win-base/bin/Debug/hello_pbr.exe
```

Renders identically to Phase 102 v0.99.34: copper sweep + skybox +
three-light rig + ACES tonemap.
