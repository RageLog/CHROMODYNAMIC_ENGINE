# ADR-20260524 / Wave 278 / v0.99.43 / Phase 113 — AssetRegistry::evict

## Status
Accepted — 2026-05-24

## Context

Phase 43.B introduced `cd::asset::MemoryCache` — an LRU accounting
primitive that tracks `(AssetId, bytes)` and picks victims when
asked. The companion side — actually dropping those victims from
`AssetRegistry::cache_` — was never wired. The marathon pending
list flagged it as "Phase 113: AssetRegistry::evict() consuming
MemoryCache."

`MemoryCache.hpp` also had a latent bug: it called `std::sort`
without including `<algorithm>`. Compiled previously because
transitive includes pulled it in; new TUs that consumed only
`<cd/asset/MemoryCache.hpp>` (this phase's evict test) broke the
chain.

## Decision

1. **`AssetRegistry::evict(MemoryCache&, release_bytes) → std::size_t`**
   - Asks the cache for LRU victims up to `release_bytes` worth.
   - For each victim id: drops it from the registry's `cache_`
     map under the existing unique_lock, then calls
     `memory_cache.forget(id)` to keep the accounting in sync.
   - Returns the number of assets actually evicted (may be less
     than victim count if an id was already removed externally).
   - `release_bytes == 0` short-circuits to a no-op (no walk, no
     touch).

2. **`MemoryCache.hpp` include fix** — added `<algorithm>` and
   `<utility>`.

3. **Two new gtests** (`cd_test_asset`):
   - `AssetRegistryEvict.DropsLruVictimsAndClearsMemoryCache`:
     install 3 text assets, touch them in oldest→newest order,
     evict 1500 bytes (1.5 entries' worth) → expect 2 dropped,
     newest survives, memory cache total drops from 3072 to 1024.
   - `AssetRegistryEvict.ZeroBytesIsNoOp`.

## Rejected alternatives

- **Bake the MemoryCache into AssetRegistry as a member.** Would
  couple every registry user to the cache primitive. The
  decoupled callsite lets gameplay/streamer code maintain the
  cache (knowing texture VRAM, mesh vertex bytes, audio sample
  count) while the registry stays storage-only.
- **Add `IAsset::byte_size() = 0`** so the registry could touch
  the cache itself. Adds a virtual every existing loader must
  override; pure overhead for the eviction-aware minority.
- **Hold the registry mutex across the entire eviction loop.**
  Was the obvious first draft but blocks `find()` for the whole
  walk; the smaller per-id critical section keeps concurrent
  readers unblocked.

## Consequences

- `AssetRegistry` gains one public method (`evict`); existing
  callers untouched.
- `MemoryCache.hpp` is now self-sufficient — no more transitive
  `<algorithm>` reliance.
- Future async streamer phase (Phase 114 candidate) can call
  `evict()` from its worker thread under its own scheduling.

## Validation

```
cmake --build --preset llvm-win-debug --target cd_test_asset
./build/llvm-win-base/bin/Debug/cd_test_asset.exe \
    --gtest_filter=AssetRegistryEvict.*:MemoryCache.*
```

6 / 6 tests pass (4 existing MemoryCache + 2 new AssetRegistryEvict).
