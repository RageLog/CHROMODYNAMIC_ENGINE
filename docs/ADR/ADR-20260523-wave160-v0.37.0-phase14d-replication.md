# ADR — v0.37.0 / Wave 160 — Phase 14.D reliable channel + replication

- Date: 2026-05-23
- Status: Accepted
- Wave: 160
- Tag: v0.37.0
- Predecessor: ADR-20260523-wave159 (v0.36.0 D3D12 PSO + triangle),
  plus the v0.36.1 sRGB polish patch.
- Phase 14 master: ADR-20260523-wave156-phase14-plan.md

## Context

Phase 14.D scope per the wave156 plan: a reliable-ordered channel
+ a toy replication test that proves it.

Codebase audit at sub-phase start: the cd::net library already
ships the reliable primitives in full — `cd::net::ChannelMux`
(kReliableOrdered + kUnreliableUnordered), `cd::net::ReliableChannel`
(RFC-6298 adaptive RTO + cum-ACK + SACK + AIMD), and a
`cd::net::make_loopback_pair()` in-process transport. The primitive
gap is closed; the missing piece is the *consumer* that proves the
shape composes for "ECS state replication" — the marathon-shippable
demo that connects the dots.

## Decision

Tag **v0.37.0**. Scope: a `samples/hello_replication` that wires
two `cd::ecs::World` instances together through a loopback
ChannelMux and replicates scene state end-to-end.

### What landed

- **`samples/hello_replication`** (headless, cross-platform):
  - Builds a loopback IConnection pair, mounts ChannelMux on
    each end.
  - Source World: 3 entities (`root`, `child` parented to root,
    `sibling`) with distinct LocalTransforms.
  - **Snapshot 1**: source serializes via
    `cd::scene::serialize_scene_binary` → sends on a kReliableOrdered
    channel → destination receives → fresh World+Scene →
    `deserialize_scene_binary`. Destination ends with 3 entities.
  - **Mutate source**: translate `child` by +4 on X, scale
    `sibling` to 2.0 component-wise.
  - **Snapshot 2**: same push/apply cycle. Destination diffs
    re-converge.
  - **Verify**: destination iterates `for_each_node`, asserts
    3 entities exist, the translated child reaches X=5, the
    scaled sibling reaches scale=2.0. Process exits 0 on all
    invariants holding; non-zero with a diagnostic on any
    mismatch.
- The sample is *cross-platform* — no `if(WIN32)` guard in
  samples/CMakeLists.txt — because the loopback transport
  doesn't touch the OS socket layer.

### What deliberately did NOT land

- **Cross-process replication.** Loopback is a pair of in-process
  endpoints. The real network path is via UdpConnection (already
  in cd::net); plumbing a sample that opens two processes and
  binds two ports is its own integration story (CI test
  orchestration, port collision handling). Deferred.
- **Diff-based delta sync.** The sample re-builds the destination
  World on every snapshot. A real replication system would
  ship a per-entity delta (just the components that changed).
  The marathon-shippable demo takes the simpler snapshot route
  because the *channel* layer is what Phase 14.D was meant to
  prove, not a replication algorithm.
- **Time-stepped replication.** No tick rate, no interpolation.
  Two explicit pushes (initial + mutated) is enough to
  demonstrate the loop end-to-end without inviting timing
  questions that belong in a future
  netcode-architecture wave.
- **Use of ReliableChannel directly.** The sample uses
  ChannelMux's kReliableOrdered (which dedupes + reorders
  internally). Loopback has no packet loss so the
  RTO/ACK/SACK machinery in ReliableChannel adds nothing
  observable here. The ReliableChannel + UDP path is
  exercised by `cd_test_net` (Wave 41-66 tests) which
  already cover the reliable semantics rigorously.

## Rejected alternatives

- *Skip the sample and rely on cd_test_net.* Rejected: a test
  binary that asserts "ReliableChannel passes 1M frames" doesn't
  show consumers how to actually wire it into game state. The
  sample is the documentation; the test is the regression net.
  Both belong.
- *Use cd::asset_json (text) instead of BinarySerializer.*
  Rejected: the binary format already ships in
  `cd::scene::BinarySerializer` and the wire is bytes anyway —
  text would just double the size for no benefit.
- *Spawn two threads + share state via mutex instead of via a
  channel.* Rejected: the entire point of Phase 14.D is to
  demonstrate the *channel* surface composes for replication.
  Threads + mutex would prove nothing about cd::net.

## Consequences

- v0.37.0 is the new latest SemVer marker.
- cd::net is now the third subsystem (after D3D12 backend and
  editor primitives) with a sample-driven proof that the public
  surface composes.
- Phase 14.E (editor 3D viewport + dock-layout preset →
  v0.38.0) opens next.
