# ADR — v0.38.0 / Wave 161 — Phase 14.E editor 3D viewport

- Date: 2026-05-23
- Status: Accepted
- Wave: 161
- Tag: v0.38.0
- Predecessor: ADR-20260523-wave160 (v0.37.0 replication)
- Phase 14 master: ADR-20260523-wave156-phase14-plan.md

## Context

Phase 14.E per the wave156 plan: editor 3D viewport + dock-layout
preset. After v0.35.1 the editor had panels (Scene / Inspector /
Toolbar / History) but no 3D scene rendering — the background was
just the clear color. The user observation
("hicbir item arkaplanda gozukuyor") confirmed the missing
viewport was the most visible gap.

## Decision

Tag **v0.38.0**. Scope: render the editor's World entities as
tinted cubes inside the editor window, behind the ImGui overlay.
The auto-orbiting camera matches the "first-look 3D" use case
without input plumbing.

### What landed

- **Cube geometry + material** declared at sample scope:
  - 8-vertex 12-triangle cube via `CubeVertex { pos[3]; color[3] }`.
  - GLSL VS + FS that take a push-constant `mat4 mvp + vec4 tint`
    so per-entity color is multiplied into the cube's vertex
    colors.
  - `cd::material::Material::create` builds the PSO with
    depth-test on, back-face cull, kD32Float depth target.
- **Per-entity tinting + initial layout** — the 3 spawned
  entities now have distinct tints (Cube=red, Sphere=green,
  Cone=blue) and starting positions (-1.6 / 0 / +1.6 on X)
  so they don't overlap.
- **Depth target** — kD32Float texture + view, rebuilt on
  resize alongside the swapchain.
- **Auto-orbit camera** — `std::chrono::steady_clock`-driven
  eye position at radius 5, ~50° vertical FOV, look-at the
  origin. Camera stays alive without WASD plumbing.
- **Render order per frame** now:
  1. begin_frame, begin_render_pass(color + depth, both
     LoadOp::kClear)
  2. set_viewport / set_scissor
  3. bind cube PSO + cube_vb + cube_ib
  4. for each entity: build MVP = proj·view·`to_mat4(LocalTransform)`,
     push_constants(MVP + tint), draw_indexed(36)
  5. ImGui new_frame + 4 panels (unchanged from v0.35.1 layout)
  6. ctx.render(cmd)
  7. end_render_pass, end_frame
- **Resize handling** extended to rebuild the depth target.
- **Sample CMakeLists** dependency list extended with
  `cd::material` and `cd::shader` (the glslang-backed material
  builder).

### What deliberately did NOT land

- **Free-fly WASD / mouse-look camera.** The auto-orbit is the
  marathon-shippable cut; input plumbing through cd::input +
  the platform window's mouse-look surface is its own wave.
- **Distinct primitive meshes (cube/sphere/cone).** Every
  entity renders as a *tinted cube* — the "cube" / "sphere" /
  "cone" names in the Scene tree are labels, not geometry
  selectors. Mesh dispatch on entity is a follow-up that wants
  an `cd::scene::MeshComponent` plus a tiny primitive mesh
  library; out of scope for v0.38.0.
- **Dock-layout preset via ImGui::DockSpace.** The v0.35.1
  hard-pinned panel positions already produce a deterministic
  layout; ImGui's docking API would add the *ability* to drag
  panels into docks but the default arrangement would be the
  same as today. The polish is real but small; deferred.
- **Golden-image baseline for the viewport.** Capturing a
  reference PNG requires deterministic frame timing (the
  auto-orbit is wall-clock driven); deferred until either
  the camera switches to frame-counter driven OR the golden
  harness supports a "first-frame-only" capture mode.

## Rejected alternatives

- *Offscreen render → ImGui::Image into a Viewport panel.*
  Rejected: requires a separate offscreen render target +
  binding it to ImGui as a texture descriptor, a fair amount
  of glue. The behind-the-overlay approach gets us a visible
  3D scene with one-tenth the surface and matches what every
  game engine's "Game" view does (3D fills the viewport, UI
  overlays).
- *Use cd::render::Renderer's higher-level primitives.* The
  Renderer's frame primitives already drive begin_frame /
  end_frame; the per-frame mesh-draw loop sits naturally as
  user-side code (matches what hello_cube does). Adding a
  scene-graph drawer to the Renderer is out of scope.
- *Draw entities as distinct meshes.* Bigger surface — needs
  a primitive mesh library + per-entity mesh component +
  asset registry. Cube-as-everything is the marathon
  compromise; the *labels* in the scene tree communicate the
  intent even if the geometry doesn't.

## Consequences

- v0.38.0 is the new latest SemVer marker.
- hello_editor now has a real 3D viewport showing the live
  effect of Inspector edits — translate / scale / rotate
  changes are visible on the rendered cube.
- Phase 14.F (audio DSP graph polish → v0.39.0) opens next.
