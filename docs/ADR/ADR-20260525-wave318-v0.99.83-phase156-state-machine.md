# ADR Wave-318 — Phase 156 AnimStateMachine on top of PoseBlend (v0.99.83)

- **Date:** 2026-05-25

- **Successor:** ADR Wave-319 (next reclaim)
- **Tag:** v0.99.83

## Context

Wave 317 shipped pose blending primitives. The natural completion is
a **state machine** that drives those blends from per-frame input —
the standard pattern every character controller follows
(production animator, production AnimBP, Bevy bevy_animation_graph).

This phase closes the character-animation loop infrastructure:
sample → blend → state-machine.

## Decision

New header `cd/anim/StateMachine.hpp` (header-only):

```cpp
struct AnimState
{
    std::string  name;
    const SkinnedClip* clip { nullptr };
    bool         looping { true };
    float        speed { 1.0F };
    float        time { 0.0F };
};

using TransitionPredicate = std::function<bool(
    const std::unordered_map<std::string, float>& blackboard,
    float elapsed_in_state)>;

struct AnimTransition
{
    std::string         from;
    std::string         to;
    TransitionPredicate condition;
    float               blend_duration { 0.15F };
};

class AnimStateMachine
{
public:
    bool add_state(AnimState);
    bool add_transition(AnimTransition);
    bool set_initial_state(string_view);
    void set(string_view key, float value);
    float get(string_view key, float fallback = 0.0F) const;
    void tick(float dt, const Skeleton&);
    const Pose& current_pose() const noexcept;
    string_view current_state() const noexcept;
    bool is_blending() const noexcept;
};
```

### Per-tick semantics

1. Increment `elapsed_in_state_` by `dt`.
2. If not already blending, walk the transitions list; first
   matching predicate fires:
   - Snapshot the current pose as `blend_from_pose_`.
   - Switch `current_` to the target state.
   - Reset `blend_time_` + start blending.
3. Advance the (possibly newly-current) state's clip clock + sample
   into a temp `new_pose`.
4. If blending: blend `blend_from_pose_` → `new_pose` by
   `blend_time_ / blend_duration_`. Finish + drop the from-pose
   when the weight hits 1.0.
5. Otherwise: `current_pose_ = new_pose`.

### Blackboard

A flat `unordered_map<string, float>`. Stringly-typed by design —
matches the production animator parameter table and lets transition
predicates be tiny lambdas:

```cpp
sm.add_transition({
    "idle", "walk",
    [](const auto& bb, float) { return bb.at("speed") > 1.0F; },
    0.15F
});
```

## Rejected alternatives

- **Templated blackboard with strong-typed keys** — more compile-
  time safety but pushes ceremony onto every caller; loses the
  "just look up a string" ergonomic the production / production user base
  expects.
- **Embedded scripting (Lua/AngelScript) for predicates** — out
  of scope; the engine has no scripting layer yet. C++ lambdas
  are fine for v1.1.
- **Multi-source blends (1D + 2D blend trees)** — productionizing
  this further (BlendSpace2D for walk + run + sprint based on
  velocity) is a follow-up phase. The current FSM covers the
  bread-and-butter idle ↔ walk transitions.
- **DAG over multiple active states (graph layering)** — same
  reasoning; the current single-blend model handles 90% of
  game-character cases.

## Consequences

- Character animation pipeline is now CPU-complete: sample +
  blend + state-machine + skinning-matrix upload.
- GPU-side skinning vertex shader path + skinned glTF importer
  remain v1.2+.

## Open follow-ups

- 1D / 2D BlendSpace for parametric motion (walk-run-sprint
  weighted by velocity).
- Crossfade transitions with arbitrary curve shapes (currently
  linear).
- `AnimEvent` markers fired at specific clip times (footstep
  sounds, hit-frame triggers).
