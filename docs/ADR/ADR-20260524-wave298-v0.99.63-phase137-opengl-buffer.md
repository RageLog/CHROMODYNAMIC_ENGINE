# ADR-20260524 / Wave 298 / v0.99.63 / Phase 137 — OpenGL DSA buffer path

## Status
Accepted — 2026-05-24 (buffer only; texture + swapchain still
stubbed)

## Context

The OpenGL backend has been boot-only since Phase 18.B (v0.49.0).
`create_buffer / create_texture / create_swapchain` all return
`kNotImplemented`. The blocker is **GL function loading**:
`opengl32.lib` only exports the GL 1.1 ABI; anything past that
(buffer objects, DSA, framebuffers, shader pipelines) has to come
via `wglGetProcAddress`.

A full GL loader (glad / glew / volk-equivalent) is multi-day
work — the marathon-shippable slice for one phase is just the
DSA buffer entry points + `create_buffer`. Texture, swapchain,
and pipeline paths continue to return `kNotImplemented` with a
clear "this loader-tax slice landed; that one didn't" message.

## Decision

Inline a tiny WGL loader for the four DSA buffer entry points:

- `glCreateBuffers(GLsizei, GLuint*)`
- `glDeleteBuffers(GLsizei, const GLuint*)`
- `glNamedBufferStorage(GLuint, GLsizeiptr, const void*, GLbitfield)`
- `glNamedBufferSubData(GLuint, GLsizeiptr, GLsizeiptr, const void*)`
- Plus `glGetError` for diagnostics.

`load_dsa_buffer_funcs()` calls `wglGetProcAddress` for each name
and stuffs the result in a `GLLoader` POD. Returned pointers are
sanity-checked against the documented junk values
(`{1, 2, 3, -1}`) that some Windows GL drivers return on failure.

`OpenGLDevice::initialize` invokes the loader once after
`wglMakeCurrent` succeeds. `gl_.valid()` guards every consumer
(currently just `create_buffer`).

`create_buffer` mirrors the Vulkan VMA path's semantic:

- Host-visible buffers (`MemoryUsage::kCpuToGpu` /
  `kGpuToCpu`) get `GL_DYNAMIC_STORAGE_BIT | MAP_READ | MAP_WRITE`
  storage flags.
- GPU-only buffers get no host-mapping bits (immutable storage).
- Empty `size == 0` rejected with `kInvalidArgument`.
- Failures rollback via `glDeleteBuffers`.

`destroy_buffer` looks up the engine handle in a per-device
`std::unordered_map<id, GLBuffer>` map, calls `glDeleteBuffers`,
and drops the record.

## Rejected alternatives

- **Pull in glad / glew / volk.** Adds an external dependency +
  CMake plumbing. The inline-load approach is one struct + one
  function for the four buffer entry points; trivially extensible
  one phase at a time.
- **Wait for the full loader before shipping anything.** Multi-
  day cost; meanwhile no D3D12-style "you can at least allocate
  a GPU buffer on GL" path exists.
- **Use legacy non-DSA GL 1.5 `glGenBuffers` / `glBindBuffer` /
  `glBufferData`.** Smaller LOC but bind-driven mutation state
  conflicts with the engine's stateless allocation model. DSA
  is the right modern target.

## Consequences

- OpenGL `kNotImplemented` count: ~30 → ~29 (just `create_buffer`
  + `destroy_buffer` landed).
- Engine consumers can allocate GPU buffers on OpenGL (read /
  write via DSA in subsequent phases).
- `upload_buffer` still kNotImplemented (separate function on
  IDevice; needs `glNamedBufferSubData` + a `host_visible` flag
  in the record — Phase 138 candidate).
- Texture, swapchain, shader, pipeline paths: still
  kNotImplemented but the loader pattern is now established —
  each phase brings in its own slice of `wglGetProcAddress`
  bindings.

## Validation

```
cmake --build --preset llvm-win-debug
```

Full engine + 33 samples + tools build green (343/343 — the
hello_rt sample joined). OpenGL buffer-only consumers can
exercise `create_buffer` + `destroy_buffer` end-to-end on a
GL 4.4+ adapter; the `gl_.valid()` guard returns
`kNotImplemented` on older drivers.
