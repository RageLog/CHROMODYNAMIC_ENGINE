# ADR — v0.30.0 / Wave 152 — Phase 13.A reviewer blockers closed

- Date: 2026-05-23
- Status: Accepted
- Wave: 152
- Tag: v0.30.0
- Predecessor: ADR-20260523-wave150 (v0.29.0 RT/mesh detection)
- Phase 13 master: ADR-20260523-wave151-phase13-plan.md

## Context

The Wave 142 independent review surfaced five blocking items
(B1-B5) that Phase 12 deliberately deferred because they were
concrete, AI-actionable, and cheaper to fix in one focused pass
than to schedule inside Phase 12's per-sub-phase scope. Phase 13.A
(per the wave151 plan) is that focused pass.

Reviewer report:
`docs/REVIEW-independent-auditor-20260523.md`.

## Decision

Tag **v0.30.0**. Scope: all five reviewer blockers closed.

### B1 — LIBRARIES.md materially incorrect

- **Was:** doc claimed 48 libraries and named `cd::serialization` as
  a foundation library. The library does not exist on disk; the
  actual `cd_add_library()` count is 55.
- **Now:** doc rewritten to 7-group topology (foundation 15, asset
  10, render 16, world 7, ui 3, runtime 1, cross-cutting 2) totalling
  54 public-API libraries + 1 internal vendored Lua build = 55 CMake
  targets. Every new library from v0.18.0+ (rhi_d3d12, rhi_metal,
  rhi_native, cluster, cluster_gpu, cluster_pbr, ibl, volumetric,
  async_submit, asset_pak, imgdiff, script) is enumerated.
- **Companion changes:** Readme.md tier summary + engine/CMakeLists.txt
  header comment also cleaned. Historical PLAN.md / DESIGN.md /
  pre-v0.30 ADRs intentionally left unchanged — they are dated
  snapshots of Phase-1 design freeze and rewriting them would distort
  the historical record.

### B2 — `Engine/` vs `engine/` case-sensitivity landmine

- **Was:** git index stored 408 paths under `Engine/` (capital E);
  every source-tree reference (`add_subdirectory(engine)`, every
  CMakeLists target_include_directories, every doc) used lowercase
  `engine/`. Windows masked the discrepancy via case-insensitive
  filesystem lookups; a fresh Linux clone would fail at
  `add_subdirectory(engine)` because `./engine` did not exist.
- **Now:** two-step Windows-safe git rename `Engine/` →
  `Engine_tmp_rename/` → `engine/` (commits 3ca344f + 9f73e50).
  Doc prose normalized in a third commit (c3fcab8) across
  ARCHITECTURE.md (3), CONSUMING.md (2), REVIEW_BRIEF.md (25),
  three Phase-12 ADRs (6), CLAUDE.md, research/README.md, and one
  comment in `engine/foundation/core/include/cd/core/Version.hpp`.
- **Audit:** `git ls-files | grep -c '^Engine/'` returns 0;
  `grep -rn 'Engine/' docs/` returns matches only inside two docs
  that *describe* the bug (the wave151 plan ADR and the
  independent-auditor review itself).

### B3 — Vulkan debug-label stack-buffer dangling pointer

- **Was:** `VulkanCommandBuffer::push_debug_group` wrote into a
  128-byte stack `char buf[128]` and passed its address to
  `vkCmdBeginDebugUtilsLabelEXT`. The Vulkan spec permits the driver
  to read `VkDebugUtilsLabelEXT::pLabelName` up until command-buffer
  execution finishes — long after the function returns. Most desktop
  drivers happen to copy on the call so the bug never fires; strict
  validation layers and certain Intel/AMD paths flag the dangling
  read.
- **Now:** each VulkanCommandBuffer owns a
  `std::deque<std::string> debug_label_arena_`. push_debug_group
  emplaces the string_view into the deque (stable pointers across
  emplace_back, unlike std::vector) and passes `c_str()` into
  Vulkan; storage outlives GPU-side consumption. `begin()` clears
  the arena to recycle space across frames.
- **Documented:** `ICommandBuffer::push_debug_group` interface now
  explicitly says the `name` argument only needs to outlive the
  call; the backend is required to copy into per-CB storage. Every
  future backend (D3D12 PIX, Metal pushDebugGroup:) inherits the
  same contract.

### B4 — CMake `SameMajorVersion` policy for 0.x line

- **Was:** `write_basic_package_version_file(... COMPATIBILITY
  SameMajorVersion)` in `cmake/CDInstall.cmake`. Treats every 0.y.z
  as interchangeable (all share major=0) — so a downstream
  `find_package(CHROMODYNAMIC 0.25 REQUIRED)` silently accepts a
  0.30.0 install tree even though SemVer 2 lets anything break
  across 0.x minors.
- **Now:** one-line conditional driven by `PROJECT_VERSION_MAJOR`:
  major == 0 → `SameMinorVersion` (honest for 0.x); major >= 1 →
  `SameMajorVersion` (correct for stable line). Auto-flips at the
  v1.0 tag, no future code change required.
- **Verified:** regenerated `CHROMODYNAMICConfigVersion.cmake` now
  carries the SameMinorVersion compatibility template.

### B5 — `catch(...)` rule vs practice

- **Was:** `ARCHITECTURE.md` §3.1 said verbatim "`catch(...) {}` is
  forbidden". Six foundation sites use the construct: four
  (JobGraph, ThreadPool, WorkStealingThreadPool, ILogger) attach an
  observable counter or recovery log call; two (CsvSink,
  ChromeTraceSink) had completely empty bodies — the actual
  intent-violating case.
- **Now:** three-part fix.
  1. ARCHITECTURE.md §3.1 rewritten: "Empty `catch(...) {}` is
     forbidden. `catch(...)` is permitted only when it observably
     records or routes the failure AND the file is enumerated in
     `docs/EXCEPTION_BOUNDARIES.md`."
  2. New `docs/EXCEPTION_BOUNDARIES.md` enumerates all six
     boundaries with file, observable action, and justification. A
     planned CI grep audit (Phase 13.B-side) will fail if a new
     `catch(...)` appears without a same-commit doc entry.
  3. CsvSink and ChromeTraceSink each gain a
     `std::atomic<std::uint64_t> failed_writes_` counter and a
     `failed_writes()` accessor so downstream code can detect a
     dropped sample stream / incomplete trace before treating the
     output as complete.

## Rejected alternatives

- *Add `cd::serialization` as a real library to satisfy B1.* Rejected:
  binary-serialization needs are already met inline by
  `cd::asset_cdmesh`, `cd::asset_cdtex`, and `cd::asset_pak`.
  Manufacturing a thin shared library to retroactively justify the
  doc would add a permanent maintenance surface for a phantom need.
- *Rewrite history (PLAN.md, DESIGN.md, older ADRs) for B2.*
  Rejected: those docs are dated Phase-1 design-freeze snapshots.
  Distorting historical intent records to retroactively match
  current naming is the opposite of the rollback-honesty the
  project commits to.
- *Skip B3 documentation; only fix the implementation.* Rejected:
  the reviewer explicitly flagged the missing contract on
  `ICommandBuffer::push_debug_group`. A future backend author
  (D3D12 PIX, Metal pushDebugGroup:) without the contract would
  re-introduce the same dangling-pointer pattern in their backend.
- *Make B5 a code-only fix by removing the six catches.* Rejected:
  removing the catches would either propagate exceptions out of a
  `noexcept` worker (immediate `std::terminate`) or out of an
  `ISink::submit` contractually-noexcept call. The intent of the
  catches is sound; the doc was the disagreement.

## Consequences

- v0.30.0 is the new latest SemVer marker.
- Phase 13.A closed. Phase 13.B (Linux lavapipe goldens → v0.31.0)
  opens next.
- The CHROMODYNAMICConfigVersion policy is now SameMinorVersion;
  any external consumer that pinned `find_package(CHROMODYNAMIC
  0.29 REQUIRED)` and relied on accidental 0.30-compat must
  re-pin to 0.30.
- The Engine/ → engine/ git rename touches 408 paths; downstream
  forks that branched before commit 9f73e50 will encounter a
  mass-rename merge conflict. The two-step (Engine →
  Engine_tmp_rename → engine) is the standard Windows-safe pivot,
  not avoidable.
