# ADR-20260524 / Wave 292 / v0.99.57 / Phase 130 — AccelRecord build-info

## Status
Accepted — 2026-05-24

## Context

`vkCmdBuildAccelerationStructuresKHR` needs the same geometry +
primitive-count list that `create_acceleration_structure` saw in
`AccelStructureDesc`. The current `AccelRecord` only retains the
AS object + storage buffer + scratch size — at build time the
caller would have to re-pass everything.

`ICommandBuffer::build_acceleration_structure(AccelStructureHandle)`
takes only the handle, so the record must own enough to rebuild
the `VkAccelerationStructureGeometryKHR` list.

## Decision

Extend `AccelRecord` with two `std::vector` fields and deep-copy
on create:

- BLAS: `triangles = desc.triangles` (`AccelTriangleGeometry`
  copies are POD-ish — just buffer handles + offsets + counts).
- TLAS: `instances = desc.instances` (`AccelInstance` is 64 B
  POD).

The actual `vkCmdBuildAccelerationStructuresKHR` call still lives
in the future Phase 131; this commit only carries the data so
Phase 131 doesn't have to re-touch `create_acceleration_structure`.

## Rejected alternatives

- **Store the raw VkAccelerationStructureGeometryKHR list at
  create time.** Saves a rebuild at build time but freezes the
  Vulkan struct shape; the engine-side cd::rhi structs are the
  long-lived source of truth.
- **Pass geometries to the build call instead.** Changes the
  cross-backend `ICommandBuffer::build_acceleration_structure`
  signature.

## Consequences

- `AccelRecord` grows by ~32 B (two empty vectors) plus per-
  geometry storage when used. Acceptable — typical scenes have
  tens to hundreds of geometries, not millions.
- Phase 131 (Vulkan cmd-buffer AS build) is now a pure-additive
  override on `VulkanCommandBuffer` — no further device-side
  refactor needed.
- Caller's `AccelStructureDesc` spans can safely go out of
  scope immediately after `create_acceleration_structure` returns.

## Validation

```
cmake --build --preset llvm-win-debug --target cd_rhi_vulkan
```

Vulkan static lib builds clean. No behaviour change yet — the
new vectors are populated but unused.
