# ADR Wave-304 — Phase 150 AsyncStreamer demo in hello_engine (v0.99.69)

- **Date:** 2026-05-25
- **Status:** Accepted
- **Predecessor:** [ADR-20260525-wave303-v0.99.68-phase154-hello-engine-save-load](./ADR-20260525-wave303-v0.99.68-phase154-hello-engine-save-load.md)
- **Successor:** ADR Wave-305 (Phase 140 kAccelerationStructure descriptor)
- **Tag:** v0.99.69

## Context

`cd::asset::AsyncStreamer` (Phase 114) wraps the Phase 45.B
`StreamQueue` with a worker thread, but no engine sample exercised it.
The MARATHON_SUMMARY "Outstanding integration" list called this out
explicitly:

> Real async streamer consuming StreamQueue

`hello_engine` is the marathon's mega-showcase — the natural place to
demonstrate that the streamer can drive pending → in-flight →
complete / failed state transitions visibly.

## Decision

Add a new ImGui-docked panel "Streamer" to `hello_engine` plus two
palette commands.

The streamer is constructed at boot with a load function that
**simulates** work via `std::this_thread::sleep_for(120-440 ms)` based
on the AssetId — deterministic and seedable per id, so the panel
animates smoothly without going async-flaky. ~6% of ids fail to
exercise `kFailed` transitions.

Panel contents:

- worker state (RUNNING/STOPPED) + pending queue depth
- counters for completed + failed (atomic ints driven from worker thread)
- "Enqueue (low prio)" / "Enqueue (high prio)" / "Enqueue 8 burst" buttons
- recent-tracked id list with state-colored labels
  (gray=PENDING, yellow=INFLIGHT, green=COMPLETE, red=FAILED)

Palette commands:

- `90 — Streamer: Enqueue 8 burst`
- `91 — Streamer: Enqueue 32 burst`

Shutdown path: `streamer.stop()` joins the worker after
`renderer.wait_idle()` so no in-flight callback escapes the program.

## Rejected alternatives

- **Drive real VFS loads** — would need on-disk fixture data + the
  not-yet-existent AssetRegistry::load wiring. The simulated sleep
  model is enough to **demonstrate the streamer**; integrating real
  loads is Phase 156+ territory.
- **Block UI on enqueue** — every enqueue is non-blocking by design;
  the panel shows the state machine, not the contents of loaded
  assets.
- **No tracking list** — would have made the panel less informative;
  the 32-element ring keeps the visual but caps memory.

## Consequences

- Marathon "Outstanding integration" list down one more bullet.
- `cd_audio` + `cd_net` + `cd_asset` AsyncStreamer all now have
  visible end-to-end exercise in the mega-showcase.
- The worker-thread join on exit means the sample exits cleanly even
  when the user closes mid-burst.

## Open follow-ups

- Wire the streamer's load function into `AssetRegistry::load` once
  that path exists — `hello_engine` would then become a real-world
  asset stress test rather than a state-machine demo.
- A `StreamGraph` (multi-streamer fanout) might be worth exploring for
  asset-dependency loading — out of scope for this phase.
