## Phase 15.F — Mobile platform window stubs

`engine/foundation/platform/src/AndroidWindow.cpp` (gated by
`__ANDROID__`) and `IosWindow.mm` (gated by `__APPLE__ &&
TARGET_OS_IPHONE`) compile under the Android NDK / Xcode iOS
toolchains and return `kNotImplemented` with an honest message that
mobile apps own the ANativeWindow*/UIView* lifecycle and bypass the
engine's `create_window` factory.

`PlatformStub.cpp` guard extended to exclude `__ANDROID__` so the
Android TU is the active one on that platform.

Runtime mobile validation still queued — same v1.0 rollback honesty
principle that gated Phase 14.H.

## Phase 15 close — interactive polish

Editor (`hello_editor`) fixes that rode v0.46.0:

- **WM_CHAR routing** — added `OSEventKind::kTextChar` with a
  `code_point` field. Win32 `WindowProc` translates `WM_CHAR` →
  `kTextChar`. `cd::imgui::Context::handle_event` routes →
  `io.AddInputCharacter`. InputFloat / InputText widgets now
  accept typed numbers (was silently broken since the cd::platform
  IWindow surface shipped).
- **WASD camera gate** — narrowed from
  `WantCaptureKeyboard || WantTextInput` to `WantTextInput` only.
  WantCaptureKeyboard stays true after any window gets focus,
  which was blocking WASD entirely.
- **Yaw direction fix** — `yaw += drag.x * sens` (was `-=`).
  Drag right → camera looks right (FPS / production / UE convention).
- **Inspector rotation = Euler XYZ degrees** instead of raw quat
  xyzw. Backend EditHistory still stores `cd::math::Quatf`; the
  Inspector converts via ZYX intrinsic composition.
- **InputFloat3 array storage** — separate static `dx, dy, dz`
  weren't C++-standard contiguous; replaced with `static float
  trans[3]` / `scale[3]` / `euler_deg[3]`.
