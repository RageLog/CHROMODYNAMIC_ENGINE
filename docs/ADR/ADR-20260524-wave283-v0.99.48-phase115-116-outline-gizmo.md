# ADR-20260524 / Wave 283 / v0.99.48 / Phase 115+116 — SelectionOutline + AxisGizmo

## Status
Accepted — 2026-05-24

## Context

Editor UX phases on the pending list:

- **Phase 115 — selection outline.** Renderer needs a "this entity is
  selected" upstream state (one shared state ≠ three duplicated
  copies across stencil-outline / wireframe / jump-flood passes).
- **Phase 116 — axis-translation gizmo.** Editor needs hover + drag
  state for X / Y / Z arrows so multiple frontends (ImGui-based,
  3D-overlay-based) share the same logic.

Both are pure state primitives: shape contracts the renderer +
sample code can fan out from. The actual outline pass shaders +
gizmo geometry land in follow-up phases.

## Decision

### `cd/editor/SelectionOutline.hpp`

- `OutlineStyle { kNone, kWireframe, kStencilEdge, kJumpFlood }`.
- `SelectionOutline` keeps a `std::vector<Entity>` of selected
  entities plus visual params (`color`, `thickness`, `opacity`).
- API: `set(entity)`, `add(entity)`, `remove(entity)`, `clear()`,
  `contains(e)`, `entities()`, `size()`, `empty()`.
- `clamp_params()` keeps slider-driven values inside reasonable
  ranges.

### `cd/editor/AxisGizmo.hpp`

- `GizmoAxis { kNone, kX, kY, kZ }`.
- `AxisGizmo` tracks target world position, hover axis, active
  drag axis, drag-origin pick point, and a snapshot of target at
  drag start.
- API: `set_target`, `set_hover`, `begin_drag`, `update_drag`,
  `end_drag` (returns total delta for `TranslateCommand` push).
- `axis_dir(a)` / `axis_color(a)` helpers for renderer-side
  geometry + inspector-side hover indicators.

## Rejected alternatives

- **`std::unordered_set<Entity>` for selection.** Vector iteration
  is faster at the typical < 16-selection sizes; ordered list
  also stabilizes the "first selected" anchor for multi-select
  transform operations.
- **Quaternion-based rotation gizmo bundled now.** Out of scope —
  Phase 116 ships translation only; rotation gizmo can reuse the
  same state-machine shape later.
- **Plane-projection drag math inside the gizmo.** Pushes
  camera-aware ray geometry into the editor library. Caller has
  the camera; passing in the world-space mouse-on-axis hit point
  keeps this header math-only.

## Consequences

- `cd::editor` gains two header-only primitives. No link-line
  changes; cd::editor library re-link verified.
- hello_editor sample wire-up: Phase 121-style polish pass can
  swap the inline "selected = ..." int with a `SelectionOutline`
  instance + spawn an `AxisGizmo` whenever a single entity is
  selected.

## Validation

```
cmake --build --preset llvm-win-debug --target cd_editor
```

Compiles clean (the two headers are include-only; cd::editor static
lib re-links unchanged).
