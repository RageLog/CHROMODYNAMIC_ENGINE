# ADR — v0.27.0 / Wave 148 — Phase 12.B D3D12 backend boot

- Date: 2026-05-23
- Status: Accepted
- Wave: 148
- Tag: v0.27.0
- Predecessor: ADR-20260523-wave147 (v0.26.0 Phase 12.A perf close)

## Context

Phase 12.B (per ADR-wave142) is "D3D12 backend completion → v0.27.0".
The IDevice surface has 51 pure-virtual methods + the ICommandBuffer
surface has 15 more. A full D3D12 implementation in a single
autonomous wave with no human pixel-checker carries unacceptable bug
risk: subtle barrier mistakes, descriptor-heap allocation off-by-ones,
root-signature mismatch are exactly the class of D3D12 bug nobody
notices until a real frame draws and looks wrong.

## Decision

Scope down v0.27.0 to a **boot-only** milestone:

- `cd::rhi_d3d12::create_d3d12_device(info)` actually creates an
  `ID3D12Device` plus an `IDXGIFactory6`, walks adapters via
  `EnumAdapterByGpuPreference`, picks one that supports the
  requested feature level, creates a `DIRECT` command queue and an
  idle fence + event.
- `backend()` returns `Backend::kD3D12`, `adapter_name()` returns the
  actual descriptor string, `limits()` / `features()` return default-
  initialised structs.
- `wait_idle()` does a real `Signal` + `SetEventOnCompletion` +
  `WaitForSingleObject` on the queue / fence pair.
- Every other virtual (50 of them) returns `kNotImplemented` or an
  invalid handle. The class compiles, the device instantiates, the
  surface is reachable.

The new `hello_d3d12_boot` sample exits 0 if the boot path is sound:

```
CHROMODYNAMIC 0.27.0 — hello_d3d12_boot
[d3d12] backend=2  adapter=NVIDIA GeForce RTX 3080 Laptop GPU
[d3d12] boot OK
```

That's enough signal to ship v0.27.0. Subsequent v0.27.x patches add
incremental surface (PSO, draw, buffer upload, swapchain present);
Phase 13's hardening pass can also pick this up depending on order.

## What went wrong before this commit (debugging note)

First boot attempt failed with `HRESULT 0x887a0002` (DXGI_ERROR_NOT_
FOUND). Root cause: `D3D12CreateInfo::min_feature_level` defaulted
to `0x0c00`, a mistaken half-value of `D3D_FEATURE_LEVEL_12_0` (the
actual SDK enumerator is `0xc000`). The adapter-probe loop's
`D3D12CreateDevice(adapter, 0x0c00, nullptr)` call rejected every
adapter because no GPU exposes a feature level that fractional. Fix
was one digit: `0x0c00 → 0xc000`. Test on NVIDIA RTX 3080 Laptop
exits 0 immediately after.

This is a typical class of "header pre-existing from a skeleton wave
nobody actually exercised" bug. The skeleton had a wrong default for
~Phase 8 → Phase 12.B; the boot test on this commit is the first
time anything actually called the factory.

## Implementation notes

- `EXCLUDE_FROM_INSTALL` is intentional: the boot-only surface is
  not stable enough to publish via `find_package`. Downstream
  consumers build from source until the surface fills out.
- `IID_PPV_ARGS` and `__uuidof` are MS language extensions that
  clang-cl flags under `-Wlanguage-extension-token`. The TU pushes
  the diagnostic state once at the Win32 include block and pops at
  end of file — narrowly scoped, no leak into the rest of the build.
- ComPtr (Microsoft::WRL::ComPtr) carries the COM-refcount lifetime
  for `IDXGIFactory6`, `IDXGIAdapter4`, `ID3D12Device`,
  `ID3D12CommandQueue`, `ID3D12Fence`. The non-COM `HANDLE` for
  the idle event is owned via the destructor's `CloseHandle`.
- Validation layer is off by default — turning it on requires the
  Windows SDK debug component to be installed; without it the
  factory creation fails. Local dev can flip the flag.

## Rejected alternatives

- *Full IDevice + ICommandBuffer implementation in one wave.*
  Rejected: 66 virtuals across two interfaces, every one a chance
  to introduce a subtle barrier / descriptor / root-sig bug that
  fails silently. Marathon rule: don't introduce silent-fail surface
  that no one will check.
- *Drop D3D12 from Phase 12 entirely; defer to Phase 13.* Rejected:
  the user explicitly wants Phase 12 to ship all four sub-phases.
  Boot-only is honest forward motion.
- *Use FXC for HLSL compile, ship a draw sample now.* Rejected:
  FXC is officially superseded by DXC, and DXC integration is its
  own dep + wave. Sample without shaders waits.

## Consequences

- v0.27.0 is the new latest SemVer marker.
- `hello_d3d12_boot.exe` exits 0 on Windows with any D3D_FEATURE_
  LEVEL_12_0+ adapter (NVIDIA, AMD, Intel discrete or iGPU).
- The bench gate from v0.26.0 was not extended for D3D12 yet (no
  surface to bench against); a D3D12-specific bench wave lands
  after the surface fills out.
- Phase 12.C (editor) opens next. D3D12 surface completion is
  scheduled as Phase 13 carry-over.
