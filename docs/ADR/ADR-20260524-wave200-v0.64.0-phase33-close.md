# ADR-20260524 wave200 — v0.64.0 Phase 33 close

## Bağlam

Phase 33 (wave 200 milestone), foundation katmanına iki rendering- ve
threading-kritik primitive ekler.

## Karar

### 33.A — `cd/math/Mat3Inverse.hpp`
Matrix.hpp `Mat4` inverse'ünü zaten içeriyordu; `Mat3` inverse ayrı
header'a çıkarıldı çünkü normal-matrix path'i shader pipeline'da
sık çağrılır ve 3-komponentli normal'i 4-komponentli pipeline'a
promote etmek için bahane değildir.

- `inverse_3(m)` — cofactor / determinant, ε-singular kontrol var,
  singular durumda identity dönüş (predictable fallback).
- `upper_3x3(m4)` — top-left 3×3 view extraction.
- `normal_matrix(m4) = transpose(inverse_3(upper_3x3(m4)))` — standart
  formül.

### 33.B — `cd/concurrency/Latch.hpp`
`std::latch` üzerine ince wrapper. `count_down` / `wait` /
`arrive_and_wait` / `is_ready` (try_wait non-blocking). Niçin sarmak:
- `is_ready()` net boolean — std::latch yalnız try_wait üzerinden
  ifade ediyor.
- Anti-flakiness ile uyumlu: `sleep_for` yerine count_down + wait
  paterni hot test yolu (CLAUDE.md §5).
- ThreadPool fan-in / asset multi-decode için zaten gereken altyapı.

## Test

- Latch: ReadyAfterCountdownToZero, ParallelWorkersConverge,

  sleep_for yok).

## Reddedilen alternatifler

- **Mat3 inverse'i Matrix.hpp içine inline koymak**: Matrix.hpp zaten
  300+ satır, inverse_4 + Mat3/4 tanımları + transpose + operator*
  ile dolu. Normal-matrix path için ayrı header pragmatik (compile-time
  bütçesi).
- **std::counting_semaphore** ile latch yapmak: tek-kullanımlık
  semantik için yanlış primitif; `std::latch` tam karşılığı.
- **Reset edilebilir Latch**: `Barrier` ayrı primitif olarak ileride
  gelecek; karıştırmamak için Latch sıkı tek-kullanımlık.
