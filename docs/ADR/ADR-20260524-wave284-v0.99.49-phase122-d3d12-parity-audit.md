# ADR-20260524 / Wave 284 / v0.99.49 / Phase 122 — D3D12 Parity Audit

## Status
Accepted — 2026-05-24

## Context

Backends sit at very different completion levels:
- Vulkan: 3 `kNotImplemented` sites (RT pipeline / TLAS only).
- D3D12: 9 sites (texture views, cube SRV, fence/semaphore family,
  RT).
- OpenGL: ~30 sites (boot-only).
- Metal: ~30 sites.

Without an audit document, contributors reaching for a method
don't know which backend it works on, and the marathon's
"prioritize what unblocks the most" planning has no concrete
matrix to consult.

## Decision

Generate `docs/D3D12_PARITY_AUDIT.md`:

- Summary table of `kNotImplemented` counts per backend.
- Per-method matrix (Buffers / Textures / Pipelines / Descriptors /
  AS / Sync / Swapchain / CommandBuffer) with one OK/Partial/Stub
  cell per (method, backend) pair.
- Outstanding-gaps lists per backend with line-number references
  into the source.
- "Recommended next phases" table with rough effort estimates and
  what each gap unblocks.

This is a snapshot document — methodology is `grep -c kNotImplemented`
per backend file plus a manual walk of `update_descriptor_set` /
`create_texture` branches that have partial coverage.

## Rejected alternatives

- **Auto-generate from source.** Tooling pass over the AST is
  worth doing eventually, but for a marathon phase the manual
  audit is faster + easier to add prose to.
- **Bake into MARATHON_SUMMARY.md.** That doc is the chronological
  changelog. A standalone parity doc gets read by contributors
  who don't care about the timeline.

## Consequences

- New top-level doc that contributors can consult before picking
  up a backend feature.
- Phase 122 also formally cleared from the outstanding list.
- Recommended next-phases section becomes the reference for
  prioritising follow-up work (D3D12 texture view + fence first;
  Vulkan TLAS implementation; D3D12 cube-map SRV).

## Validation

Document only — no code changes. Engine + samples build
unaffected.
