# ADR — v0.25.0 / Wave 132 — Honest baseline after v1.0 rollback

- Date: 2026-05-23
- Status: Accepted
- Wave: 132
- Tag: v0.25.0

## Context

ADR-20260523-wave125 rolled back v1.0.0 + v1.0.0-rc.1 after a manual
sample smoke surfaced 5 visual / UX bugs the 58 ctest binaries could
not catch. That ADR committed us to:

1. Fix every one of the 5 bugs.
2. Run a hardening pass for the patterns the bugs revealed.
3. Re-baseline against a real "this is what works visually" matrix.
4. Tag v0.25.0 as the honest milestone before re-opening the v1.0 path.

This ADR closes that loop. v0.25.0 is the first release that has been
**visually validated** by a human against every windowed sample.

### Hardening (the patterns the bugs revealed)

**Wave 131 — engine-level fixes** for the two systemic patterns that
let multiple sample bugs land:

- **`RasterState::front_face` default → `kClockwise`**.
  Three of the five rollback bugs shared the same root cause: the
  engine's `front_face = kCounterClockwise` default combined with the
  Vulkan-NDC `clip.y = -clip.y` Y-flip every windowed sample uses
  inverted the winding after perspective divide. Cull dropped what
  should have been the front faces. Switching the default removes the
  trap so any new sample using the Y-flip convention works without
  the `cull = kNone` override. Existing samples keep their explicit
  overrides — backward compatible.
- **`cd::core::kEngineVersion` sync to CMake `PROJECT_VERSION`**.
  Pre-Wave 131 the constant was hard-coded `{0, 1, 0}` in
  `Version.hpp` with a comment claiming "synchronized with top-level
  CMakeLists.txt" that no build step honored. Every sample banner
  printed "CHROMODYNAMIC v0.1.0" forever, drifting from CMake's
  project version (which was hitting v1.0.0 right before the
  rollback). Now wired as PUBLIC compile definitions
  (`CD_ENGINE_VERSION_MAJOR/MINOR/PATCH`) stamped from
  `PROJECT_VERSION_*`. `hello_core` + `hello_foundation` verified
  printing the actual project version (`v0.25.0`).

### Smoke + ctest results at v0.25.0

- **58/58 ctest binaries green** on ninja-debug (`cmake --build
  --preset ninja-debug && ctest --preset ninja-debug`).
- **39/39 sample exit-0** in headless smoke (`--headless 3`, per-sample
  timeout 12s).
- **5/5 critical visual baseline** manually validated by the human
  reviewer:
  - `hello_triangle` — classic Vulkan RGB-corner gradient triangle.
  - `hello_cube` — 3D depth + push-constant cube, no regression
    after front-face default flip.
  - `hello_anim` — opaque keyframe-driven cube, animation correct.
  - `hello_pbr` — 5×5 metallic/roughness sweep with vertical
    roughness gradient and horizontal metallic tint visible.
  - `hello_skybox` — fullscreen atmosphere gradient renders (no more
    uniform black). Saturation is soft due to the
    Reinhard-then-gamma path in the shader's atmosphere math; that's
    an artistic / atmospheric-model item, not a render bug.

### What v0.25.0 does NOT include (deferred to v1.0 work)

The Wave 125 rollback ADR defined a 4-axis v1.0 maturity gate:

- Axis A — Visual correctness across every windowed sample.
  → **Partially met** (5 critical samples manually verified; the
  other 9 windowed samples passed exit-0 smoke but weren't
  individually pixel-checked at v0.25.0).
- Axis B — Cross-hardware validation (≥ 2 GPU vendors).
  → **Not yet.** Single NVIDIA RTX 3080 Laptop. Linux Vulkan via
  SwiftShader / lavapipe still pending.
- Axis C — Real downstream consumer linking
  `find_package(CHROMODYNAMIC)`.
  → **Not yet.** Internal smoke
  (`tests/find_package_smoke/`) only.
- Axis D — Independent review of the public surface.
  → **Not yet.**

v0.25.0 is therefore an **internal-baseline** release, not a v1.0
candidate. Phase 11 will work the four axes above.

## Decision

Tag **v0.25.0** as the honest baseline. The version number itself is
the message: the marathon ran `v0.20.0 → v0.21.0 → ... → v0.24.0 →
[v1.0.0-rc.1 / v1.0.0 rolled back] → v0.25.0`. The v0.25.0 tag carries
the same library / sample / test surface as v0.24.0 plus the five bug
fixes and the two hardening changes.

`release.yml` will fire on this tag and produce per-platform archives
(Windows zip, Linux + macOS tar.zst) consumable from a staged
`find_package(CHROMODYNAMIC 0.25)` prefix.

## Rejected alternatives

- *Skip the baseline and roll straight into Phase 11.* Rejected:
  the rollback ADR explicitly committed to a baseline tag before any
  new work. Skipping the tag would leave Phase 10's polish stranded
  on dev with no SemVer marker, and the next downstream consumer
  would have nothing to pin against.
- *Tag v1.0.0 again now that the smoke is green.* Rejected: only
  axis A is partly met (5 of 14 windowed samples pixel-checked, plus
  39 exit-0 headless). Axes B/C/D haven't been touched. A second
  premature v1.0 would reproduce the original Wave 124 mistake.
- *Manually pixel-check the remaining 9 windowed samples before
  tagging.* Considered but deferred: the smoke is green for all of
  them; per-sample manual review for `hello_mesh`, `hello_texture`,
  `hello_framegraph`, `hello_clustered_lights`, `hello_imgui` etc.
  can fold into Phase 11's Axis-A coverage sweep. The 5 we checked
  are the ones with shader pipelines that had to be touched by the
  fixes — those carried the regression risk.

## Consequences

- v0.25.0 is the new "latest" SemVer marker. Pre-v0.25.0 tags
  (v0.20 — v0.24) remain in the archive as their respective
  marathon milestones.
- Phase 10 closes here, **honestly** this time. The v1.0 path
  re-opens under Phase 11 with the maturity-gate work.
- The two superseded v1.0 ADRs (Wave 123 / Wave 124) and the
  Wave 125 rollback ADR remain in the archive — the chain
  (claimed → smoke → rolled back → bug-fixed → baseline) is the
  load-bearing lesson.
- All five rollback bugs have golden regression coverage going
  forward via the manual visual-check matrix above. A proper
  FLIP/SSIM golden-image diff CI gate is queued for Phase 11.
