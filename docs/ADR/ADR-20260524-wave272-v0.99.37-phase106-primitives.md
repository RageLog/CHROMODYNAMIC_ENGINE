# ADR-20260524 / Wave 272 / v0.99.37 / Phase 106 — Procedural Primitives

## Status
Accepted — 2026-05-24

## Context

hello_editor v3 shipped `make_sphere` + `make_cone` builders inline in
the sample TU. Other samples and the editor will want the same plus
cube, cylinder, plane, torus, capsule — and there is no single place
to read "what's the canonical layout of a vertex used by the demo
pipeline?"

## Decision

New header-only `cd/asset/Primitives.hpp`:

- `PrimitiveVertex` POD (44 B) = pos + normal + uv + color. Tight pack,
  static-asserted to keep the upload contract stable.
- `PrimitiveMesh` = `vector<PrimitiveVertex> + vector<uint16_t>`.
- Builders: `make_cube()`, `make_sphere(stacks, slices)`,
  `make_cone(slices)`, `make_cylinder(slices)`, `make_plane(size)`,
  `make_torus(major_r, minor_r, rings, sides)`,
  `make_capsule(radius, height, rings, slices)`.
- All unit-sized by default (caller applies scale via transform).
- Right-handed coordinate frame, +Y up. CCW winding from outside.

## Rejected alternatives

- **Generic template on vertex type.** Would let callers re-use the
  builder with their own vertex layout, but explodes the header into a
  template specialization tangle. The single canonical layout is the
  pragmatic choice — anyone wanting a different layout repacks into
  their own buffer after the build call.
- **Cooked `.cdmesh` assets shipped in repo.** Higher fidelity but
  requires an asset cooker pass + version-tracked binaries. Procedural
  is dependency-free and trivial to regenerate at any tessellation.
- **Reusing OBJ importer with built-in primitive files.** Adds file IO
  + parser dependency for what should be a header-only spawn.

## Consequences

- `cd::asset` gains its first header-only sub-component (the rest of
  cd::asset is registry + IO heavy). Pure data, no link order shifts.
- hello_editor sample's local `make_sphere` / `make_cone` will migrate
  to consume this header in the next polish pass (Phase 121 candidate).
- Engine + editor + future hello_terrain / hello_physics samples can
  all spawn meshes from one shared utility.

## Validation

```
cmake --build --preset llvm-win-debug
```

Full engine + all 33 samples + cook tools + bench binaries built
green. Header-only, so no runtime smoke needed.
