## Architectural deliverables

* **ADR-20260530-ui-widget-library** committed phase429. Specifies the
  full UI tier: Phase 1.0 layout (Yoga-shape Flex), 1.1 font (stb -> FT
  + HarfBuzz in Phase 4), 1.2 renderer (CPU batcher), 1.2b renderer_rhi,
  Phase 2.1 input + 2.2 widget catalog, Phase 3 animation. Eight of the
  promised libraries shipped this session.
* **ADR-20260530-auto-exposure-pipeline** committed mid-session as the
  GPU companion to phase454; phase461 implemented the compute reduction
  skeleton.
* **Naming sweep (phase432)** — final audit of cd_<lib> target /
  cd::<lib> alias / cd/<lib>/ include / CD_<LIB>_API export macro
  consistency; ten-plus inconsistencies documented + retired.
* **engine/ui/ui -> engine/ui flatten (phase430)** and engine/render/render
  -> engine/render flatten (phase431). Trims one directory level off
  every consumer include path.
* **Sponza rendering visual quality** — phases 425, 426, 433, 434, 435,
  436, 437, 438, 446, 447, 448, 449, 450, 451, 452, 455, 456 collectively
  walked from "scene loads but black fragments + wrong shadows" to a
  data-driven per-prim PBR pipeline with proper bias scaling and
  vegetation alpha-test.
* **glTF -> scene pipeline (phase439, 440, 441, 452)** — `cd::asset_gltf::
  SceneLoader` produces a `LoadedScene` POD with mesh / material /
  texture indices; `cd::render::scene_ingest::SceneIngest` uploads the
  textures + builds the renderable mesh. Both fully unit-tested.
* **hello_ui sample (phase463)** — first end-to-end tie-together of
  every Phase-1/Phase-2 cd::ui library, gated by Vulkan in CMake and
  with a NullDevice fallback so CI can smoke-test without a GPU.

## Known limitations + queued items

### hello_ui

* Live Vulkan validation (validation-layer-clean fragment output)
  not exercised this session — needs a host with a Vulkan ICD and
  the GPU-validation harness. The sample compiles + boots clean on
  NullDevice; the Submitter::record path is touched on each frame
  but the actual GPU draws are no-ops under NullDevice.
* Glyph rendering not yet wired in the sample — `cd::ui::font::Font`
  is loaded and the atlas is rasterized, but the sample only emits
  background panels for the leaf rects. Wiring `Font::glyph_uv` to
  `DrawBatcher::glyph` per-codepoint is straightforward and queued
  for the hello_ui v2 pass.
* No swapchain integration in the sample — the Vulkan branch
  creates a command buffer but does not present. Adding
  `cd::render::Renderer::begin_frame / end_frame` (same shape as
  hello_imgui) lifts this to a fully drawing demo.

### UI tier

* Phase 3 (animation) shipped easings + Tweener + Timeline (phase458)
  but no widgets currently consume them. Tween hooks queued for
  Phase 2.2-followup.
* Phase 4 (FreeType + HarfBuzz, MSDF, variable fonts, BiDi shaping)
  not started.
* `cd::ui_input` ships HitTester + FocusManager but no gesture
  recognizers (double-click / drag / long-press) — Phase 2.2+.
* `cd::ui_widgets::Modal` shipped but the dropdown / modal stack
  integration with the FocusManager is documented-but-not-tested at
  the integration tier.

### Auto-exposure

* `cd::post::exposure` GPU compute skeleton (phase461) is API only;
  the actual reduction pipeline is not wired into the composite
  framegraph. CPU path (phase454) is fully tested + integrated.

### Sponza

* Per-prim PBR is data-driven from the glTF material catalog (phase448)
  but the Sponza ground-truth is reference-only — no golden-image
  diff CI gate yet.
* Vegetation alpha-test (phase436) is enabled; alpha-to-coverage
  variant for AA is queued.

### Tests

* No new tests for the hello_ui sample itself (it is a sample, not a
  test). Its compile-cleanliness IS the CI gate.

### Architecture

* Phase 463 marks the first time every Phase-1 + Phase-2 UI library
  is exercised from one binary. Phase 5 (constraint solver / grid /
  RTL / WebGPU backend etc.) remains future work.
